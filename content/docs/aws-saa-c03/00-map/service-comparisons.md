SAA 문항은 거의 항상 **둘 다 동작하는 두 답**으로 좁혀집니다.
그때 필요한 것은 서비스 설명이 아니라 **"지문에 이 낱말이 있으면 이쪽"** 이라는 신호입니다.

각 칸의 뜻은 이렇습니다.

| 칸 | 뜻 |
|---|---|
| **선택 신호** | 지문에 이게 있으면 **이 서비스** |
| **탈락 신호** | 지문에 이게 있으면 **이 서비스가 아님** |
| **★ 결정적 차이** | 한 문장으로 줄인 것. 헷갈리면 이 줄만 |

`[★★★]` 는 실제 시험에서 봤다는 증언이 있는 세트입니다. 여기부터 외우세요.

> [!note] 채워지는 중입니다
> 지금은 **1차 6세트**입니다. 문제를 풀다 헷갈리는 쌍이 나올 때마다 한 세트씩 늘립니다.
> 통째로 채워 놓고 시작하지 않는 이유는, 안 헷갈리는 쌍까지 외우면 시간만 나가기 때문입니다.

## 1. 공유 파일 시스템 — EFS vs FSx [★★★]

실제 시험에서 **EFS · EFS-IA · FSx for Lustre · FSx for ONTAP 가 각각 따로** 나왔다는 보고가 있습니다.
"FSx" 로 뭉뚱그려 외우면 변종 문제에서 그대로 틀립니다.

| | 선택 신호 | 탈락 신호 | ★ 결정적 차이 |
|---|---|---|---|
| **Amazon EFS** | `Linux 여러 대가 동시에` · `NFS` · `POSIX` · `용량 자동 확장` · `여러 AZ` | `Windows` · `SMB` · `HPC` · `수백 GB/s` | 리전 단위 **Linux 공유 폴더**. 고민 없이 쓰는 기본값 |
| **FSx for Lustre** | `HPC` · `고성능 컴퓨팅` · `머신러닝 학습` · `S3 데이터를 빠르게 처리` · `밀리초 미만 지연` | `일반 파일 공유` · `Windows 애플리케이션` | **속도가 목적.** S3 버킷을 파일 시스템처럼 붙여 쓴다 |
| **FSx for Windows File Server** | `SMB` · `Active Directory 통합` · `Windows 애플리케이션` · `NTFS 권한` | `Linux 전용` · `HPC` | **Windows 전용 SMB.** AD 가 나오면 거의 이것 |
| **FSx for NetApp ONTAP** | `NetApp` · `온프레미스 ONTAP 그대로` · `NFS 와 SMB 를 동시에` · `iSCSI` · `스냅샷·클론` | `단일 프로토콜이면 충분` | **멀티프로토콜.** 리눅스와 윈도우가 한 볼륨을 함께 쓸 때 |

> [!tip] 한 줄 판정
> `Windows` → **Windows File Server** / `속도·HPC` → **Lustre** /
> `둘 다 붙어야` → **ONTAP** / 그 외 리눅스 공유 → **EFS**

## 2. VPC 엔드포인트 — Gateway vs Interface [★★★]

| | 선택 신호 | 탈락 신호 | ★ 결정적 차이 |
|---|---|---|---|
| **Gateway 엔드포인트** | `S3` · `DynamoDB` · `추가 비용 없이` · `라우팅 테이블` | `S3·DynamoDB 이외의 서비스` · `온프레미스에서 접근` · `보안 그룹으로 제어` | **S3 와 DynamoDB 딱 둘뿐이고 무료.** 라우팅 테이블에 항목이 생긴다 |
| **Interface 엔드포인트 (PrivateLink)** | `그 밖의 AWS 서비스` · `온프레미스에서 Direct Connect·VPN 을 거쳐` · `프라이빗 IP` · `보안 그룹 적용` | `가장 저렴한` (시간당 + 데이터 처리 요금이 붙는다) | VPC 안에 **ENI 를 꽂는다.** 프라이빗 IP 가 생겨서 온프레미스에서도 닿는다 |

> [!warning] 여기서 가장 많이 틀립니다
> **"Gateway 엔드포인트로 Kinesis 에 접근"** 같은 보기는 그냥 불가능한 조합입니다.
> Gateway 는 **S3·DynamoDB 두 개**뿐입니다. 보이는 즉시 지우세요.
> 반대로 `비용을 추가하지 않고 S3 에 프라이빗하게` 는 Gateway 를 정확히 가리킵니다.

## 3. VPC 를 잇는 법 — 피어링 vs Transit Gateway [★★★]

실제 시험에서 **Transit Gateway 가 1~2문항** 나왔다는 보고가 있습니다.

| | 선택 신호 | 탈락 신호 | ★ 결정적 차이 |
|---|---|---|---|
| **VPC 피어링** | `VPC 두 개만` · `가장 저렴한` · `단순 연결` | `VPC 가 계속 늘어난다` · `전이적` · `온프레미스까지 함께` · `CIDR 이 겹친다` | **1:1 전용.** 전이적 라우팅이 안 되므로 N개면 연결이 N² 로 폭발한다 |
| **Transit Gateway** | `수십·수백 개 VPC` · `허브` · `온프레미스(VPN·Direct Connect)까지 한 곳에서` · `중앙에서 라우팅 관리` · `멀티캐스트` | `VPC 두 개뿐인데 가장 저렴한` | **허브 앤 스포크.** 한 곳에 다 꽂고 라우팅 테이블로 통제한다 |

> **연결 3종을 한 줄로:** 피어링 = 두 VPC 를 직접 · Transit Gateway = 전부 허브에 ·
> PrivateLink = **서비스 하나만** 남에게 노출 (VPC 전체를 여는 게 아니다)

## 4. 메시징 — SQS vs SNS [★★★]

| | 선택 신호 | 탈락 신호 | ★ 결정적 차이 |
|---|---|---|---|
| **Amazon SQS** | `유실되면 안 된다` · `처리 속도를 완충` · `주문이 몰려도` · `느슨한 결합` · `순서 보장(FIFO)` · `재처리·DLQ` | `여러 시스템에 동시에 알림` · `실시간 푸시` | **큐에 쌓아 두고 소비자가 꺼내 간다(pull).** 소비자가 죽어도 메시지가 남는다 |
| **Amazon SNS** | `여러 구독자에게 동시에` · `팬아웃` · `이메일·SMS 알림` · `푸시` | `한 번만 처리되어야` · `나중에 처리해도 된다` · `순서대로 하나씩` | **주제에 던지면 구독자 전원에게 밀어 준다(push).** 구독자가 없으면 그 메시지는 사라진다 |

> [!tip] 둘 다 나오면 팬아웃입니다
> `여러 시스템이 각자의 속도로 같은 이벤트를 처리` → **SNS 주제 하나에 SQS 큐 여러 개**를 구독시킵니다.
> 이 조합이 보기에 있으면 대개 그게 정답입니다.
>
> `일정 · 서드파티 SaaS 이벤트 · 이벤트 패턴으로 라우팅` 이 나오면 SQS/SNS 가 아니라 **EventBridge** 쪽입니다.

## 5. 보호 — Shield vs WAF [★★]

실제 시험에서 **`DDoS 보호`** 시나리오가 나왔다는 보고가 있습니다.

| | 선택 신호 | 탈락 신호 | ★ 결정적 차이 |
|---|---|---|---|
| **Shield Standard** | `DDoS` · `추가 설정 없이` · `기본 제공` | `SQL 인젝션` · `특정 국가 차단` | **자동으로 켜져 있는** L3/L4 방어. 고를 것이 없다 |
| **Shield Advanced** | `대규모 DDoS` · `전담 대응 팀` · `공격으로 늘어난 요금을 보전` | `요청 내용을 보고 판단` | 사람이 붙는 **유료 구독**. 요금 급증 보호가 결정적 신호 |
| **AWS WAF** | `SQL 인젝션` · `크로스 사이트 스크립팅` · `특정 국가 차단` · `IP 속도 제한` · `봇` | `볼륨 공격` · `네트워크 계층` | **요청 내용을 읽고** 규칙으로 막는다. CloudFront·ALB·API Gateway 에 붙인다 |

> **한 줄 판정:** 트래픽을 **들이붓는** 공격이면 Shield, 요청 **내용**이 나쁜 것이면 WAF.

## 6. Storage Gateway 3종 [★★]

실제 시험에서 **`온프레미스 스토리지`** 시나리오가 나왔다는 보고가 있습니다.

| | 선택 신호 | 탈락 신호 | ★ 결정적 차이 |
|---|---|---|---|
| **File Gateway** | `NFS·SMB 로 마운트` · `파일을 S3 객체로` · `온프레미스 앱은 그대로` | `블록 볼륨` · `테이프` | 파일로 넣으면 **S3 객체가 된다** |
| **Volume Gateway** | `iSCSI 블록 볼륨` · `EBS 스냅샷으로 백업` | `파일 공유` · `테이프 라이브러리` | **블록 장치**로 붙는다. 캐시형(주 데이터는 S3) / 저장형(주 데이터는 온프레미스) 두 가지 |
| **Tape Gateway** | `기존 백업 소프트웨어` · `가상 테이프 라이브러리` · `테이프를 없애고 싶다` | `실시간 파일 접근` | 백업 소프트웨어에는 **테이프 장치로 보이고** 실제로는 S3 Glacier 로 간다 |

> [!tip] Volume Gateway 는 한 번 더 갈립니다
> `온프레미스에 전체 데이터를 그대로 두고 백업만` → **저장형(stored)**
> `온프레미스 용량이 부족해서 자주 쓰는 것만 로컬에` → **캐시형(cached)**
> 지문이 "저지연 접근이 전체 데이터셋에 필요한가"를 묻고 있다면 그게 갈림길입니다.

## 이 표를 쓰는 법

1. 문제를 풀다 **2개로 좁혀졌는데 못 고르겠으면** 그 쌍의 표를 엽니다
2. 지문에서 **선택 신호에 해당하는 낱말**을 찾습니다. 대개 딱 하나 있습니다
3. 없으면 **탈락 신호**로 지웁니다
4. 표에 없는 쌍이었다면 **한 세트 추가하세요.** 그게 이 노트가 자라는 방식입니다

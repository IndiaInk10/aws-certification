> SAA 에서 가장 자주 깔리는 바탕. **퍼블릭/프라이빗을 가르는 것은 라우팅 테이블 한 줄**이다

## 한 줄로 말하면

내 전용 가상 네트워크입니다. 서브넷·라우팅 테이블·게이트웨이·보안 그룹·NACL 이 전부 여기 살고, 보안 문항의 절반이 이 구조 위에서 벌어집니다.

## 핵심 개념

**퍼블릭과 프라이빗**

- 서브넷에 "퍼블릭" 스위치는 없습니다. **인터넷 게이트웨이로 가는 경로가 라우팅 테이블에 있으면** 퍼블릭입니다
- **서브넷은 가용 영역 하나에만** 존재합니다. 두 AZ 에 걸치는 서브넷은 만들 수 없습니다
- **인터넷 연결 로드 밸런서는 퍼블릭 서브넷**에, 대상 인스턴스는 프라이빗에 — 이것이 정상 구성입니다

- **서브넷마다 IP 5개가 예약**됩니다. /28(16개) 이면 실제로 쓸 수 있는 것은 11개입니다 — 필요한 인스턴스 수를 계산하는 문항에서 이 5개를 빼먹으면 답이 어긋납니다
- VPC 는 리전당 **기본 5개**(할당량 상향 요청 가능)

**밖으로 나가는 통로**

| | 무엇을 위해 |
|---|---|
| **NAT 게이트웨이** | 프라이빗 서브넷이 **인터넷으로** 나갈 때. **퍼블릭 서브넷에 있어야** 하고 **AZ 단위**라 AZ 마다 둬야 한다 |
| **VPC 엔드포인트** | **AWS 서비스**에 갈 때. 인터넷을 아예 안 탄다 |
| **PrivateLink** | 남의 VPC 의 **서비스 하나**에 갈 때 |

- NAT 게이트웨이는 **IPv4 전용**이고 5Gbps 에서 45Gbps 까지 알아서 늘어납니다. 관리할 것이 없습니다
- **NAT 인스턴스**는 구형이지만 여전히 출제됩니다 — 직접 EC2 로 띄우는 방식이라 **소스/대상 확인을 꺼야** 하고, 고가용성과 대역폭을 내가 책임집니다. `관리 부담 최소` 지문에서는 항상 NAT 게이트웨이가 이깁니다
- **NAT 게이트웨이는 IPv6 트래픽을 다루지 못합니다.** IPv6 에서 나가기만 허용하려면 **송신 전용 인터넷 게이트웨이(Egress-only IGW)** 입니다

**VPC 엔드포인트 두 종류**

- **게이트웨이** — **S3 와 DynamoDB 딱 둘뿐**이고 **무료**. 라우팅 테이블에 항목이 생깁니다. 온프레미스에서는 못 씁니다
- **인터페이스(PrivateLink)** — 그 밖의 서비스. VPC 에 **ENI 를 꽂아** 프라이빗 IP 가 생기므로 온프레미스에서 Direct Connect·VPN 을 거쳐도 닿습니다. 시간당·데이터 처리 요금이 붙습니다

**보안 그룹 vs 네트워크 ACL**

| | 보안 그룹 | 네트워크 ACL |
|---|---|---|
| 대상 | 인스턴스(ENI) | 서브넷 |
| 상태 | **상태 저장** — 나간 것의 응답은 자동 허용 | **상태 비저장** — 응답도 규칙에 있어야 |
| 규칙 | 허용만 | 허용 + **거부** |
| 평가 | 전체를 합쳐서 | **번호 순서대로** |

- **특정 IP 를 막아야 하면 NACL** 입니다. 보안 그룹에는 거부 규칙이 없습니다
- 보안 그룹은 **다른 보안 그룹을 소스로** 지정할 수 있어 계층 연쇄에 씁니다. 다만 **리전을 넘으면 그 참조가 안 되고** IP·CIDR 로 지정해야 합니다
- NACL 로 열 때는 **인바운드와 임시 포트 아웃바운드를 둘 다** 열어야 합니다

**VPC 를 잇는 법** — 피어링(1:1, 전이적 라우팅 불가) · [[aws-transit-gateway\|Transit Gateway]](허브) · [[aws-privatelink\|PrivateLink]](서비스 하나만)

**CIDR** — VPC CIDR 은 **/16 ~ /28** 만 유효합니다. 기본 CIDR 은 **나중에 크기를 못 바꾸고**, 주소가 모자라면 **보조 CIDR 을 추가**합니다. 피어링하려면 CIDR 이 겹치면 안 됩니다.

**IPv6** — VPC 에서 켜면 **듀얼 스택**이 됩니다(IPv4 와 함께 씀). IPv6 는 **전부 공인 주소**라 사설 범위가 없습니다.

> [!warning] IPv6 를 켰는데 EC2 가 안 뜬다면
> 원인은 IPv6 가 아니라 **서브넷의 IPv4 주소가 바닥난 것**입니다. 듀얼 스택이라 IPv4 도 하나 필요합니다. 답은 서브넷에 **IPv4 CIDR 을 추가**하는 것입니다.

**보고 진단하는 도구들**

- **흐름 로그** — 트래픽 메타데이터(ACCEPT/REJECT)를 S3 나 CloudWatch Logs 로 보냅니다. **VPC · 서브넷 · ENI** 세 수준에서 켤 수 있고, S3 에 쌓아 [[amazon-athena\|Athena]] 로 분석하는 구성이 표준입니다. `누가 거부당했는지 조사` 의 답
- **Reachability Analyzer** — 두 자원 사이가 통하는지 **패킷을 보내지 않고** 구성만으로 판정합니다. `왜 연결이 안 되는지 찾아라` 의 답
- **트래픽 미러링** — ENI 의 트래픽을 **복사해** 보안 어플라이언스로 보냅니다. 흐름 로그는 메타데이터뿐이지만 이쪽은 **내용까지** 봅니다. `패킷 내용을 검사해야` 가 신호입니다
- **AWS Network Firewall** — VPC 전체에 3~7계층 방화벽을 겁니다. 도메인 목록 필터링·침입 방지까지 하며, 보안 그룹/NACL 로는 안 되는 요구에 답이 됩니다

## 요금 모델

- VPC 자체는 무료입니다. **NAT 게이트웨이(시간당 + 처리량)**, 인터페이스 엔드포인트, Transit Gateway 에 요금이 붙습니다
- 데이터 전송은 **나가는 쪽 · AZ 를 넘는 쪽 · 리전을 넘는 쪽**에 붙고, **같은 AZ 안 프라이빗 IP 통신은 무료**입니다
- S3·DynamoDB 트래픽이 NAT 를 거치고 있다면 **게이트웨이 엔드포인트 하나로** 시간당 요금과 처리량 요금이 함께 사라집니다

## 시험 포인트

- [ ] `인터넷에서 접근 불가` + `패치는 받아야` → 프라이빗 + NAT 게이트웨이
- [ ] `S3 에 프라이빗하게, 추가 비용 없이` → **게이트웨이 엔드포인트**
- [ ] `특정 IP 차단` → **NACL** (보안 그룹은 거부 불가)
- [ ] NACL 은 상태 비저장 — **임시 포트 아웃바운드**까지 열어야
- [ ] 최소 권한 계층 통신 → **보안 그룹 ID 를 소스로**
- [ ] IP 부족 → **보조 CIDR 추가** (기본 CIDR 은 못 늘림)
- [ ] 서브넷은 **AZ 하나**에만 존재 · **IP 5개 예약**
- [ ] IPv6 아웃바운드만 → **송신 전용 인터넷 게이트웨이**
- [ ] `패킷 내용까지 검사` → **트래픽 미러링** (흐름 로그는 메타데이터뿐)
- [ ] `연결이 왜 안 되는지` → **Reachability Analyzer**
- [ ] NAT 인스턴스를 쓴다면 **소스/대상 확인 비활성화**

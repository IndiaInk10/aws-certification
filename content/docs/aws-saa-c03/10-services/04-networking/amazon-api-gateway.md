> API 앞단. **제한(throttling)·캐시·인증**이 시험에서 묻는 세 가지다

## 한 줄로 말하면

API 를 만들고 앞에서 **인증·제한·캐시**를 걸어 줍니다. 뒤에는 Lambda·HTTP 엔드포인트·AWS 서비스를 직접 붙일 수 있습니다.

## 핵심 개념

**제한과 사용량 계획**

- **스로틀링**으로 요청 폭주를 앞단에서 잘라냅니다. `백엔드가 과부하로 죽는다` · `특정 고객이 API 를 남용한다` 의 답입니다
- **사용량 계획 + API 키** 로 고객별 한도를 다르게 줍니다. 티어별 요금제 지문의 자리입니다

**캐싱** — 응답을 캐시해 백엔드 호출을 줄입니다. `같은 응답이 반복` + `백엔드 부하·비용 감소` 면 이쪽입니다.

**인증 방식 세 갈래**

| 방식 | 언제 |
|---|---|
| **IAM 권한** | 호출자가 **AWS 자격 증명**을 가진 내부 시스템 |
| **[[amazon-cognito\|Cognito]] 사용자 풀** | **최종 사용자 로그인** — 앱 사용자 |
| **Lambda 권한 부여자** | 사내 토큰·서드파티 등 **자체 로직**이 필요할 때 |

**요청을 흘려보내는 법**

- **Lambda 프록시 통합**이 기본입니다
- **직접 통합** — SQS·Kinesis·DynamoDB 에 Lambda 없이 바로 넣을 수 있습니다. `요청을 잃지 않게 큐에 버퍼링` 이면 API Gateway → SQS 가 답입니다
- **긴 작업**은 API 를 붙잡아 두면 안 됩니다. 요청만 받아 큐나 Step Functions 로 넘기고 **비동기로 응답**하는 것이 정석입니다

**엔드포인트 유형** — 엣지 최적화 · 리전 · **프라이빗**(VPC 안에서만). `내부 전용 API` 면 프라이빗 엔드포인트 + 인터페이스 엔드포인트입니다.

**타임아웃** — 통합 타임아웃 상한이 있습니다. 오래 걸리는 처리를 동기로 붙이는 보기는 그래서 틀립니다.

**단계(stage)** — dev/prod 를 나누고 카나리 배포로 일부 트래픽만 새 버전에 보낼 수 있습니다.

## 요금 모델

- **요청 수 + 전송 데이터** 로 붙습니다. 서버는 없습니다
- **캐시는 시간당 별도 요금**입니다 — 캐시를 켜면 API Gateway 요금은 늘고 백엔드 호출은 줍니다
- HTTP API 는 REST API 보다 싸고 가볍습니다. 기능이 덜 필요하면 이쪽

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[elastic-load-balancing\|ALB]] | ALB 는 대상으로 **분산**만. 스로틀링·API 키·캐시는 API Gateway 쪽 |
| [[amazon-cloudfront\|CloudFront]] | CloudFront 는 콘텐츠 캐시. API 인증·한도는 API Gateway |

## 시험 포인트

- [ ] `백엔드 과부하` · `남용하는 고객` → **스로틀링 / 사용량 계획**
- [ ] `같은 응답 반복 + 백엔드 부하 감소` → **캐싱**
- [ ] `앱 사용자 로그인` → **Cognito 사용자 풀 권한 부여자**
- [ ] `사내 토큰으로 검증` → **Lambda 권한 부여자**
- [ ] `요청을 잃지 않게` → API Gateway → **SQS** 직접 통합
- [ ] `VPC 안에서만 호출` → **프라이빗 엔드포인트**
- [ ] 오래 걸리는 작업을 동기로 붙이는 보기는 타임아웃 때문에 오답

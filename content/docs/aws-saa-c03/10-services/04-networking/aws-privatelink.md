> **네트워크를 붙이지 않고 서비스 하나만** 노출한다. 피어링·TGW 와 가르는 지점

## 한 줄로 말하면

내 VPC 에 **ENI 를 하나 꽂아** 상대 서비스에 프라이빗 IP 로 닿게 합니다. 인터페이스 VPC 엔드포인트가 곧 PrivateLink 입니다.

## 핵심 개념

- **노출 범위가 서비스 하나**입니다. 피어링이나 Transit Gateway 는 네트워크를 통째로 붙이지만, PrivateLink 는 **NLB 뒤의 그 서비스만** 보여 줍니다. `최소 노출` · `다른 VPC 전체에 접근을 주고 싶지 않다` 가 신호입니다
- **CIDR 이 겹쳐도 됩니다.** 피어링은 겹치면 아예 불가능한데, PrivateLink 는 상관없습니다. 인수·합병으로 주소가 충돌하는 지문에서 결정적입니다
- **제공자 쪽에는 NLB**(또는 GWLB)가 필요합니다. ALB 는 엔드포인트 서비스로 직접 노출되지 않습니다
- **단방향**입니다. 소비자가 제공자를 부르는 방향만 열립니다
- **온프레미스에서도 닿습니다** — Direct Connect·VPN 을 거쳐 인터페이스 엔드포인트를 부를 수 있습니다. 게이트웨이 엔드포인트는 이게 안 됩니다
- **AWS 서비스에도 같은 방식**입니다 — S3·DynamoDB 를 뺀 나머지 서비스를 프라이빗하게 부를 때 쓰는 인터페이스 엔드포인트가 바로 이것입니다
- **SaaS 제공자**가 고객 VPC 에 서비스를 넣어 주는 표준 방식이기도 합니다

## 요금 모델

- **엔드포인트당 AZ 별 시간당 요금 + 처리한 데이터량** 으로 붙습니다
- **게이트웨이 엔드포인트(S3·DynamoDB)는 무료**입니다. `추가 비용 없이 S3 에 프라이빗하게` 라면 인터페이스가 아니라 게이트웨이가 답입니다
- NAT 게이트웨이를 대체하면 오히려 절감이 되기도 합니다 — 인터넷 경유 트래픽이 사라지기 때문입니다

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| VPC 피어링 | 피어링은 **네트워크 전체**, CIDR 중복 불가, 양방향 |
| [[aws-transit-gateway\|Transit Gateway]] | TGW 도 네트워크를 붙입니다. PrivateLink 는 서비스 하나 |
| 게이트웨이 엔드포인트 | S3·DynamoDB 전용 · 무료 · 온프레미스 불가 |

## 시험 포인트

- [ ] `서비스 하나만 노출` · `네트워크 전체는 안 됨` → PrivateLink
- [ ] `CIDR 이 겹친다` → 피어링 탈락, PrivateLink
- [ ] `온프레미스에서 프라이빗하게 AWS 서비스` → **인터페이스 엔드포인트**
- [ ] `S3 에 추가 비용 없이 프라이빗하게` → **게이트웨이 엔드포인트** (PrivateLink 아님)
- [ ] 제공자 쪽 NLB 가 보기에 없으면 그 PrivateLink 구성은 성립하지 않습니다

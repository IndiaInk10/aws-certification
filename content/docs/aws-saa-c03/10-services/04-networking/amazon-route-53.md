> DNS + 상태 확인. **라우팅 정책 일곱 개를 요구사항 낱말로 가르는 것**이 전부다

## 한 줄로 말하면

DNS 서비스이면서 **상태 확인으로 비정상 대상을 응답에서 빼 줍니다.** 리전 단위 장애 조치의 기본 재료입니다.

## 핵심 개념

**라우팅 정책 — 지문의 낱말이 곧 정책**

| 정책 | 지문의 신호 |
|---|---|
| 단순 | 대상이 하나 |
| **가중치** | `트래픽의 10%만 새 버전으로` — 카나리 |
| **지연 시간** | `가장 빠른 리전으로` |
| **장애 조치** | `주 사이트가 죽으면 대기 사이트로` — 능동-수동 |
| **지리 위치** | `국가별로 다른 콘텐츠` · 규정 준수 |
| 지리 근접 | 리소스 위치 기준 + 편향치 |
| **다중값 응답** | `모든 정상 인스턴스에 트래픽이 닿아야` — 여러 IP 를 상태 확인과 함께 |

- `가장 낮은 지연 시간` 은 **지연 시간 기반**, `한국 사용자는 한국 법을 따라야` 는 **지리 위치**입니다. 이 둘을 바꿔 고르기 쉽습니다
- **상태 확인**을 붙여야 비정상 대상이 응답에서 빠집니다. 붙이지 않으면 죽은 IP 가 그대로 나갑니다
- **TTL 을 늘리면 잘못된 응답이 더 오래 캐시**됩니다. 장애 대응에서는 반대 방향입니다

**한계도 알아야 합니다**

- DNS 기반이라 **캐시 때문에 전환이 느립니다.** 초 단위 전환이 필요하면 [[aws-global-accelerator\|Global Accelerator]] 쪽입니다
- Route 53 은 **어디로 보낼지만** 정합니다. 접근을 막지는 못하므로 `시청 제한` 같은 요구에는 CloudFront 지리적 제한이 답입니다

**별칭 레코드** — ELB·CloudFront·API Gateway·S3 웹사이트 같은 AWS 자원을 가리킬 때 씁니다. 와일드카드 레코드로 고객별 하위 도메인을 한 번에 처리할 수 있습니다.

## 요금 모델

- **호스팅 영역마다 월 요금**과 **쿼리 수**에 붙습니다
- **상태 확인**에도 요금이 붙습니다
- 별칭 레코드로 AWS 자원을 가리키는 쿼리는 대개 무료입니다

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-global-accelerator\|Global Accelerator]] | GA 는 **고정 IP + 초 단위 전환**. DNS 캐시 문제가 없습니다 |
| [[elastic-load-balancing\|ELB]] | ELB 는 리전 안 분산, Route 53 은 리전·엔드포인트 선택 |

## 시험 포인트

- [ ] `가장 빠른 리전` → 지연 시간 기반 / `국가별` → 지리 위치
- [ ] `10%만 새 버전` → 가중치
- [ ] `주 사이트 장애 시 자동 전환` → 장애 조치 + **상태 확인**
- [ ] `모든 정상 인스턴스에 닿아야` → **다중값 응답**
- [ ] 비정상 IP 가 응답에 섞이면 → **상태 확인이 없는 것** (TTL 을 늘리면 악화)
- [ ] 초 단위 리전 전환이 필요하면 Route 53 이 아니라 Global Accelerator

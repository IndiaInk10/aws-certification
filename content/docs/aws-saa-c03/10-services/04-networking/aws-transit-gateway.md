> 허브 앤 스포크. **전이적 라우팅**이 피어링과 가르는 지점이다

## 한 줄로 말하면

VPC 들과 온프레미스 연결(VPN·Direct Connect)을 **한 허브에 다 꽂아** 중앙에서 라우팅을 통제합니다.

## 핵심 개념

- **전이적 라우팅이 됩니다** — 이것이 VPC 피어링과의 결정적 차이입니다. 피어링은 1:1 이라 A↔B, B↔C 가 있어도 A↔C 는 통하지 않고, VPC 가 N 개면 연결이 N² 규모로 늘어납니다
- **라우팅 테이블로 통제** — 어떤 연결이 어떤 대상과 통할지 허브에서 정합니다. 격리가 필요한 환경을 분리할 수 있습니다
- **온프레미스까지 한 곳에서** — VPN 과 Direct Connect 연결을 같은 허브에 붙입니다
- **IP 멀티캐스트를 지원하는 유일한 AWS 네트워크 서비스**입니다. `멀티캐스트` 가 지문에 있으면 다른 보기는 전부 탈락합니다
- **ECMP** — Site-to-Site VPN 을 여러 터널로 붙여 **대역폭을 합산**합니다. VGW 에 직접 붙이면 안 되는 기능이라, `VPN 대역폭이 부족하다` 의 답이 TGW 가 되는 이유입니다
- **리전 간 피어링**으로 허브끼리 연결할 수 있습니다
- **Direct Connect 게이트웨이**와 붙여 온프레미스 회선을 여러 VPC 에 나눠 줍니다
- **언제 피어링이 나은가** — VPC 가 **두어 개뿐이고 가장 저렴해야** 하면 피어링입니다. 피어링은 연결 자체에 시간당 요금이 없습니다

## 요금 모델

- **연결(attachment)마다 시간당 요금 + 처리한 데이터량** 으로 붙습니다
- 그래서 VPC 두 개를 잇는 데 쓰면 피어링보다 비쌉니다. **개수가 늘수록** 관리 이득이 비용을 넘어섭니다
- 비용 문항에서 `VPC 두 개만` 이라는 조건이 보이면 TGW 는 오답 쪽입니다

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| VPC 피어링 | 피어링은 1:1·전이적 불가·연결 무료. TGW 는 허브·전이적 가능·유료 |
| [[aws-privatelink\|PrivateLink]] | TGW 는 **네트워크끼리** 붙입니다. PrivateLink 는 **서비스 하나만** 노출 |

## 시험 포인트

- [ ] `VPC 가 수십 개로 늘어난다` · `온프레미스까지 한 곳에서` → Transit Gateway
- [ ] `VPC 두 개만, 가장 저렴하게` → **피어링**
- [ ] `전이적` 이라는 낱말이 보이면 피어링은 탈락
- [ ] 대상 서비스 하나로만 제한해야 하면 TGW 가 아니라 PrivateLink
- [ ] CIDR 이 겹치면 피어링이 불가능합니다 — 그 경우도 TGW 검토 대상
- [ ] `멀티캐스트` → **Transit Gateway** (유일)
- [ ] `VPN 대역폭 부족` → TGW 에 붙여 **ECMP 로 터널 추가**

> 컨테이너를 돌리되 **서버가 없다**. `추가 인프라를 관리할 수 없다` 는 지문의 답

## 한 줄로 말하면

ECS·EKS 의 **시작 유형**입니다. 컨테이너를 얹을 EC2 노드를 두지 않으므로 패치·용량 계획·확장이 사라집니다.

## 핵심 개념

- **오케스트레이션과 시작 유형은 다른 축입니다** — 무엇이 컨테이너를 배치하느냐는 ECS 냐 EKS 냐이고, 그것을 **어디서 돌리느냐**가 Fargate 냐 EC2 냐입니다. 시험 문항은 대개 뒤쪽을 묻습니다
- **노드 관리가 없습니다** — AMI 패치, 노드 확장, 용량 계획이 전부 사라집니다. `추가 인프라를 관리할 수 없다` 가 이것을 지목합니다
- **태스크 단위로 자원을 잡습니다** — vCPU 와 메모리를 태스크 정의에 적고 그만큼만 냅니다
- **예약 작업** — EventBridge 일정으로 태스크를 띄웠다 내립니다. 10분마다 1~3분 도는 작업이라면 상시 인스턴스보다 훨씬 쌉니다
- **Lambda 로 안 될 때의 다음 후보**입니다 — 15분을 넘거나, 기존 컨테이너 이미지를 그대로 써야 하거나, Windows 컨테이너인 경우
- **권한은 태스크 역할**로 줍니다. 보안 그룹은 네트워크 접근이지 권한이 아닙니다
- **Fargate Spot** 으로 중단을 견디는 워크로드의 비용을 더 낮출 수 있습니다

## 요금 모델

- **태스크가 요청한 vCPU·메모리 × 실행 시간** 으로 붙습니다. 노드를 켜 두는 비용이 없습니다
- 그래서 **간헐적으로 짧게 도는 작업**에 유리하고, 24시간 꽉 채워 도는 워크로드라면 EC2 시작 유형이 더 쌀 수 있습니다
- **Compute Savings Plans 가 Fargate 에도 적용**됩니다 — EC2 전용 약정과 갈리는 지점입니다

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| ECS on EC2 | 노드를 내가 패치·확장하면 EC2, 아니면 Fargate |
| [[aws-lambda\|AWS Lambda]] | 15분 이내 짧은 이벤트면 Lambda, 그보다 길거나 컨테이너면 Fargate |
| [[amazon-eks\|Amazon EKS]] | EKS 는 오케스트레이터. Fargate 는 그 위에서 고르는 시작 유형 |

## 시험 포인트

- [ ] `추가 인프라를 관리할 수 없다` + 컨테이너 → **ECS on Fargate**
- [ ] `10분마다 1~3분` 같은 짧은 반복 → Fargate **예약 작업**
- [ ] 문항이 ECS/EKS 를 묻는지 **Fargate/EC2 를 묻는지** 먼저 가르세요
- [ ] Compute Savings Plans 는 Fargate·Lambda 까지 덮습니다
- [ ] 권한은 **태스크 역할**(보안 그룹 아님)

> `한 자리 밀리초` · `무제한 확장` · `서버리스` — 이 셋 중 하나가 보이면 여기다

## 한 줄로 말하면

완전 관리형 키-값·문서 데이터베이스입니다. 서버가 없고, 규모가 아무리 커져도 응답이 일정합니다.

## 핵심 개념

**용량 모드**

| | 언제 |
|---|---|
| **온디맨드** | 트래픽을 **예측할 수 없다** · 갑자기 튄다 · 개발/테스트 |
| **프로비저닝** | 예측 가능한 안정적 부하. **오토 스케일링**을 켜면 범위 안에서 조절 |
| 프로비저닝 + **예약 용량** | 꾸준한 기본 부하에 장기 약정 할인 |

- `비용을 아끼려는데 부하가 일정하다` → **프로비저닝 + 오토 스케일링**
- `블랙 프라이데이처럼 튄다` → **온디맨드**

**보조 인덱스**

- **글로벌 보조 인덱스(GSI)** — **다른 파티션 키**로 조회. 나중에 추가할 수 있습니다
- **로컬 보조 인덱스(LSI)** — 같은 파티션 키에 **다른 정렬 키**. **테이블 생성 시에만** 만들 수 있습니다
- `이미 있는 테이블을 다른 속성으로 조회해야` → **GSI** (LSI 는 불가능하다는 것이 판단 포인트)

**DAX** — DynamoDB 전용 인메모리 캐시. **마이크로초**로 떨어뜨립니다. 코드 수정이 거의 없습니다. `밀리초를 마이크로초로` 가 신호이고, 일반 캐시가 필요하면 [[amazon-elasticache\|ElastiCache]] 입니다.

**스트림** — 항목 변경을 이벤트로 흘립니다. **Lambda 를 붙여** 변경에 반응하는 처리를 만듭니다. `데이터가 바뀔 때마다 알림·집계` 의 표준 답입니다.

**글로벌 테이블** — 여러 리전에 **다중 활성** 복제. 모든 리전에서 읽고 씁니다. `전 세계 사용자가 각자 가까운 리전에 쓴다` 의 답입니다.

**TTL** — 만료 시각이 지난 항목을 **자동 삭제**합니다. 세션·임시 데이터 정리에 쓰고, **무료**라 비용 문항에서 유리합니다.

**일관성** — 기본은 최종 일관성, 요청 시 **강력한 일관성**(비용 두 배·지연 증가). `쓴 직후 반드시 읽혀야` 면 강력한 일관성입니다.

**핫 파티션** — 파티션 키가 한쪽에 몰리면 스로틀링이 납니다. 카디널리티가 높은 키를 고르는 것이 답입니다.

**백업** — 온디맨드 백업, **특정 시점 복구(35일)**. S3 로 내보내 [[amazon-athena\|Athena]] 로 분석할 수 있습니다.

## 요금 모델

- **읽기/쓰기 요청 단위 + 저장 용량** 입니다. 서버 요금이 없습니다
- 온디맨드가 단가는 높지만 유휴가 많으면 총액이 낮습니다
- **TTL 로 오래된 항목을 지우면 저장 요금이 바로 줍니다**
- 큰 객체는 **S3 에 두고 DynamoDB 에는 포인터만** — 400KB 항목 제한도 있고 비용도 유리합니다

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-rds\|RDS]]·[[amazon-aurora\|Aurora]] | 조인·복잡한 쿼리·트랜잭션 스키마가 필요하면 관계형 |
| [[amazon-documentdb\|DocumentDB]] | MongoDB 호환이 요구되면 DocumentDB |
| [[amazon-elasticache\|ElastiCache]] | 범용 캐시. DynamoDB 전용 캐시는 DAX |

## 시험 포인트

- [ ] `한 자리 밀리초` · `서버리스` · `무제한 확장` → DynamoDB
- [ ] `마이크로초` → **DAX**
- [ ] `기존 테이블을 다른 키로 조회` → **GSI** (LSI 는 생성 후 추가 불가)
- [ ] `변경될 때마다 처리` → **스트림 + Lambda**
- [ ] `여러 리전에서 읽고 쓴다` → **글로벌 테이블**
- [ ] `오래된 항목 자동 삭제` → **TTL**
- [ ] `쓴 직후 반드시` → 강력한 일관성 읽기
- [ ] 스로틀링 → **핫 파티션 키**

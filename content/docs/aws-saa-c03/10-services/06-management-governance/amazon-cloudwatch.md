> 지표·로그·경보. SAA 에서 가장 자주 걸리는 함정은 **메모리와 디스크는 기본 지표가 아니다**

## 한 줄로 말하면

AWS 자원의 지표를 모으고, 로그를 쌓고, 임계값을 넘으면 알리거나 조치합니다.

## 핵심 개념

> [!warning] 메모리와 디스크 사용량은 기본 지표에 없습니다
> 하이퍼바이저 밖에서 보는 것만 기본 지표입니다 — CPU·네트워크·디스크 I/O 는 있지만
> **메모리 사용률과 디스크 여유 공간은 없습니다.** 보려면 **CloudWatch 에이전트(통합 에이전트)** 를 깔아야 합니다.
> `메모리 기준으로 확장` · `디스크가 찰 때 알림` 지문의 답이 항상 이 에이전트입니다.

**지표와 경보**

- **사용자 지정 지표**를 직접 올릴 수 있습니다(고해상도 1초까지)
- **경보** — 임계값을 넘으면 **SNS 알림 · Auto Scaling 조정 · EC2 작업(중지·종료·복구)** 을 겁니다
- **EC2 자동 복구** — 하드웨어 장애 시 같은 인스턴스를 **IP·메타데이터를 유지한 채** 새 호스트에서 살립니다. `단일 인스턴스인데 하드웨어 장애에 대비` 의 답
- **복합 경보**로 여러 경보를 묶어 오탐을 줄입니다

**로그**

- **로그 그룹 · 스트림**으로 정리하고 **보존 기간**을 정합니다. 기본이 "무기한"이라 **보존 기간을 안 정하면 비용이 계속 쌓입니다** — 비용 문항의 단골
- **Logs Insights** — 로그를 쿼리로 조회합니다. 간단한 조사는 여기서 끝납니다
- **구독 필터** — 로그를 실시간으로 **Kinesis·Firehose·Lambda·OpenSearch** 로 흘려보냅니다. `로그를 실시간 분석·검색` 구성의 시작점
- **S3 로 내보내기** — 장기 보관은 S3 가 훨씬 쌉니다
- **지표 필터** — 로그에서 특정 패턴(예: `ERROR`, 루트 로그인)을 세어 **지표로 만들고 경보**를 겁니다. `로그에 이 문구가 나오면 알림` 의 답

**대시보드**는 리전을 넘어 한 화면에 모을 수 있습니다.

**Insights 계열** — Container Insights(ECS·EKS) · Lambda Insights · Contributor Insights(상위 기여자) · Application Insights.

## 요금 모델

- **사용자 지정 지표 · 경보 · 로그 수집량 · 로그 저장량 · 대시보드** 각각에 붙습니다
- 로그 비용을 줄이는 방법은 정해져 있습니다 — **보존 기간 설정**, 오래된 것은 **S3 로 내보내기**, 불필요한 상세 로그 끄기
- 상세 모니터링(1분)은 기본(5분)보다 비쌉니다

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-cloudtrail\|CloudTrail]] | **누가 어떤 API 를 호출했는지**. CloudWatch 는 **성능·상태** |
| [[aws-config\|Config]] | **구성이 규칙에 맞는지** |
| [[amazon-opensearch-service\|OpenSearch]] | 복잡한 로그 검색·대시보드 |
| AWS X-Ray | 요청이 서비스 사이를 지나는 **추적** |

## 시험 포인트

- [ ] `메모리 사용률` · `디스크 여유 공간` → **CloudWatch 에이전트** 설치
- [ ] `로그에 특정 문구가 나오면 알림` → **지표 필터 + 경보**
- [ ] `단일 인스턴스 하드웨어 장애 대비` → **EC2 자동 복구 경보**
- [ ] `로그 비용이 계속 늘어난다` → **보존 기간 설정 + S3 내보내기**
- [ ] `로그를 실시간으로 검색해야` → **구독 필터 → Firehose → OpenSearch**
- [ ] `누가 그 자원을 지웠나` → CloudWatch 가 아니라 **CloudTrail**

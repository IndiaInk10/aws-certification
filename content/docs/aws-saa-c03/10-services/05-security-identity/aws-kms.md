> 암호화 문항의 기본값. **CloudHSM 은 "전용 하드웨어"가 지문에 있을 때만**

## 한 줄로 말하면

암호화 키를 만들고 관리합니다. S3·EBS·RDS·DynamoDB 등 거의 모든 서비스가 KMS 로 미사용 데이터를 암호화합니다.

## 핵심 개념

**키의 세 종류**

| | 특징 |
|---|---|
| **AWS 관리형** | 서비스가 알아서. 무료지만 **정책을 내가 못 씁니다** |
| **고객 관리형(CMK)** | 내가 정책·교체·감사를 통제. **계정 간 공유 가능** |
| **KMS 외부 가져오기** | 내가 만든 키 재료를 올립니다. 규정 준수용 |

- **계정을 넘어 공유하려면 고객 관리형**이어야 합니다. `다른 계정에서 암호화된 스냅샷을 복원해야` 라면 AWS 관리형 키로는 불가능하고, 고객 관리형 키로 다시 암호화해 공유하는 것이 답입니다
- **자동 키 교체** — 고객 관리형 키는 연 단위 자동 교체를 켤 수 있습니다. 이전 키 자료는 남아 있어 예전 데이터도 계속 읽힙니다
- **키 정책**이 최종 권한입니다. IAM 정책만으로는 부족하고 **키 정책에도 허용이 있어야** 합니다. `권한을 줬는데 KMS 오류` 지문이 여기서 나옵니다
- **봉투 암호화** — 데이터 키로 데이터를 암호화하고, 그 데이터 키를 KMS 키로 감쌉니다. 큰 파일을 KMS 에 직접 넘기지 않는 이유입니다
- **CloudTrail 에 모든 키 사용이 기록**됩니다. `누가 언제 복호화했는지 감사` 의 답
- **리전 서비스**입니다 — 다른 리전으로 스냅샷을 복사하면 **대상 리전의 키로 다시 암호화**해야 합니다. **다중 리전 키**를 쓰면 같은 키 자료를 여러 리전에서 씁니다
- **삭제는 즉시 안 됩니다** — 7~30일 대기 기간을 둡니다

## 요금 모델

- **키마다 월 요금 + API 호출 수** 로 붙습니다
- **AWS 관리형 키는 무료**입니다. 그래서 `가장 저렴하게 암호화` 면 서비스 기본 암호화(SSE-S3, AWS 관리형 KMS 키)가 답이고, 고객 관리형은 통제가 필요할 때만입니다
- 호출이 많으면 요금이 커집니다 — S3 **버킷 키**를 켜면 KMS 호출이 크게 줄어 비용이 내려갑니다

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-cloudhsm\|CloudHSM]] | 전용 단일 테넌트 HSM · FIPS 140-2 레벨 3 · **키를 AWS 도 못 봅니다** |
| [[aws-secrets-manager\|Secrets Manager]] | KMS 는 **키**, Secrets Manager 는 **비밀번호 같은 값** |
| [[aws-certificate-manager\|ACM]] | ACM 은 **TLS 인증서** |

## 시험 포인트

- [ ] 암호화 지문의 기본값은 **KMS**. `전용 HSM`·`FIPS 레벨 3` 가 있을 때만 CloudHSM
- [ ] `다른 계정과 공유` · `키 정책을 직접` → **고객 관리형 키**
- [ ] `연 1회 자동 교체` → 고객 관리형 키 자동 교체
- [ ] `권한은 줬는데 접근 거부` → **키 정책** 확인
- [ ] `누가 복호화했는지` → **CloudTrail**
- [ ] 리전 간 복사는 **대상 리전 키로 재암호화**, 아니면 **다중 리전 키**
- [ ] S3 KMS 요금이 크다 → **S3 버킷 키**

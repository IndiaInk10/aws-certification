> KMS 로 안 되는 **딱 그 조건**에만 답이 된다 — 전용 하드웨어 · FIPS 140-2 레벨 3 · AWS 도 못 보는 키

## 한 줄로 말하면

나만 쓰는 **전용 하드웨어 보안 모듈**입니다. 키를 AWS 조차 접근할 수 없는 형태로 보관합니다.

## 핵심 개념

- **단일 테넌트**입니다. KMS 는 여러 고객이 공유하는 관리형 서비스인 반면 CloudHSM 은 내 클러스터입니다
- **FIPS 140-2 레벨 3** 인증이 필요하다는 요구가 지문에 있으면 CloudHSM 입니다
- **키를 내가 전적으로 통제**합니다 — 그래서 **잃어버리면 AWS 도 복구해 주지 못합니다.** 백업과 클러스터 이중화가 내 책임입니다
- **AWS 는 키를 볼 수 없습니다.** `AWS 직원조차 접근할 수 없어야` 라는 조건의 답
- **VPC 안에** 배치되며, 여러 AZ 에 HSM 을 두어 고가용성을 만듭니다
- **KMS 사용자 지정 키 스토어**로 KMS 뒤에 CloudHSM 을 붙일 수 있습니다 — 편의는 KMS, 키 보관은 HSM
- **SSL 오프로드·Oracle TDE·사설 CA 키 보관** 같은 특수 용도가 있습니다
- **운영 부담이 큽니다.** 클러스터 관리·사용자 관리·백업이 모두 내 몫이라, `운영 부담 최소` 지문에서는 오답 쪽입니다

## 요금 모델

- **HSM 인스턴스마다 시간당 요금** 입니다. KMS 보다 훨씬 비쌉니다
- 고가용성을 위해 여러 대를 두면 그만큼 배가 됩니다
- `가장 저렴하게` · `운영 부담 최소` 가 지문에 있으면 CloudHSM 은 거의 오답입니다

## 시험 포인트

- [ ] `FIPS 140-2 레벨 3` · `전용 HSM` · `AWS 도 키에 접근 불가` → **CloudHSM**
- [ ] 그 조건이 없으면 **KMS** 가 답입니다
- [ ] `KMS 의 편의 + HSM 보관` → **사용자 지정 키 스토어**
- [ ] `운영 부담 최소`·`비용 최소` 지문에서 CloudHSM 은 오답
- [ ] 키 분실 시 AWS 가 복구해 준다는 보기 → 오답

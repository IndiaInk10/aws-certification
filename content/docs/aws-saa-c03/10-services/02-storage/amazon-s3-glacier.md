> 아카이브 3종. **꺼내는 속도**로 갈리고, 최소 보관 기간이 함정이 된다

## 한 줄로 말하면

S3 안의 **장기 보관용 스토리지 클래스 묶음**입니다. 저장 단가를 크게 낮추는 대신 꺼내는 데 비용과 시간이 붙습니다.

## 핵심 개념

| 클래스 | 꺼내는 시간 | 언제 | 최소 보관 |
|---|---|---|---|
| **Glacier Instant Retrieval** | **밀리초 (즉시)** | 분기 1회쯤 보지만 볼 때는 바로 | 90일 |
| **Glacier Flexible Retrieval** | 분~시간 (옵션에 따라) | 연 1~2회 · 기다려도 되는 백업 | 90일 |
| **Glacier Deep Archive** | **12시간** | 연 1회 미만 · 규정 때문에 두는 것 | 180일 |

- **세 클래스를 가르는 것은 오직 꺼내는 속도**입니다. `즉시` 가 지문에 있으면 Instant Retrieval 하나만 남습니다
- `언제든 즉시 접근` 이 조건이면 **Flexible 과 Deep Archive 는 그 자리에서 탈락**합니다
- 반대로 `며칠 걸려도 된다` · `연 1회 미만` 이면 Deep Archive 가 가장 쌉니다

**최소 보관 기간이 함정입니다**

- 최소 기간 전에 지우거나 다른 클래스로 옮기면 **남은 기간만큼 요금이 청구**됩니다
- 그래서 `한 달 뒤 삭제` 같은 짧은 수명의 데이터를 Glacier 로 내리면 오히려 비쌉니다

**S3 Glacier 볼트는 다른 이야기입니다**

- 위 세 개는 **S3 의 스토리지 클래스**이고, 수명 주기 정책으로 전환합니다
- 별도의 **Glacier 볼트**(볼트 잠금 정책, WORM)는 예전 방식입니다. 시험에서 `객체 잠금` 과 `볼트 잠금` 이 함께 보기로 나오면 **S3 버킷 이야기면 객체 잠금**입니다

**규정 준수와 함께 나올 때** — `N년 보관 + 아무도 삭제 불가` 는 **Deep Archive + 객체 잠금 규정 준수 모드** 조합으로 자주 나옵니다.

## 요금 모델

- **저장 단가가 S3 계열 중 가장 낮습니다.** Deep Archive 가 가장 낮습니다
- 대신 **꺼낼 때 요금**이 붙고, 꺼내는 속도를 빠르게 고를수록 비쌉니다
- **최소 보관 기간**을 못 채우면 조기 삭제 요금이 붙습니다
- 아카이브마다 메타데이터 오버헤드가 있어 **아주 작은 파일 수백만 개**를 그대로 올리면 예상보다 비쌉니다

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| Standard-IA | IA 는 **즉시 조회**되지만 저장 단가가 더 높습니다. 분기 1회면 Glacier Instant Retrieval 이 쌉니다 |
| [[amazon-s3\|Intelligent-Tiering]] | 패턴을 **모를 때** 씁니다. 기간이 명시돼 있으면 수명 주기로 Glacier 에 내리는 쪽 |
| One Zone-IA | 더 싸지만 **AZ 하나**뿐입니다. 규정 보관용에는 부적절 |

## 시험 포인트

- [ ] `즉시` · `밀리초` 가 있으면 → Glacier Instant Retrieval (나머지 아카이브 탈락)
- [ ] `12시간 걸려도 된다` · `연 1회 미만` → Deep Archive
- [ ] `N년 보관 + 누구도 삭제 불가` → Deep Archive + **객체 잠금 규정 준수 모드**
- [ ] 짧게 두고 지울 데이터를 Glacier 로 내리는 보기는 **최소 보관 기간** 때문에 오답
- [ ] 아카이브는 **S3 의 클래스**입니다. 수명 주기 정책으로 전환합니다

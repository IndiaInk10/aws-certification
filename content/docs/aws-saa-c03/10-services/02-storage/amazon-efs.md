> 여러 Linux 인스턴스가 함께 쓰는 리전 단위 NFS. "공유"와 "자동 확장" 두 낱말이 신호다

## 한 줄로 말하면

**여러 EC2 가 동시에 마운트하는 완전관리형 파일 시스템**입니다. 용량을 미리 잡지 않고, 리전 안 여러 가용 영역에 걸쳐 있습니다.

## 핵심 개념

- **NFS 프로토콜 · POSIX 호환** — 표준 파일 시스템 구조가 필요하다는 지문이 나오면 객체 스토리지가 아니라 이쪽입니다
- **리전 단위** — 가용 영역마다 **탑재 대상(mount target)** 이 생기고, 각 AZ 의 인스턴스가 그 AZ 의 탑재 대상으로 붙습니다. `각 AZ 에 탑재 대상` 이라는 표현이 나오면 EFS 입니다
- **용량을 프로비저닝하지 않습니다** — 넣으면 늘고 지우면 줍니다. `자동으로 확장` 조건에 그대로 맞습니다
- **가용성 등급 두 가지**
  - **표준(리전)** — 여러 AZ 에 저장. 최대 내구성
  - **One Zone** — AZ 하나에만. 더 싸지만 그 AZ 를 잃으면 끝
- **수명 주기 관리** — 정해진 기간 접근되지 않은 파일을 **IA 계층으로 자동 이동**합니다. 비용 문항의 단골
- **성능·처리량 모드** — 대부분 기본값으로 충분하지만, 처리량이 부족하면 프로비저닝 모드로 올릴 수 있습니다
- **접근 지점(access point)** — 애플리케이션마다 진입 디렉터리와 POSIX 사용자를 고정해 접근을 나눕니다
- **AWS Backup 지원** — 교차 리전 복사로 RPO 를 맞출 수 있습니다
- **Linux 전용입니다** — SMB 가 필요하면 [[amazon-fsx\|FSx for Windows File Server]] 입니다

## 요금 모델

- **실제로 저장된 용량** 기준입니다. EBS 처럼 미리 잡아 둔 크기가 아닙니다
- IA 계층은 저장 단가가 낮은 대신 **읽어 올 때 요금**이 붙습니다. 자주 읽는 파일을 내리면 손해입니다
- One Zone 은 표준보다 쌉니다 — 내구성과 맞바꾸는 것입니다
- 같은 용량이면 S3 보다 GB 단가가 높습니다. **수백 TB 규모의 문서 저장소**라면 S3 쪽이 훨씬 쌉니다

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-ebs\|Amazon EBS]] | EFS 는 **파일·리전·여러 인스턴스**, EBS 는 **블록·단일 AZ·한 인스턴스** |
| [[amazon-s3\|Amazon S3]] | S3 는 API 로 접근. **표준 파일 시스템 구조**가 필요하면 EFS, 규모가 매우 크고 통째로 넣고 꺼내면 S3 |
| [[amazon-fsx\|FSx for Windows]] | EFS 는 **NFS/Linux**, FSx for Windows 는 **SMB/AD**. Windows 가 보이면 EFS 가 아닙니다 |
| FSx for Lustre | EFS 는 범용 공유, Lustre 는 **HPC·머신러닝용 초고속** |

## 시험 포인트

- [ ] `여러 Linux 인스턴스가 같은 파일을 동시에` → EFS
- [ ] `각 가용 영역에 탑재 대상` → EFS 의 구조 그대로
- [ ] `표준 파일 시스템 구조` + `자동 확장` → EFS (S3 탈락)
- [ ] `최대 내구성` 이 붙으면 One Zone 은 탈락
- [ ] `Lustre 클라이언트` 라고 프로토콜을 못 박으면 **EFS 를 Lustre 로 구성할 수 없습니다** — 없는 설정입니다
- [ ] 인스턴스 스토어에 있던 데이터를 **내구성 있게** 옮기라면 EFS 가 답이 되는 경우가 많습니다

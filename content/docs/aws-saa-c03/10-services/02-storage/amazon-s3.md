> 객체 스토리지. SAA 에서 가장 넓게 나오는 서비스 — 클래스·수명 주기·암호화·접근 제어가 전부 문항이 된다

## 한 줄로 말하면

파일을 **통째로 넣고 통째로 꺼내는** 무제한 객체 저장소이고, 그 위에 **비용·보호·접근 제어 기능이 층층이** 붙어 있습니다. SAA 는 저장 자체가 아니라 **그 층들 중 어느 것을 켤 것인가**를 묻습니다.

## 핵심 개념

**스토리지 클래스 — 접근 빈도 한 축**

| 클래스 | 언제 | 꺼내는 비용 | 최소 보관 |
|---|---|---|---|
| Standard | 자주 | 없음 | 없음 |
| **Intelligent-Tiering** | **패턴을 모를 때** | 없음 (모니터링 수수료) | 없음 |
| Standard-IA | 가끔, 즉시 필요 | 있음 | 30일 |
| One Zone-IA | 가끔, **다시 만들 수 있는** 데이터 | 있음 | 30일 |
| Glacier Instant Retrieval | 분기 1회, **즉시** | 있음 | 90일 |
| Glacier Flexible Retrieval | 연 1~2회, 분~시간 | 있음 | 90일 |
| Glacier Deep Archive | 연 1회 미만, **12시간** | 있음 | 180일 |

- **아는 패턴이면 수명 주기, 모르는 패턴이면 Intelligent-Tiering.** 이 한 줄이 클래스 문항의 절반입니다.
- One Zone-IA 는 **가용 영역 하나에만** 저장합니다. 잃어도 다시 만들 수 있는 데이터에만 씁니다.
- Intelligent-Tiering 은 **128KB 미만 객체를 저비용 계층으로 내리지 않습니다.** 지문에 객체 크기가 적혀 있으면 그 이유입니다.

**수명 주기 정책** — 클래스 전환 · 만료 · **비현행(이전) 버전 만료** · **불완전한 멀티파트 업로드 삭제**. 뒤의 둘은 조용히 쌓이는 비용이라 문항으로 자주 나옵니다.

**스토리지 클래스 분석** — 어떤 객체를 언제 IA 로 내려야 할지 **데이터로 알려 줍니다.** `수명 주기 기간을 얼마로 잡아야 할지 모르겠다` 의 답입니다. Standard 와 Standard-IA 만 분석하고 Glacier 는 보지 않습니다.

**버전 관리와 보호**

- **버전 관리** — 덮어쓰기·삭제를 되돌립니다. 삭제하면 삭제 표식만 붙고 이전 버전은 남습니다
- **MFA 삭제** — 버전을 영구 삭제할 때 추가 인증을 요구합니다. 버전 관리가 켜져 있어야 씁니다
- **객체 잠금** — 정해진 기간 동안 아무도 못 지웁니다
  - **보존 기간** — 기간을 정해 둘 때. **거버넌스** 모드는 특별 권한으로 해제 가능, **규정 준수** 모드는 루트도 불가
  - **법적 보존** — **기간이 없습니다.** 해제할 때까지 유지

**암호화 — 키를 누가 쥐느냐**

| | 키를 만드는 쪽 | 키를 보관하는 쪽 | 언제 |
|---|---|---|---|
| SSE-S3 | AWS | AWS | 기본값 |
| **SSE-KMS** | 내가 | KMS | **키 사용 기록이 CloudTrail 에 남아야** 할 때 |
| SSE-C | 내가 | **내가** | AWS 에 키를 두면 안 될 때 |
| 클라이언트 측 | 내가 | 내가 | 올리기 전에 이미 암호화 |

기본 암호화는 **앞으로 올라오는 객체에만** 적용됩니다. 이미 있는 것은 배치 작업으로 다시 써야 합니다.

- **SSE-KMS 는 KMS API 한도에 걸립니다.** 객체마다 KMS 를 부르기 때문에, 요청이 폭주하면 **스로틀링**이 납니다. 답은 **S3 버킷 키**를 켜는 것 — KMS 호출이 크게 줄어 한도와 요금이 함께 해결됩니다
- **SSE-C 는 HTTPS 가 필수**이고 키를 **요청 헤더로 매번** 보내야 합니다. AWS 는 키를 저장하지 않습니다
- **암호화하지 않은 업로드를 막으려면 버킷 정책**에서 `s3:x-amz-server-side-encryption` 헤더가 없는 PUT 을 **명시적으로 거부**합니다. 기본 암호화만 켜는 것과는 다릅니다 — 정책은 **거부**하고, 기본 암호화는 **조용히 암호화**합니다

**접근 제어**

- **퍼블릭 액세스 차단** — 계정 수준에서 켜면 버킷 정책이 무엇이든 공개되지 않습니다
- **버킷 정책** — 리소스 기반 정책. 교차 계정 접근에 필수. `aws:PrincipalOrgID` 로 조직 전체를 한 줄에
- **사전 서명 URL** — 특정 객체에 기간 한정 접근을 줍니다. **URL 을 만든 주체의 권한을 그대로 물려받습니다** — 그래서 권한이 큰 역할로 만들면 그만큼 열립니다
- **오리진 액세스 제어(OAC)** — CloudFront 에만 버킷을 열어 줍니다. **최종 사용자 구분이 아닙니다**
- **액세스 포인트** — 버킷 하나에 **용도별 진입점**을 만들어 각자 정책을 붙입니다. 버킷 정책 하나가 비대해지는 것을 막습니다. `팀마다 다른 접두사에만 접근` 의 답
- **Object Lambda** — 꺼낼 때 Lambda 를 태워 **원본을 바꾸지 않고** 변형해서 내보냅니다. `같은 데이터를 어떤 팀에는 개인정보를 가려서` · `형식을 바꿔서` 의 답입니다. 사본을 여러 개 만드는 보기와 대비됩니다
- **CORS** — 다른 도메인의 웹 페이지가 버킷을 부르려면 CORS 헤더를 설정해야 합니다. `웹 폰트/이미지가 다른 도메인에서 안 불러와진다` 의 원인
- **액세스 로그** — 모든 요청을 다른 버킷에 기록합니다. **로그 대상 버킷을 자기 자신으로 두면 로그가 로그를 낳아 무한히 커집니다** — 이 함정이 그대로 출제됩니다

**성능과 전송**

- **접두사당 초당 3,500 PUT/COPY/POST/DELETE · 5,500 GET/HEAD.** 접두사를 나누면 그만큼 배가 됩니다. `요청이 몰려 503 이 난다` 면 접두사 분산이 답입니다
- **멀티파트 업로드** — 100MB 넘으면 권장, **5GB 넘으면 필수**. 병렬로 올려 빠르고, 실패한 부분만 다시 올립니다
- **Transfer Acceleration** — 먼 곳에서 **올릴** 때 엣지를 경유
- **바이트 범위 가져오기** — 파일의 일부만, 또는 여러 조각을 **병렬로** 내려받습니다
- **S3 Select · Glacier Select** — 객체 **하나 안에서** SQL 로 필요한 행·열만 꺼냅니다. 전부 내려받아 애플리케이션에서 거르는 것보다 전송량과 CPU 가 줍니다. **여러 파일에 걸친 조회는 [[amazon-athena\|Athena]]** 입니다
- **S3 Batch Operations** — 수십억 개 객체에 **일괄 작업**(복사·암호화·태그·Lambda 호출)을 걸고 재시도·진행률을 관리합니다. `기존 객체를 전부 다시 암호화` 의 답
- 게이트웨이 VPC 엔드포인트(인터넷을 안 탄다, 무료)

**이벤트 알림** — `ObjectCreated`·`ObjectRemoved`·`ObjectRestore` 등을 SNS·SQS·Lambda 로 보냅니다. **EventBridge 로 보내면** JSON 규칙으로 더 세밀하게 거르고 대상도 여럿으로 늘릴 수 있습니다.

**복제**

- 교차 리전(CRR)·같은 리전(SRR)이 있고, **양쪽 버킷 모두 버전 관리가 켜져 있어야** 합니다 — 이 전제가 빠진 보기가 오답입니다
- **복제는 전이되지 않습니다** — A→B, B→C 가 있어도 A 의 객체가 C 로 가지 않습니다
- **기존 객체는 복제되지 않습니다.** 이미 있는 것까지 옮기려면 **배치 복제**를 씁니다
- **복제 시간 제어(RTC)** 를 켜면 복제 완료 시간이 보장되고 지표가 나옵니다

**정적 웹사이트 호스팅** — 켜면 리전별 URL 이 생깁니다. **403 이 나면 퍼블릭 읽기를 허용하는 버킷 정책이 없는 것**입니다(퍼블릭 액세스 차단도 함께 확인).

## 요금 모델

- **저장한 용량 · 요청 수 · 나가는 데이터 전송** 세 갈래로 붙습니다
- IA 와 Glacier 계열은 **저장이 싼 대신 꺼낼 때 요금**이 붙고 **최소 보관 기간**이 있습니다. 자주 읽는 데이터를 IA 로 내리면 오히려 비싸집니다
- 들어오는 전송은 대체로 무료, **나가는 전송에 돈이 붙습니다.** 게이트웨이 엔드포인트를 쓰면 NAT 를 거치지 않아 그 비용이 사라집니다
- **요청자 지불** 을 켜면 내려받는 쪽이 요청·전송 요금을 냅니다. 저장 요금은 여전히 소유자 몫입니다

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-ebs\|Amazon EBS]] | S3 는 **객체**, EBS 는 **블록**. EBS 는 인스턴스 한 대에 붙고 단일 AZ 입니다 |
| [[amazon-efs\|Amazon EFS]] | S3 는 API 로 접근, EFS 는 **파일 시스템으로 마운트**. 표준 파일 구조가 필요하면 EFS |
| Transfer Acceleration vs CloudFront | Transfer Acceleration 은 **올리는** 것을, CloudFront 는 **내려받는** 것을 빠르게 합니다 |
| 객체 잠금 vs 버전 관리 | 잠금은 **못 지우게**, 버전 관리는 **지워도 되돌리게** |
| S3 Select vs [[amazon-athena\|Athena]] | Select 는 **객체 하나** 안. 여러 파일·조인은 Athena |
| 액세스 포인트 vs 버킷 정책 | 진입점마다 정책을 나누느냐, 하나에 몰아넣느냐 |
| Object Lambda vs 사본 만들기 | Object Lambda 는 **원본 하나**로 여러 형태를 내보냅니다 |

## 시험 포인트

- [ ] `접근 패턴을 모른다` → Intelligent-Tiering / `30일 후` 처럼 기간 명시 → 수명 주기
- [ ] `언제든 즉시 접근` 이 있으면 Glacier 계열이 전부 탈락
- [ ] `키 사용 내역을 감사` → SSE-KMS 고객 관리형 키
- [ ] `누구도 지울 수 없다` → 객체 잠금 **규정 준수** 모드 / `기간이 정해지지 않음` → 법적 보존
- [ ] 버전 관리 버킷에서 용량이 안 줄면 → **비현행 버전 만료 규칙**이 없는 것
- [ ] 용량과 객체 수가 안 맞으면 → **불완전한 멀티파트 업로드**
- [ ] `인터넷을 타지 않고 S3 에` → 게이트웨이 VPC 엔드포인트 (무료, S3·DynamoDB 뿐)
- [ ] `팀마다 개인정보를 가려서 같은 데이터를` → **Object Lambda**
- [ ] `기존 객체를 전부 다시 처리` → **S3 Batch Operations** (기본 암호화는 새 객체만)
- [ ] `객체 하나에서 일부 행만` → **S3 Select** / 여러 파일이면 Athena
- [ ] 복제가 안 된다 → **양쪽 버전 관리** · **기존 객체는 배치 복제**
- [ ] SSE-KMS 스로틀링·요금 → **S3 버킷 키**
- [ ] `암호화 안 된 업로드를 거부` → **버킷 정책의 명시적 Deny**
- [ ] 요청이 몰려 503 → **접두사 분산** (접두사당 3,500 PUT / 5,500 GET)
- [ ] 로그 버킷을 자기 자신으로 두는 보기 → **무한 루프**, 오답
- [ ] 정적 웹사이트 403 → 퍼블릭 읽기 **버킷 정책** 확인
- [ ] 사전 서명 URL 은 **만든 주체의 권한**을 물려받습니다

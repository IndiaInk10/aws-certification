> 온프레미스를 AWS 스토리지에 잇는다. **지금 어떤 방식으로 마운트돼 있는지**가 답을 정한다

## 한 줄로 말하면

온프레미스 애플리케이션은 그대로 두고 **저장만 AWS 로 옮기는** 하이브리드 게이트웨이입니다. 세 종류가 각각 다른 프로토콜로 붙습니다.

## 핵심 개념

| 종류 | 온프레미스에서 보이는 모습 | 실제 저장 |
|---|---|---|
| **S3 파일 게이트웨이** | NFS · SMB 파일 공유 | **S3 객체** |
| **볼륨 게이트웨이** | iSCSI 블록 장치 | S3 + EBS 스냅샷 |
| **테이프 게이트웨이** | 가상 테이프 라이브러리 | S3 Glacier |
| **FSx 파일 게이트웨이** | SMB 파일 공유 | FSx for Windows File Server |

**S3 파일 게이트웨이**

- 파일을 쓰면 **그 순간 S3 객체가 됩니다.** 그래서 S3 수명 주기 정책으로 오래된 것을 싼 계층에 내릴 수 있습니다
- 자주 쓰는 파일은 **로컬 캐시**에서 나와 지연이 유지됩니다
- `온프레미스 용량이 부족한데 앱은 그대로` 라는 지문의 기본 답입니다

**볼륨 게이트웨이 — 한 번 더 갈립니다**

- **캐시형(cached)** — 주 데이터는 S3 에, **자주 쓰는 것만 로컬 캐시**. 온프레미스 용량이 부족할 때
- **저장형(stored)** — 주 데이터는 **온프레미스에 전부** 두고 스냅샷만 S3 로. **전체 데이터셋에 저지연 접근이 필요한 DR** 구성
- 지문이 "전체 데이터에 지연 없이 접근해야 하는가"를 묻고 있다면 그것이 갈림길입니다

**테이프 게이트웨이** — 기존 백업 소프트웨어에는 **테이프 장치로 보이고** 실제로는 Glacier 로 갑니다. `테이프 라이브러리를 없애고 싶다` 가 신호입니다.

## 요금 모델

- **저장된 데이터**(S3·Glacier 단가)와 **게이트웨이를 통한 데이터 전송**에 붙습니다
- 로컬 캐시 디스크는 온프레미스 자원이라 AWS 요금과 무관합니다
- 새 NAS 장비를 사거나 지원 계약을 갱신하는 비용을 대신하는 자리라, 비용 문항에서 `장비를 증설하는 대신` 으로 등장합니다

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-datasync\|AWS DataSync]] | DataSync 는 **옮기는** 도구(일회성·주기적 전송), Storage Gateway 는 **상시 연결해 쓰는** 것 |
| Snow Family | Snow 는 **물리 장치로 대량 이전**. 회선이 감당 못 할 때 |
| [[amazon-fsx\|FSx 파일 게이트웨이]] | 저장이 **S3 객체**면 S3 파일 게이트웨이, **Windows 파일 시스템**이면 FSx 파일 게이트웨이 |

## 시험 포인트

- [ ] `NFS·SMB 로 쓰는데 저장은 S3` → S3 파일 게이트웨이
- [ ] `iSCSI 블록 장치` → 볼륨 게이트웨이 (전체 데이터 저지연이면 **저장형**)
- [ ] `기존 백업 소프트웨어` · `가상 테이프` → 테이프 게이트웨이
- [ ] `주기적으로 계속 동기화` 는 게이트웨이가 아니라 **DataSync**
- [ ] 저장이 S3 객체가 되면 **NTFS 권한이 보존되지 않습니다** — Windows 권한 요구가 있으면 FSx 쪽

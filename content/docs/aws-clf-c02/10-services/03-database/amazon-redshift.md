## 한 줄로 말하면

여기저기 흩어진 데이터를 한곳에 모아 두고 대규모 분석 쿼리를 돌리는 **관리형 데이터 웨어하우스**입니다.

## 핵심 개념

- **데이터 웨어하우스** — 여러 시스템에 나뉘어 있는 과거 데이터를 한곳에 모아 두고 **분석과 리포팅**에 씁니다. 실시간 거래를 접수하는 용도가 아닙니다.
- **OLAP** — 대량의 행을 훑어 집계하는 질의에 최적화되어 있습니다. 반대로 건건이 읽고 쓰는 트랜잭션(OLTP)은 [[amazon-rds]]의 영역입니다.
- **열 기반 저장과 병렬 처리** — 데이터를 열 단위로 저장하고 여러 노드에 나눠 병렬로 처리하므로, 큰 테이블을 집계할 때 훨씬 빠릅니다. 페타바이트 규모까지 확장됩니다.
- **SQL을 그대로 씁니다** — 기존 BI 도구와 SQL 클라이언트를 그대로 붙일 수 있습니다. [[amazon-quicksight]]로 시각화하는 조합이 흔합니다.
- **Redshift Spectrum** — [[amazon-s3]]에 있는 데이터를 웨어하우스로 옮기지 않고 그 자리에서 조회할 수 있습니다.
- **Redshift Serverless** — 클러스터를 직접 관리하고 싶지 않으면 서버리스로 쓸 수 있습니다. 쿼리를 돌린 만큼만 냅니다.

## 요금 모델

- 프로비저닝 방식은 **노드를 실행한 시간(시간당) × 노드 수**가 기준이고, 노드 유형에 따라 시간당 요금이 달라집니다.
- **Redshift Serverless**는 실제로 쿼리를 처리한 만큼 **RPU(Redshift 처리 단위) 시간**으로 과금합니다.
- **관리형 스토리지(GB-월)**, 백업, Spectrum으로 **S3에서 스캔한 데이터양**이 별도로 붙습니다.
- 1년·3년 **예약 인스턴스**로 할인받을 수 있습니다.
- 클러스터를 띄워 놓기만 해도 노드 요금이 계속 나갑니다. 쓰지 않을 때는 일시 중지하시거나 서버리스를 쓰시는 편이 좋습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-rds]] | Redshift는 분석(OLAP), RDS는 트랜잭션(OLTP)입니다. "주문을 접수한다"면 RDS, "지난 3년 매출을 집계한다"면 Redshift입니다 |
| [[amazon-athena]] | Athena는 S3 데이터를 **옮기지 않고** 즉석에서 SQL로 조회하고 스캔한 만큼만 냅니다. 데이터를 적재해 **반복 분석**하면 Redshift입니다 |
| [[amazon-emr]] | EMR은 Hadoop·Spark 같은 빅데이터 **프레임워크**를 돌리는 클러스터이고, Redshift는 SQL 웨어하우스입니다 |
| [[amazon-quicksight]] | QuickSight는 결과를 **보여 주는** BI 대시보드이고, Redshift는 그 뒤에서 데이터를 담고 계산하는 쪽입니다 |

## 시험 포인트

- [ ] "**데이터 웨어하우스**", "**비즈니스 인텔리전스**", "**과거 데이터 분석**", "**페타바이트급**", "**복잡한 집계 쿼리**" → Redshift
- [ ] **트랜잭션 처리 = RDS / 분석 = Redshift** — 둘 다 SQL을 쓰기 때문에 가장 자주 헷갈리는 짝입니다
- [ ] 함정: "S3 데이터를 **가끔** 조회한다"면 Athena가 더 맞습니다. 적재와 반복 분석이면 Redshift입니다
- [ ] 함정: Redshift는 실시간 스트리밍 처리 서비스가 아닙니다. 그것은 [[amazon-kinesis]] 쪽입니다
- [ ] Redshift는 데이터베이스이면서 **분석 카테고리 서비스**로도 출제된다는 점을 기억해 두시기 바랍니다

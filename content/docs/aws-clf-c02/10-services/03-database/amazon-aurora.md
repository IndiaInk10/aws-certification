## 한 줄로 말하면

AWS가 클라우드에 맞게 새로 만든 관계형 데이터베이스 엔진이고, **MySQL·PostgreSQL과 호환**됩니다.

## 핵심 개념

- **RDS 제품군의 한 엔진입니다** — Aurora는 [[amazon-rds]]에서 고르는 엔진 중 하나입니다. 그래서 자동 백업, 패치, 복구 같은 관리형 이점을 그대로 가져갑니다.
- **MySQL·PostgreSQL 호환** — 기존 애플리케이션 코드와 드라이버를 거의 그대로 두고 성능만 올릴 수 있습니다. 옮겨 갈 때 부담이 적다는 점이 강점입니다.
- **높은 성능** — AWS는 표준 MySQL 대비 최대 5배, 표준 PostgreSQL 대비 최대 3배의 처리량을 제시하고 있습니다. 문제에서 "관계형인데 성능이 더 필요하다"가 나오면 이 지점입니다.
- **스토리지 구조** — 데이터를 세 개 가용 영역에 여섯 벌로 복제해 두고, 스토리지 용량은 쓰는 만큼 자동으로 늘어납니다. 미리 크기를 잡아 둘 필요가 없습니다.
- **Aurora Serverless** — 수요에 따라 용량이 자동으로 오르내립니다. 트래픽이 들쭉날쭉하거나 예측하기 어려운 워크로드에 씁니다.
- **비용 메시지** — 상용 데이터베이스에 준하는 성능과 가용성을 훨씬 낮은 비용으로 제공한다는 것이 AWS가 내세우는 포인트입니다.

## 요금 모델

- **DB 인스턴스를 실행한 시간(시간당)** 이 기본 축입니다.
- **스토리지는 실제로 쓴 만큼(GB-월)** 과금하며 자동으로 늘어납니다. 구성에 따라 **I/O 요청 수**에도 요금이 붙습니다.
- **백업 스토리지**와 리전 밖으로 나가는 **데이터 전송**이 별도입니다.
- **Aurora Serverless**는 인스턴스 시간 대신 **ACU(Aurora 용량 단위) 사용량**을 기준으로 과금하므로, 트래픽이 없는 시간에는 비용이 줄어듭니다.
- RDS의 다른 엔진과 달리 **12개월 프리 티어 대상이 아닙니다.** 실습하실 때 비용을 염두에 두시기 바랍니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-rds]] | Aurora는 RDS가 제공하는 엔진 중 하나입니다. "MySQL/PostgreSQL **호환**이면서 **더 높은 성능**"을 요구하면 Aurora, 기존 엔진을 그대로 쓰겠다면 RDS입니다 |
| [[amazon-dynamodb]] | Aurora는 SQL·스키마·트랜잭션이 있는 관계형, DynamoDB는 키-값 NoSQL입니다 |
| [[amazon-redshift]] | Aurora는 트랜잭션 처리(OLTP), Redshift는 데이터 웨어하우스 분석(OLAP)입니다 |

## 시험 포인트

- [ ] "**MySQL 또는 PostgreSQL과 호환되면서 성능은 더 높은** 관리형 관계형 데이터베이스" → Aurora
- [ ] "**엔터프라이즈급 성능과 가용성을 더 낮은 비용으로**"라는 표현이 관계형 문맥에서 나오면 Aurora
- [ ] "**사용량을 예측하기 어렵고 용량이 자동으로 오르내리길 원한다**" → Aurora Serverless
- [ ] 함정: Aurora는 NoSQL이 아닙니다. 스키마 없는 키-값이면 DynamoDB, 문서면 [[amazon-documentdb]]입니다
- [ ] 함정: Aurora는 데이터 웨어하우스가 아닙니다. 페타바이트급 분석 쿼리는 Redshift입니다

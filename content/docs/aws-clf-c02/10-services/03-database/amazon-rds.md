## 한 줄로 말하면

관계형 데이터베이스를 AWS가 대신 설치·패치·백업해 주는 **관리형** 서비스입니다.

## 핵심 개념

- **관리형이라는 뜻** — 하드웨어 프로비저닝, 데이터베이스 엔진 설치와 패치, 백업, 장애 복구를 AWS가 맡습니다. 고객은 스키마 설계, 쿼리, 데이터에만 집중하시면 됩니다.
- **고를 수 있는 엔진** — MySQL, PostgreSQL, MariaDB, Oracle, Microsoft SQL Server, 그리고 AWS가 직접 만든 [[amazon-aurora]] 중에서 고릅니다. 기존에 쓰던 엔진을 그대로 옮겨 올 수 있습니다.
- **다중 AZ 배포** — 다른 가용 영역에 대기 복제본을 두고 **동기식**으로 복제합니다. 기본 인스턴스에 장애가 나면 AWS가 **자동으로 장애 조치**를 수행합니다. 목적은 **고가용성**입니다.
- **읽기 전용 복제본** — 읽기 트래픽을 나눠 받는 사본을 여러 개 둘 수 있습니다. **비동기** 복제라 약간의 지연이 있고, 목적은 **읽기 성능 향상**입니다.
- **자동 백업과 스냅샷** — 지정한 보존 기간 동안 자동으로 백업이 이루어지고, 원하는 시점으로 복구할 수 있습니다. 수동 스냅샷은 직접 지울 때까지 남습니다.
- **관계형 · OLTP** — 정해진 스키마와 SQL, 트랜잭션이 필요한 업무 시스템에 씁니다. 주문 접수, 재고 관리, 회원 정보 같은 것이 대표 사례입니다.

## 요금 모델

- **DB 인스턴스를 실행한 시간(시간당)** 이 기본입니다. 인스턴스 클래스가 클수록 시간당 요금이 올라갑니다.
- **스토리지 용량(GB-월)** 과 프로비저닝한 IOPS, **백업 스토리지**가 따로 붙습니다.
- **데이터 전송**, 특히 리전 밖이나 인터넷으로 나가는 트래픽에 요금이 붙습니다. AWS로 들어오는 트래픽은 무료입니다.
- 온디맨드 외에 **예약 인스턴스**(1년·3년 약정)로 할인받을 수 있습니다.
- 프리 티어로 소형 인스턴스와 일정 용량의 스토리지를 12개월 동안 무료로 쓸 수 있습니다.
- **다중 AZ를 켜면 대기 복제본 몫이 추가**되므로 요금이 대략 두 배가 된다는 점을 기억해 두시기 바랍니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-ec2]] | EC2에 데이터베이스를 직접 설치하면 **비관리형**이라 OS·엔진 패치와 백업까지 전부 고객 책임입니다. "운영 부담을 줄이고 싶다"면 RDS입니다 |
| [[amazon-aurora]] | 같은 관계형이지만 Aurora는 AWS가 새로 만든 엔진이라 MySQL·PostgreSQL **호환**이면서 처리량이 훨씬 높습니다 |
| [[amazon-dynamodb]] | RDS는 스키마·SQL·조인이 있는 관계형, DynamoDB는 스키마가 유연한 키-값 NoSQL입니다 |
| [[amazon-redshift]] | RDS는 건건이 처리하는 트랜잭션(OLTP), Redshift는 대량 집계와 리포팅(OLAP)입니다 |

## 시험 포인트

- [ ] 문제에 **"데이터베이스 관리 부담을 줄이고 싶다" / "패치와 백업을 AWS가 대신 해 주면 좋겠다"** 가 나오면 RDS입니다. EC2에 직접 설치하는 선택지는 비관리형이므로 오답입니다
- [ ] **다중 AZ = 고가용성**입니다. **동기** 복제이고 자동 장애 조치가 되지만, 대기 복제본으로 읽기 트래픽을 보내는 것이 목적은 아닙니다
- [ ] **읽기 전용 복제본 = 읽기 성능**입니다. **비동기** 복제라 지연이 있고 고가용성이 목적이 아닙니다. 이 둘을 서로 바꿔 놓은 선택지가 가장 흔한 함정입니다
- [ ] "**MySQL·PostgreSQL·Oracle·SQL Server를 그대로 쓰고 싶다**"면 RDS, "**유연한 스키마·키-값**"이 보이면 DynamoDB로 넘어가시면 됩니다
- [ ] 공동 책임 모델에서 RDS는 관리형이므로 **OS 패치와 DB 엔진 패치는 AWS 책임**입니다. 고객은 데이터, 접근 권한, 스키마 설계를 책임집니다

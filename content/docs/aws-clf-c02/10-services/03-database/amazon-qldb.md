## 한 줄로 말하면

한 번 기록하면 고치거나 지울 수 없고, 변경 이력이 통째로 남는 **원장(ledger) 데이터베이스**입니다.

## 핵심 개념

- **원장이라는 말** — 회계 장부처럼 **추가만 가능한(append-only)** 기록입니다. 기존 기록을 수정하거나 삭제하는 동작 자체가 없습니다.
- **변경 불가 · 검증 가능** — 모든 변경이 암호화 해시로 연결되어 저장되므로, 데이터가 조작되지 않았다는 것을 수학적으로 증명할 수 있습니다.
- **완전한 이력** — 어떤 값이 언제 어떻게 바뀌었는지 전체 히스토리를 그대로 조회할 수 있습니다. 감사가 필요한 시스템에서 이 점이 핵심입니다.
- **중앙 신뢰 기관이 있습니다** — 원장의 소유자가 한 곳이라는 점이, 여러 참여자가 합의로 운영하는 블록체인과 갈리는 지점입니다. 여러 당사자가 공동으로 원장을 운영해야 하면 Amazon Managed Blockchain 쪽입니다.
- **대표 용도** — 금융 거래 기록, 공급망 추적, 의료 기록, 규제 대응용 시스템 로그입니다.

## 요금 모델

- 서버를 띄우지 않는 서버리스 방식이라 **인스턴스 시간 요금이 없습니다.**
- **쓰기 I/O와 읽기 I/O 요청 수**, **저널과 인덱스 저장 용량(GB-월)**, **데이터 전송**을 기준으로 과금합니다.
- 프리 티어는 없습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-rds]] | 관계형 데이터베이스는 값을 고치고 지울 수 있습니다. "**고칠 수 없어야 한다**"가 조건이면 QLDB입니다 |
| [[amazon-dynamodb]] | 둘 다 서버리스지만 DynamoDB는 값을 덮어쓸 수 있고 이전 값의 이력을 남기지 않습니다 |
| [[aws-cloudtrail]] | CloudTrail은 **AWS API 호출**을 기록하는 감사 로그이고, QLDB는 **애플리케이션 데이터**의 변경 이력을 저장합니다 |

## 시험 포인트

- [ ] "**변경 불가(immutable)**", "**원장(ledger)**", "**변경 이력을 완전하고 검증 가능하게 보관**" → QLDB
- [ ] "**중앙에서 신뢰하는 기관 하나**가 원장을 소유" → QLDB / "**여러 당사자가 공동 소유하고 합의**" → Amazon Managed Blockchain
- [ ] 함정: 감사가 목적이라고 무조건 QLDB가 아닙니다. AWS 계정에서 **누가 무엇을 했는지** 추적하는 것은 CloudTrail입니다

## 한 줄로 말하면

데이터 **사이의 관계**를 저장하고 빠르게 탐색하는 데 특화된 관리형 그래프 데이터베이스입니다.

## 핵심 개념

- **그래프 모델** — 데이터를 **정점(노드)** 과 **간선(관계)** 으로 저장합니다. "누가 누구와 어떻게 연결되어 있는가"가 데이터의 본체입니다.
- **관계 탐색에 강합니다** — 몇 단계 건너 이어진 연결을 찾는 질의를, 관계형 데이터베이스에서 조인을 겹겹이 쌓는 것보다 훨씬 빠르게 처리합니다.
- **대표 용도** — 소셜 네트워크, 추천 엔진, **사기 탐지**, 지식 그래프, 네트워크 보안 분석입니다. 이 단어들이 문제에 등장하면 Neptune을 떠올리시면 됩니다.
- **관리형** — 프로비저닝, 패치, 백업, 복구를 AWS가 맡고, 여러 가용 영역에 복제해 가용성을 확보합니다.
- **질의 언어가 다릅니다** — SQL이 아니라 Gremlin, openCypher, SPARQL 같은 그래프 질의 언어를 씁니다.

## 요금 모델

- **인스턴스를 실행한 시간(시간당)** 이 기본입니다.
- **스토리지 용량(GB-월)**, **I/O 요청 수**, **백업 스토리지**가 별도로 붙습니다.
- 리전 밖으로 나가는 **데이터 전송**은 따로 과금합니다.
- 프리 티어 대상이 아닙니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-rds]] | 관계형에서도 조인으로 관계를 표현할 수 있지만 단계가 깊어질수록 느려집니다. **관계를 여러 단계 타고 들어가야** 하면 Neptune입니다 |
| [[amazon-documentdb]] | DocumentDB는 문서 하나의 내용을 다루고, Neptune은 문서들 **사이의 연결**을 다룹니다 |
| [[amazon-dynamodb]] | DynamoDB는 키로 항목 하나를 빠르게 찾는 데 최적이고, 연결 관계를 따라가는 탐색은 Neptune입니다 |

## 시험 포인트

- [ ] "**그래프 데이터베이스**", "**고도로 연결된 데이터**", "**소셜 네트워크**", "**추천 엔진**", "**지식 그래프**" → Neptune
- [ ] "관계를 **여러 단계 타고 들어가는** 질의를 빠르게" → Neptune
- [ ] 함정: **사기 탐지**는 Amazon GuardDuty와 헷갈릴 수 있습니다. GuardDuty는 AWS 계정의 위협을 탐지하고, **데이터의 관계 패턴**으로 사기를 찾는 것이 Neptune입니다
- [ ] 함정: Neptune은 SQL 데이터베이스가 아닙니다. SQL 쿼리가 조건에 있으면 RDS나 Redshift 쪽입니다

## 한 줄로 말하면

**MongoDB와 호환**되는 관리형 문서 데이터베이스입니다.

## 핵심 개념

- **문서 데이터베이스** — 데이터를 행과 열이 아니라 **JSON 형태의 문서**로 저장합니다. 문서마다 필드 구성이 달라도 됩니다.
- **MongoDB 호환** — 기존 MongoDB 드라이버와 코드를 대부분 그대로 쓸 수 있습니다. 그래서 온프레미스에서 돌리던 MongoDB를 옮길 때 자연스러운 목적지가 됩니다.
- **관리형** — 프로비저닝, 패치, 백업, 복구, 여러 가용 영역 복제를 AWS가 맡습니다.
- **대표 용도** — 콘텐츠 관리 시스템, 사용자 프로필, 상품 카탈로그처럼 **항목마다 구조가 제각각인** 데이터를 다룰 때 씁니다.
- **키-값과는 다릅니다** — 문서 안의 필드로 조회하고 인덱스를 걸 수 있다는 점이 단순 키-값 저장소와 갈리는 지점입니다.

## 요금 모델

- **인스턴스를 실행한 시간(시간당)** 이 기본입니다. 클러스터를 띄워 두면 계속 요금이 나갑니다.
- **스토리지 용량(GB-월)**, **I/O 요청 수**, **백업 스토리지**가 각각 별도로 붙습니다.
- 리전 밖으로 나가는 **데이터 전송**은 따로 과금합니다.
- 프리 티어 대상이 아니므로 실습하실 때는 다 쓰고 나서 클러스터를 지우시기 바랍니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-dynamodb]] | 둘 다 NoSQL입니다. **MongoDB**가 언급되면 DocumentDB, **키-값·서버리스**면 DynamoDB입니다 |
| [[amazon-rds]] | RDS는 관계형(SQL·스키마 고정), DocumentDB는 문서(JSON·유연한 구조)입니다 |
| [[amazon-neptune]] | DocumentDB는 문서 하나하나의 내용을 저장하고, Neptune은 데이터 **사이의 관계**를 저장합니다 |

## 시험 포인트

- [ ] 문제에 **MongoDB**라는 단어가 나오면 거의 항상 DocumentDB입니다
- [ ] "**JSON 문서를 저장하고 쿼리한다**", "**문서 데이터베이스**" → DocumentDB
- [ ] 함정: 그냥 "NoSQL"만 나오면 DynamoDB일 가능성이 큽니다. DocumentDB는 **문서 또는 MongoDB**라는 단서가 있을 때 고르시기 바랍니다
- [ ] 함정: DocumentDB는 서버리스가 아니라 클러스터 인스턴스를 띄우는 방식입니다

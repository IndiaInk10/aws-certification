## 한 줄로 말하면

운영 중인 데이터베이스를 **다운타임을 최소화하면서** AWS로 옮겨 주는 마이그레이션 서비스입니다.

## 핵심 개념

- **최소 다운타임** — 원본 데이터베이스가 계속 서비스하는 동안 데이터를 복사하고, 그사이 발생한 변경분까지 따라붙습니다. 준비가 끝나면 전환만 하면 됩니다.
- **동종 마이그레이션** — MySQL → MySQL처럼 엔진이 같은 경우입니다. 스키마를 바꿀 필요가 없으니 DMS만으로 그대로 옮깁니다.
- **이기종 마이그레이션** — Oracle → Aurora PostgreSQL처럼 엔진이 다른 경우입니다. 먼저 **AWS Schema Conversion Tool(SCT)** 로 스키마와 저장 프로시저를 변환한 뒤, DMS로 데이터를 옮깁니다.
- **원본과 대상의 위치** — 온프레미스 → AWS가 대표적이지만 AWS → AWS, AWS → 온프레미스도 됩니다. 다만 **한쪽은 반드시 AWS 안에** 있어야 합니다.
- **일회성만은 아닙니다** — 개발·테스트 환경에 데이터를 계속 복제하거나, 여러 데이터베이스를 통합하거나, 분석 대상으로 데이터를 흘려보내는 용도로도 씁니다.

## 요금 모델

- **복제 인스턴스를 실행한 시간(시간당)** 이 기본입니다. 고른 인스턴스 유형과 켜 둔 시간만큼 냅니다.
- 로그에 쓰는 **스토리지(GB-월)** 와 리전 밖으로 나가는 **데이터 전송**이 추가됩니다. AWS로 **들어오는** 데이터 전송은 무료입니다.
- **AWS Schema Conversion Tool은 무료**로 내려받아 쓰실 수 있습니다.
- 프리 티어에 소형 복제 인스턴스가 일정 시간 포함됩니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-datasync]] | DataSync는 **파일·객체 스토리지**(NFS·SMB·S3·EFS)를 옮기고, DMS는 **데이터베이스**를 옮깁니다 |
| [[aws-snow-family]] | Snow는 네트워크로 보내기 어려운 대용량 데이터를 **물리 장비**에 담아 옮깁니다. 회선이 느리고 용량이 페타바이트급이면 Snow입니다 |
| [[aws-migration-hub]] | Migration Hub는 여러 마이그레이션의 **진행 상황을 한곳에서 보는** 대시보드이고, 실제로 옮기는 일은 DMS가 합니다 |

## 시험 포인트

- [ ] "**데이터베이스를 AWS로 옮긴다**", "**다운타임을 최소화하면서 마이그레이션**" → DMS
- [ ] **이기종 마이그레이션은 SCT로 스키마를 변환한 뒤 DMS로 데이터를 옮깁니다.** 이 역할 분담과 순서가 단골 출제 지점입니다
- [ ] 함정: 파일 서버나 S3 데이터를 옮기는 문제에는 DMS가 아니라 DataSync입니다
- [ ] 함정: 원본과 대상 중 **한쪽은 반드시 AWS 서비스**여야 합니다. 온프레미스에서 온프레미스로는 옮기지 못합니다

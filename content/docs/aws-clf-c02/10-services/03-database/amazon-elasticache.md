## 한 줄로 말하면

자주 읽는 데이터를 메모리에 올려 두고 데이터베이스 앞단에서 대신 응답해 주는 **관리형 인메모리 캐시**입니다.

## 핵심 개념

- **캐시가 푸는 문제** — 같은 쿼리가 반복되면 데이터베이스가 매번 디스크를 읽습니다. 결과를 메모리에 담아 두면 응답이 훨씬 빨라지고 데이터베이스 부하도 함께 줄어듭니다.
- **두 가지 엔진** — **Redis**와 **Memcached** 중에서 고릅니다. Redis는 복제·영속성·정렬 집합 같은 자료 구조를 지원하고, Memcached는 단순한 키-값 캐시라 구조가 가볍습니다.
- **관리형** — 노드 프로비저닝, 패치, 장애 노드 교체, 모니터링을 AWS가 맡습니다. 직접 캐시 서버를 세우고 관리할 필요가 없습니다.
- **대표 용도** — 데이터베이스 쿼리 결과 캐싱, **세션 정보 공유**, 게임 리더보드, 실시간 순위 집계입니다.
- **원본이 아닙니다** — 캐시는 어디까지나 빠른 사본입니다. 원본 데이터는 [[amazon-rds]]나 [[amazon-dynamodb]] 같은 데이터베이스에 남아 있어야 합니다.

## 요금 모델

- **캐시 노드를 실행한 시간(시간당)** 이 기본이고, 노드 유형이 클수록 시간당 요금이 올라갑니다. 노드를 여러 개 두면 그 수만큼 곱해집니다.
- 백업 스토리지와 리전 간 데이터 전송은 별도로 붙습니다.
- 온디맨드 외에 **예약 노드**(1년·3년 약정)로 할인받을 수 있습니다.
- 서버리스 옵션은 노드 시간 대신 **저장한 데이터양과 처리한 요청량**을 기준으로 과금합니다.
- 프리 티어로 소형 노드를 12개월 동안 무료로 쓸 수 있습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-dynamodb]] | DynamoDB는 데이터를 영구 저장하는 데이터베이스, ElastiCache는 그 앞에 두는 **휘발성** 캐시입니다 |
| [[amazon-cloudfront]] | 둘 다 캐시지만 CloudFront는 **엣지에서 콘텐츠**를, ElastiCache는 **애플리케이션과 DB 사이에서 데이터**를 캐싱합니다 |
| [[amazon-rds]] | 읽기 부하를 줄이는 방법으로 읽기 전용 복제본과 자주 비교됩니다. **같은 쿼리가 반복**되면 캐시, **읽기 쿼리 자체가 많고 다양**하면 읽기 전용 복제본입니다 |

## 시험 포인트

- [ ] "**인메모리**", "**캐싱**", "**Redis**", "**Memcached**", "DB 부하를 줄이면서 **읽기 지연 시간을 낮춘다**" → ElastiCache
- [ ] "여러 웹 서버가 **세션 정보를 공유**해야 한다" → ElastiCache가 자주 정답입니다
- [ ] Redis와 Memcached **둘 다** 지원한다는 점 — 두 이름 중 하나만 보고도 ElastiCache를 고르실 수 있어야 합니다
- [ ] 함정: 데이터를 **영구 보관**해야 한다면 캐시는 답이 아닙니다
- [ ] 함정: 전 세계 사용자에게 **정적 콘텐츠**를 빠르게 전달하는 것은 CloudFront입니다

## 한 줄로 말하면

AWS가 설계한 **실제 하드웨어 랙을 고객의 데이터 센터 안에 설치해서**, 온프레미스에서도 AWS 서비스를 그대로 쓰게 해 주는 하이브리드 서비스입니다.

## 핵심 개념

- **물리 하드웨어가 고객 시설로 들어옵니다** — AWS가 랙 또는 서버 형태의 장비를 배송·설치하고, **이후 유지 관리와 패치까지 AWS가 담당합니다.**
- **같은 API, 같은 도구를 씁니다** — 리전에서 쓰던 EC2·EBS·ECS·EKS·RDS 등을 Outposts 위에서 **똑같은 콘솔과 API로** 운영하실 수 있습니다. 별도의 운영 방식을 배우실 필요가 없습니다.
- **왜 필요한가** — 공장 설비 제어처럼 **지연 시간이 아주 짧아야 할 때**, 데이터가 **국경이나 건물 밖으로 나갈 수 없을 때**(데이터 레지던시·규정 준수), 로컬 시스템과 붙어 있어야 할 때 씁니다.
- **리전에 연결된 확장입니다** — Outposts는 특정 AWS 리전에 **논리적으로 연결된 확장**으로 동작합니다. 완전히 독립된 별도 클라우드가 아닙니다.
- **진정한 하이브리드 모델** — 온프레미스와 클라우드가 **같은 운영 체계**를 공유하는 구성이고, 시험에서는 이 문장 하나로 정답이 결정되는 경우가 많습니다.

## 요금 모델

- 필요한 **하드웨어 구성(용량)을 정해 1년 또는 3년 단위로 계약**하고, 그 용량에 대해 요금을 냅니다. 선결제·부분 선결제·선결제 없음 중에서 고르실 수 있습니다.
- 요금에는 **하드웨어, 설치, 유지 관리, 소프트웨어 패치가 포함**됩니다.
- 실제 사용량이 아니라 **약정한 용량**이 기준이므로, EC2처럼 껐다고 요금이 멈추지는 않습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-storage-gateway]] | Outposts는 **컴퓨팅과 스토리지를 포함한 AWS 인프라 자체**를 현장에 두고, Storage Gateway는 온프레미스 앱이 **AWS 클라우드의 스토리지에 접근하게** 이어 줍니다. |
| [[aws-snow-family]] | Snow는 **데이터를 옮기기 위해 잠시 빌리는 장비**이고, Outposts는 **계속 두고 쓰는 상주 인프라**입니다. |
| [[aws-direct-connect]] | Direct Connect는 온프레미스와 AWS를 잇는 **전용 네트워크 회선**일 뿐이고, Outposts는 **AWS 하드웨어를 현장에 두는 것**입니다. |

## 시험 포인트

- [ ] 문제에 **"온프레미스 데이터 센터에서 AWS 서비스를 실행"**, **"AWS와 동일한 하드웨어·API를 현장에서"** 가 나오면 Outposts입니다
- [ ] **"지연 시간이 매우 낮아야 한다 + 데이터가 현장을 벗어날 수 없다"** 조합이 대표적인 신호입니다
- [ ] Outposts는 **AWS가 관리하는 하드웨어**입니다. "고객이 하드웨어를 구매해 직접 유지 관리한다"는 선택지는 오답입니다
- [ ] 데이터 **마이그레이션 수단이 아닙니다.** 대용량 데이터를 클라우드로 옮기는 문제라면 Snow Family나 DataSync 쪽입니다
- [ ] 하이브리드 클라우드의 대표 서비스로 외워 두시기 바랍니다

## 한 줄로 말하면

**서버를 하나도 만들지 않고 코드(함수)만 올려서 실행하는** 서버리스 컴퓨팅 서비스입니다.

## 핵심 개념

- **서버리스** — 프로비저닝할 인스턴스도, 패치할 OS도 없습니다. AWS가 실행 환경을 통째로 관리하므로 **고객은 코드와 설정만** 신경 쓰시면 됩니다.
- **이벤트 기반으로 실행됩니다** — S3에 파일이 올라왔을 때, API Gateway로 요청이 들어왔을 때, EventBridge 일정이 되었을 때처럼 **무슨 일이 일어나면 그때** 함수가 깨어납니다.
- **자동 스케일링** — 요청이 한 건이면 한 번, 수천 건이면 수천 개가 동시에 실행됩니다. Auto Scaling 그룹 같은 것을 따로 설정하실 필요가 없습니다.
- **실행 시간 제한 15분** — 한 번 호출의 최대 실행 시간이 **15분**입니다. 몇 시간씩 도는 작업에는 맞지 않습니다. 이 제한이 시험에서 결정적인 신호가 됩니다.
- **짧고 단발성인 작업에 맞습니다** — 이미지 썸네일 생성, 로그 처리, 데이터 검증, 서비스 사이를 잇는 접착제 코드 같은 용도입니다.
- **아무 일도 없으면 요금이 0입니다** — 대기 상태에는 과금이 없으므로, 드문드문 실행되는 워크로드에서 EC2보다 훨씬 저렴해집니다.

## 요금 모델

- **요청 수**와 **실행 시간**(할당한 메모리 × 실행한 밀리초, 즉 GB-초) 두 가지를 기준으로 과금합니다.
- **함수가 실행되지 않는 동안에는 요금이 붙지 않습니다.** 서버를 켜 두는 비용이라는 개념 자체가 없습니다.
- 프리 티어에 매월 일정 요청 수와 일정 GB-초의 컴퓨팅 시간이 **기간 만료 없이** 포함되어 있습니다.
- 절감형 플랜(Compute Savings Plans)을 Lambda 사용량에도 적용하실 수 있습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-ec2]] | EC2는 **서버를 띄우고 OS까지 관리**하며 켜 둔 시간만큼 과금하고, Lambda는 **서버가 없고** 실행된 시간만큼만 과금합니다. |
| [[aws-fargate]] | 둘 다 서버 관리가 없지만, Fargate는 **컨테이너 이미지**를 오래 실행할 수 있고 Lambda는 **함수 코드**를 15분 안에 끝내야 합니다. |
| [[aws-batch]] | Batch는 **몇 시간씩 걸리는 대량 배치 작업**을 큐에 넣어 돌리고, Lambda는 **짧고 이벤트에 반응하는** 작업을 돌립니다. |
| [[aws-elastic-beanstalk]] | Beanstalk는 **웹 애플리케이션 전체**를 EC2 위에 배포해 주고, Lambda는 **함수 단위**로 실행합니다. |

## 시험 포인트

- [ ] 문제에 **"서버를 프로비저닝하거나 관리하지 않고"**, **"이벤트에 반응해서"**, **"코드만 업로드"** 가 나오면 Lambda입니다
- [ ] **15분 제한**이 함정으로 자주 나옵니다. "몇 시간 동안 실행되는 작업"이면 Lambda가 아니라 Batch·EC2·Fargate 쪽입니다
- [ ] **"사용하지 않을 때는 비용이 발생하지 않는다"** 는 표현은 Lambda를 가리킵니다
- [ ] Lambda는 **스케일링을 직접 설정하지 않습니다.** "Auto Scaling 그룹을 구성해야 한다"는 선택지는 오답입니다
- [ ] 서버리스 4종 세트로 **Lambda · Fargate · [[amazon-sqs]] · [[amazon-dynamodb]]** 를 묶어 두시면 "서버리스인 것을 고르시오" 문제에 대응됩니다

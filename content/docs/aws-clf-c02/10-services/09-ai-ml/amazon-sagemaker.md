# Amazon SageMaker

> ML 모델을 만들고 훈련하고 배포하는 통합 환경

## 한 줄로 말하면

**기계 학습 모델을 직접 구축·학습·배포**하는 플랫폼입니다. 완성된 기능을 부르는 API가 아니라, 모델을 내가 만드는 자리입니다.

## 핵심 개념

- **완성형 API가 아니라 ML 플랫폼입니다** — Rekognition이나 Comprehend는 "이미 만들어진 기능을 부르는" 서비스이지만, SageMaker는 **내 데이터로 내 모델을 만드는** 서비스입니다. 이 구분이 시험에서 갈리는 지점입니다.
- **구축 → 학습 → 배포 전 과정을 한곳에서 합니다** — 데이터를 준비하고, 모델을 훈련시키고, 성능을 조정하고, 엔드포인트로 배포해 실제 예측을 받는 단계까지 이어집니다.
- **인프라를 대신 관리해 줍니다** — 학습용 GPU 인스턴스를 직접 띄우고 프레임워크를 설치하는 수고를 덜어 줍니다.
- **기존 AI 서비스로 안 되는 문제에 씁니다** — 우리 회사 고유의 수요 예측, 이탈 고객 예측, 특수한 이미지 분류처럼 **일반 API로는 풀리지 않는** 문제가 대상입니다.
- **ML 전문 지식이 필요합니다** — 데이터 과학자·ML 엔지니어가 쓰는 도구입니다. CLF-C02 수준에서는 **"직접 모델을 만들 때 쓴다"** 정도만 아시면 충분합니다.

## 요금 모델

- **사용한 인스턴스의 시간**을 기준으로 과금합니다. 모델을 학습시킨 시간, 노트북을 켜 둔 시간, 배포한 엔드포인트가 떠 있는 시간이 각각 계산됩니다.
- 여기에 데이터 저장 용량과 데이터 전송 요금이 더해집니다.
- **배포한 엔드포인트는 예측 요청이 없어도 떠 있는 동안 요금이 발생합니다.** 쓰지 않는 엔드포인트는 내리셔야 합니다.
- 절감형 플랜을 SageMaker 사용량에도 적용할 수 있습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-rekognition]] | Rekognition은 **이미 학습된 이미지 분석 기능을 그냥 호출**합니다. SageMaker는 **모델을 내가 만듭니다.** "ML 전문 지식 없이 바로 쓰고 싶다"면 Rekognition 쪽입니다 |
| [[amazon-comprehend]] | 마찬가지로 Comprehend는 완성형 API입니다. **사용자 정의 모델이 필요하다**는 조건이 붙으면 SageMaker입니다 |
| [[amazon-emr]] | EMR은 **대규모 데이터 처리** 클러스터이고, SageMaker는 그 데이터로 **모델을 학습·배포**합니다 |

## 시험 포인트

- [ ] 문제에 **"기계 학습 모델을 구축·학습·배포", "데이터 과학자", "사용자 지정 ML 모델"** 이 나오면 SageMaker입니다
- [ ] 반대로 **"ML 경험이 없는 팀", "바로 사용 가능한", "미리 학습된"** 이 조건이면 SageMaker가 아니라 Rekognition·Comprehend 같은 완성형 서비스입니다
- [ ] 과금 기준은 **사용한 인스턴스 시간**입니다. 요청 수가 아닙니다
- [ ] 배포한 엔드포인트를 방치하면 계속 과금된다는 점이 비용 문제로 나올 수 있습니다

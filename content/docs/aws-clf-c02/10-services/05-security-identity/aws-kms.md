## 한 줄로 말하면

데이터를 암호화할 **키를 만들고 관리하고, 누가 그 키를 쓸 수 있는지 통제**하는 서비스입니다.

## 핵심 개념

- **KMS 키** — 암호화의 뿌리가 되는 키입니다. 키는 **KMS 밖으로 나오지 않고**, 암호화·복호화 요청을 KMS에 보내는 방식으로 사용합니다.
- **AWS 관리형 키와 고객 관리형 키** — AWS가 알아서 만들어 주는 키를 그대로 쓰셔도 되고, 직접 만들어 정책·교체 주기·삭제까지 제어하는 **고객 관리형 키**를 쓰셔도 됩니다. 제어권이 필요하면 후자를 고릅니다.
- **거의 모든 서비스와 통합됩니다** — S3, EBS, RDS, DynamoDB, Lambda 등에서 "암호화 사용"에 체크하면 KMS 키가 연결됩니다. **저장 데이터 암호화(encryption at rest)** 의 기본 도구입니다.
- **접근 제어는 IAM 정책과 키 정책으로** — 데이터를 손에 넣더라도 키 사용 권한이 없으면 읽지 못합니다. 그래서 데이터를 지우는 대신 **키 사용 권한을 회수**하는 방식이 쓰입니다.
- **자동 키 교체** — 고객 관리형 키는 연 단위 자동 교체를 켤 수 있습니다.
- **모든 사용 기록이 남습니다** — 키를 언제 누가 썼는지가 [[aws-cloudtrail]]에 기록되어 감사에 활용됩니다.

## 요금 모델

- **보관 중인 키 개수(월 단위)** 와 **API 요청 수** 두 가지로 과금됩니다.
- AWS 관리형 키에는 보관 요금이 붙지 않고, 고객 관리형 키는 개수만큼 월 요금이 발생합니다.
- API 요청에는 매월 **프리 티어**가 제공됩니다.
- 키를 삭제 예약하더라도 대기 기간 동안에는 요금이 계속 나갑니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-cloudhsm]] | KMS는 AWS가 관리하는 **공유 HSM** 기반이고, CloudHSM은 **전용 하드웨어**를 고객이 단독으로 제어합니다 |
| [[aws-secrets-manager]] | KMS는 **암호화 키**를, Secrets Manager는 **비밀번호·DB 자격 증명**을 다룹니다. Secrets Manager도 내부적으로는 KMS 키로 암호화합니다 |
| [[aws-certificate-manager]] | 통신 구간을 보호하는 **SSL/TLS 인증서**는 ACM의 일입니다 |

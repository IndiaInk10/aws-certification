## 한 줄로 말하면

나만 쓰는 **전용 하드웨어 보안 모듈(HSM)** 을 클라우드에 두고, 암호화 키를 단독으로 제어하는 서비스입니다.

## 핵심 개념

- **전용 하드웨어입니다** — 다른 고객과 공유하지 않는 **단독 HSM 장비**를 프로비저닝합니다. 물리적 격리가 규정으로 요구될 때 선택합니다.
- **AWS도 키를 볼 수 없습니다** — 키의 생성·관리·삭제를 고객이 전적으로 제어합니다. AWS는 하드웨어와 가용성만 관리하고 키에는 접근하지 못합니다.
- **엄격한 규정 준수용** — FIPS 140 검증을 받은 하드웨어를 사용하므로, 감사와 규정 요건이 까다로운 워크로드에 쓰입니다.
- **책임도 내 몫으로 넘어옵니다** — 사용자 관리, 백업, 클러스터 구성이 고객 책임입니다. 자격 증명을 잃어버리면 **AWS도 복구해 줄 수 없습니다.**
- **업계 표준 인터페이스** — PKCS#11, JCE, CNG 같은 표준 API로 접근하므로 기존 온프레미스 애플리케이션을 그대로 옮기기 좋습니다.

## 요금 모델

- **HSM을 띄워 둔 시간(시간당)** 기준입니다. 실제로 쓰지 않아도 클러스터가 떠 있으면 요금이 발생합니다.
- 고가용성을 위해 HSM을 여러 개 두면 개수만큼 요금이 곱해집니다.
- 프리 티어가 없고 일반적으로 KMS보다 비쌉니다. 규정 요건이 없다면 KMS를 먼저 검토하시는 편이 좋습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-kms]] | KMS는 AWS가 관리하는 **공유형** 관리형 키 서비스이고, CloudHSM은 **전용 장비를 단독으로 제어**합니다. "전용", "단독 제어", "AWS도 접근 불가"가 갈리는 지점입니다 |
| [[aws-secrets-manager]] | Secrets Manager는 **비밀번호·API 키**를 보관하고 교체합니다. 암호화 키 자체를 다루는 서비스가 아닙니다 |
| [[aws-certificate-manager]] | SSL/TLS 인증서의 발급과 자동 갱신은 ACM의 일입니다 |

## 시험 포인트

- [ ] "**전용(dedicated) 하드웨어**", "키를 **AWS가 접근할 수 없어야** 한다", "**단독 제어**" → CloudHSM
- [ ] 대부분의 암호화 문제에서 기본 정답은 KMS입니다. **전용 하드웨어나 엄격한 규정이 명시될 때만** CloudHSM으로 갑니다
- [ ] 키를 잃어버리면 AWS도 복구할 수 없다는 점이 KMS와 갈리는 큰 차이입니다
- [ ] 시간당 과금이라 켜 두기만 해도 요금이 계속 나갑니다

## 한 줄로 말하면

이미 탐지된 보안 사건이 **왜, 어떻게 벌어졌는지**를 로그를 이어 붙여 시각적으로 파고드는 **조사 도구**입니다.

## 핵심 개념

- **하는 일은 조사이지 탐지가 아닙니다** — 위협을 처음 찾아내는 일은 GuardDuty·Inspector 같은 앞 단계 서비스가 합니다. Detective는 그 결과를 받아 **원인 분석**을 합니다. 순서를 기억하시기 바랍니다.
- **여러 로그를 자동으로 모읍니다** — VPC 플로 로그, [[aws-cloudtrail]] 이벤트, [[amazon-guardduty]] 조사 결과 등을 자동으로 끌어와 하나로 연결합니다. 분석가가 로그를 직접 모아 붙일 필요가 없습니다.
- **동작 그래프를 만듭니다** — 어떤 사용자가, 어떤 리소스에, 어느 IP에서 접근했는지를 관계로 엮은 그래프를 유지합니다. 이것이 조사 속도를 끌어올리는 핵심입니다.
- **시간 흐름에 따른 대화형 시각화** — "이 IP가 언제부터 평소와 다르게 움직였는가"를 그래프와 타임라인으로 클릭해 가며 확인하실 수 있습니다.
- **기준선과 비교합니다** — 평소 활동량을 기계 학습으로 익혀 두고, 이번 사건이 정상 범위에서 얼마나 벗어났는지 보여 줍니다.
- **차단하지 않습니다** — 조사 결과를 보여 줄 뿐 공격을 막거나 리소스를 고치지 않습니다.

## 요금 모델

- **분석을 위해 수집·처리한 로그 데이터 양(GB)** 기준으로 계정마다 과금합니다.
- 로그를 어디에 얼마나 남기고 있느냐에 따라 금액이 크게 달라지므로, 켜기 전에 예상 데이터 양을 확인하시는 편이 좋습니다.
- 신규 사용자에게는 **무료 평가 기간**이 있어 규모를 미리 가늠하실 수 있습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-guardduty]] | GuardDuty가 **탐지**(무슨 일이 벌어지고 있는가), Detective가 **조사**(왜 벌어졌는가)입니다. GuardDuty의 결과가 Detective의 입력이 됩니다 |
| [[amazon-inspector]] | Inspector는 **취약점 스캔**입니다. EC2·컨테이너 이미지·Lambda에 뚫릴 구멍이 있는지 미리 보는 쪽이라, 사건이 터진 뒤의 조사와는 단계가 다릅니다 |
| [[aws-security-hub]] | Security Hub는 여러 서비스의 결과를 한 화면에 **모아 보여 주는 대시보드**이고, Detective는 그중 한 건을 골라 **깊이 파고드는** 도구입니다 |
| [[aws-cloudtrail]] | CloudTrail은 API 호출을 **기록**하는 원본 로그이고, Detective는 그 로그를 관계로 엮어 **해석**해 줍니다 |

## 시험 포인트

- [ ] "**근본 원인**", "**원인 분석**", "**대화형 시각화**", "**시간 흐름에 따라 조사**" → Detective
- [ ] 탐지 3형제 구분이 이 모듈 최대의 함정입니다. **탐지 = GuardDuty / 취약점 스캔 = Inspector / 조사 = Detective**로 외워 두시기 바랍니다
- [ ] 함정: "EC2·Lambda·컨테이너의 취약성을 평가한다"는 Detective가 아니라 [[amazon-inspector]]입니다. 보기에 나란히 등장합니다
- [ ] 함정: "위협을 지속적으로 모니터링해 찾아낸다"는 [[amazon-guardduty]]입니다
- [ ] Detective는 **막아 주지 않습니다.** 차단·완화가 조건이면 다른 서비스입니다

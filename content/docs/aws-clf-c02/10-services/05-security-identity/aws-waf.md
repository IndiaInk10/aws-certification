## 한 줄로 말하면

웹 애플리케이션 앞에서 **HTTP(S) 요청 하나하나를 규칙으로 검사해 허용하거나 차단**하는 방화벽입니다.

## 핵심 개념

- **계층 7 방화벽입니다** — 보안 그룹이나 네트워크 ACL이 IP와 포트를 보는 것과 달리, WAF는 **요청의 내용**(URL, 헤더, 쿼리 문자열, 본문)까지 들여다봅니다.
- **막는 공격** — SQL 인젝션, 크로스 사이트 스크립팅(XSS) 같은 흔한 웹 취약점 공격입니다. 시험에서 이 두 단어가 곧 WAF의 신호입니다.
- **웹 ACL과 규칙** — 규칙을 모은 **웹 ACL**을 만들어 리소스에 붙입니다. IP 주소, 국가, 요청 속도, 문자열 패턴 등으로 조건을 만들고 허용·차단·CAPTCHA 중에서 동작을 고릅니다.
- **관리형 규칙 그룹** — AWS와 마켓플레이스 공급업체가 만들어 둔 규칙 세트를 가져다 쓰면, 규칙을 직접 짜지 않고도 흔한 공격을 막을 수 있습니다.
- **붙일 수 있는 곳** — [[amazon-cloudfront]], Application Load Balancer, [[amazon-api-gateway]], AWS AppSync처럼 요청이 처음 들어오는 지점입니다.
- **속도 제한(rate limiting)** — 특정 IP가 짧은 시간에 지나치게 많은 요청을 보내면 차단할 수 있습니다.

## 요금 모델

- **웹 ACL 수 + 규칙 수 + 처리한 요청 수** 세 가지를 기준으로 월 단위 과금됩니다.
- 유료 구독형 관리형 규칙 그룹을 쓰면 그 요금이 따로 추가됩니다.
- Shield Advanced 구독자는 보호 대상 리소스에 대한 WAF 요금이 구독에 포함됩니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-shield]] | WAF는 요청의 **내용**을 검사하고, Shield는 **DDoS 트래픽의 규모**를 상대합니다 |
| [[aws-firewall-manager]] | 규칙을 만들어 **직접 차단하는 것**이 WAF, 그 규칙을 **여러 계정에 배포·관리하는 것**이 Firewall Manager입니다 |
| [[amazon-vpc]] | 보안 그룹과 네트워크 ACL은 **IP·포트** 수준이고, WAF는 그 위 **애플리케이션 계층**입니다 |

## 시험 포인트

- [ ] "**SQL 인젝션**", "**크로스 사이트 스크립팅(XSS)**", "악의적인 웹 요청 차단" → WAF
- [ ] "특정 **국가**나 IP에서 오는 요청을 차단", "요청 **속도 제한**"도 WAF입니다
- [ ] DDoS라는 단어가 나오면 먼저 Shield를 봅니다. 다만 계층 7 DDoS를 막을 때는 둘을 함께 씁니다
- [ ] WAF는 CloudFront·ALB·API Gateway에 붙입니다. EC2 인스턴스에 직접 설치하는 것이 아닙니다

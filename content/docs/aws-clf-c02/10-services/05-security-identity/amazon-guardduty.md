# Amazon GuardDuty

> 위협 탐지. 로그를 분석해 이상 행위 탐지

## 한 줄로 말하면

계정과 네트워크의 로그를 계속 분석해 **위협을 찾아내 알려 주는** 서비스입니다.

## 핵심 개념

- **하는 일은 위협 탐지입니다** — 공격을 막아 주는 서비스가 아니라, **이상 징후를 발견해 알려 주는** 서비스입니다. 차단은 다른 서비스가 맡습니다.
- **분석 대상은 로그** — CloudTrail 이벤트, VPC 흐름 로그, DNS 로그처럼 AWS가 이미 만들고 있는 로그를 읽습니다. 인스턴스에 에이전트를 설치할 필요가 없고, 워크로드 성능에도 영향을 주지 않습니다.
- **탐지 방식** — 위협 인텔리전스 정보와 기계 학습으로 평소와 다른 행동을 찾습니다. 알려진 악성 IP와의 통신, 암호화폐 채굴 패턴, 낯선 곳에서 들어온 비정상적인 API 호출 같은 것들입니다.
- **결과는 조사 결과(Findings)** — 심각도가 매겨진 항목으로 나오고, EventBridge나 [[aws-security-hub]]로 보내 자동 대응을 붙이실 수 있습니다.
- **켜기만 하면 됩니다** — 콘솔에서 활성화하는 순간 바로 분석이 시작됩니다. 별도의 로그 수집 설정을 미리 해 둘 필요가 없습니다.

## 요금 모델

- 분석한 **로그의 양** 기준입니다. 처리한 CloudTrail 이벤트 수, VPC 흐름 로그와 DNS 로그의 데이터 양에 따라 과금됩니다.
- 계정마다 **30일 무료 평가 기간**이 있어, 켜 보고 실제 비용 규모를 가늠하실 수 있습니다.
- GuardDuty가 로그를 직접 받아 읽으므로, 이를 위해 CloudTrail이나 흐름 로그를 따로 켜서 저장할 필요가 없고 그 저장 비용도 붙지 않습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-inspector]] | GuardDuty는 로그를 보고 **지금 벌어지는 위협**을 찾고, Inspector는 EC2·컨테이너·Lambda를 스캔해 **소프트웨어 취약점**을 찾습니다 |
| [[amazon-macie]] | Macie는 **S3에 들어 있는 데이터가 민감한지**를 봅니다. 데이터의 내용을 들여다보는 쪽이 Macie입니다 |
| [[aws-security-hub]] | GuardDuty는 탐지기 하나이고, Security Hub는 GuardDuty를 포함한 여러 탐지 결과를 **모아 보여 주는** 대시보드입니다 |
| [[aws-cloudtrail]] | CloudTrail은 API 호출을 **기록**만 하고, 그 기록을 읽어 위협인지 **판단**하는 쪽이 GuardDuty입니다 |

- [ ] 에이전트를 설치해야 한다는 설명은 틀립니다. 로그 기반이라 워크로드에 손대지 않습니다

## 한 줄로 말하면

**Amazon S3에 저장된 데이터** 중에서 개인 정보 같은 민감 데이터가 어디에 있는지 찾아 주는 서비스입니다.

## 핵심 개념

- **대상은 Amazon S3입니다** — Macie는 S3 버킷 안의 데이터를 봅니다. 데이터베이스나 EBS 볼륨을 훑는 서비스가 아닙니다.
- **민감 데이터 발견과 분류** — 이름·주소·주민등록번호 같은 개인 식별 정보(PII), 금융 정보, 자격 증명 등을 기계 학습과 패턴 매칭으로 찾아냅니다.
- **버킷 상태도 함께 점검합니다** — 어떤 버킷이 **퍼블릭으로 열려 있는지**, 암호화가 꺼져 있는지, 다른 계정과 공유되어 있는지를 알려 줍니다.
- **왜 쓰나** — GDPR·HIPAA 같은 규정을 지키려면 "우리가 민감 데이터를 어디에 두고 있는지"를 먼저 알아야 합니다. 그 목록을 자동으로 만들어 주는 서비스라고 생각하시면 됩니다.
- **결과 전달** — 조사 결과는 [[aws-security-hub]]와 EventBridge로 보내 알림이나 자동 조치에 연결할 수 있습니다.

## 요금 모델

- **버킷 목록을 평가하는 비용**과 **실제로 검사한 데이터 양(GB)** 두 가지로 과금됩니다.
- 신규 계정에는 **무료 평가 기간**이 제공됩니다.
- 검사 범위를 특정 버킷이나 접두사로 좁히면 비용을 줄일 수 있습니다. 전체 데이터를 무조건 훑을 필요는 없습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-guardduty]] | Macie는 **데이터의 내용**을 보고, GuardDuty는 **계정·네트워크 로그**를 봅니다 |
| [[amazon-inspector]] | Inspector는 EC2·컨테이너·Lambda의 **취약점**을 스캔합니다. 데이터의 내용은 들여다보지 않습니다 |
| [[aws-kms]] | 민감 데이터를 **찾아내는** 쪽이 Macie, 찾은 데이터를 **암호화할 키**를 제공하는 쪽이 KMS입니다 |

## 시험 포인트

- [ ] "**S3**" + "**개인 식별 정보(PII)**", "민감 데이터", "규정 준수를 위해 어디에 있는지 파악" → Macie
- [ ] 탐지 3종은 대상으로 가릅니다 — 로그면 GuardDuty, 워크로드 취약점이면 Inspector, **S3 데이터면 Macie**입니다
- [ ] Macie는 **S3 전용**입니다. RDS나 EBS를 스캔한다는 설명은 틀립니다
- [ ] 발견하고 알려 줄 뿐, 데이터를 삭제하거나 접근을 차단하지는 않습니다

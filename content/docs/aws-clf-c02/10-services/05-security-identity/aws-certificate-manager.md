# AWS Certificate Manager

> SSL/TLS 인증서 발급·자동 갱신 (무료)

## 한 줄로 말하면

SSL/TLS 인증서를 발급하고 **만료되기 전에 자동으로 갱신**해 주는 서비스입니다.

## 핵심 개념

- **하는 일** — 웹사이트와 애플리케이션에 HTTPS를 붙이는 데 필요한 인증서를 발급·저장·배포·갱신합니다. 통신 구간을 암호화하는 쪽입니다.
- **자동 갱신이 가장 큰 가치입니다** — 인증서 만료를 깜빡해 사이트가 멈추는 사고를 없애 줍니다. ACM이 발급한 퍼블릭 인증서는 조건을 만족하면 알아서 갱신됩니다.
- **AWS 서비스에 붙여 씁니다** — [[elastic-load-balancing]], [[amazon-cloudfront]], [[amazon-api-gateway]] 같은 통합 서비스에 몇 번의 클릭으로 연결하는 것이 기본 사용법입니다.
- **퍼블릭 인증서는 프라이빗 키를 내보낼 수 없습니다** — 그래서 EC2 인스턴스에 직접 설치해서 쓰는 용도로는 쓰지 못하고, **통합 서비스에 붙이는 방식으로만** 사용합니다. 시험에서 자주 묻는 제약입니다.
- **도메인 소유권 검증** — 발급 전에 DNS 레코드를 추가하거나 이메일을 확인하는 방식으로 도메인이 내 것임을 증명해야 합니다.
- **프라이빗 CA** — 사내 전용 인증서가 필요하면 AWS Private CA로 내부 인증 기관을 운영할 수 있습니다. 이쪽은 별도 유료입니다.

## 요금 모델

- **ACM이 발급하는 퍼블릭 SSL/TLS 인증서는 무료입니다.** 발급도 갱신도 요금이 붙지 않습니다.
- 요금은 인증서를 붙인 **ELB나 CloudFront 같은 리소스의 사용량**에만 발생합니다.
- 사설 인증 기관(AWS Private CA)을 운영하면 **CA 운영 요금과 발급한 인증서 수**에 따라 별도로 과금됩니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-kms]] | ACM은 통신을 보호하는 **인증서**를, KMS는 저장 데이터를 암호화하는 **키**를 다룹니다 |
| [[aws-secrets-manager]] | 비밀번호와 API 키를 보관하고 교체하는 쪽이 Secrets Manager입니다. 인증서 갱신은 ACM의 일입니다 |
| [[aws-waf]] | ACM은 통신을 **암호화**하고, WAF는 들어온 요청의 **내용을 검사해 차단**합니다. HTTPS를 쓴다고 공격이 막히지는 않습니다 |

## 시험 포인트

- [ ] "**SSL/TLS 인증서**", "HTTPS 적용", "인증서 **만료·갱신을 자동화**" → ACM
- [ ] 퍼블릭 인증서는 **무료**입니다. 비용을 이유로 다른 답을 고르지 않도록 주의하시기 바랍니다
- [ ] ACM 인증서는 ELB·CloudFront·API Gateway 같은 **통합 서비스에 붙여** 쓰는 것이 기본입니다
- [ ] 사설 인증 기관(Private CA)은 **별도 유료**라는 점이 퍼블릭 인증서와 갈리는 지점입니다
- [ ] "EC2에 직접 인증서를 설치해야 한다"는 지문이 나오면 **ACM 퍼블릭 인증서로는 안 됩니다**. 프라이빗 키를 내보낼 수 없기 때문입니다

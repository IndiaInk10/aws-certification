# Amazon Cognito

> 앱 사용자의 가입·로그인·인증

## 한 줄로 말하면

내가 만든 **웹·모바일 앱의 사용자 가입과 로그인**을 대신 처리해 주는 서비스입니다.

## 핵심 개념

- **다루는 대상은 앱 사용자입니다** — AWS 콘솔에 들어오는 직원이 아니라, 내 서비스에 가입하는 **최종 고객**을 관리합니다. 여기가 IAM과 갈리는 가장 중요한 지점입니다.
- **사용자 풀(User Pool)** — 가입·로그인·비밀번호 재설정·MFA를 제공하는 사용자 디렉터리입니다. **인증**, 즉 "누구인지 확인하는 일"을 맡습니다.
- **자격 증명 풀(Identity Pool)** — 인증을 마친 사용자에게 **임시 AWS 자격 증명**을 발급해, 앱이 S3나 DynamoDB에 직접 접근할 수 있게 해 줍니다.
- **소셜·기업 로그인 연동** — Google, Apple, Facebook 같은 소셜 로그인과 SAML·OIDC 기반 기업 ID 공급자를 붙일 수 있습니다.
- **로그인 화면을 직접 만들지 않아도 됩니다** — 호스팅 UI가 제공되므로 인증 화면과 흐름을 처음부터 구현하실 필요가 없습니다.
- **확장성** — 사용자가 수백만 명으로 늘어도 인증 서버를 직접 운영하지 않습니다.

## 요금 모델

- **월간 활성 사용자(MAU)** 수를 기준으로 과금됩니다. 실제로 로그인이나 토큰 갱신이 일어난 사용자만 셉니다.
- 일정 규모까지는 **프리 티어**가 있어, 소규모 앱이라면 요금 없이 시작하실 수 있습니다.
- 계정만 만들어 두고 그 달에 활동이 없는 사용자는 과금 대상에 들어가지 않습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-iam]] | IAM은 **AWS 리소스에 접근하는 주체**의 권한을 다루고, Cognito는 **내 앱에 로그인하는 최종 사용자**를 다룹니다. 시험에서 가장 자주 뒤바뀌는 조합입니다 |
| [[aws-directory-service]] | 사내 **Active Directory** 연동이면 Directory Service이고, 앱 회원가입이면 Cognito입니다 |
| [[amazon-api-gateway]] | API Gateway는 API의 앞단이고, 그 API를 호출하는 사용자를 인증할 때 Cognito를 붙여 씁니다 |

## 한 줄로 말하면

데이터베이스 비밀번호나 API 키 같은 **비밀 정보를 안전하게 보관하고 주기적으로 자동 교체**해 주는 서비스입니다.

## 핵심 개념

- **비밀을 코드에서 빼냅니다** — 소스 코드나 설정 파일에 비밀번호를 적어 두는 대신 Secrets Manager에 넣고, 실행 시점에 API로 가져와 씁니다.
- **자동 교체(rotation)가 핵심입니다** — 정해진 주기마다 비밀번호를 **자동으로 바꿔 줍니다.** RDS·Aurora·Redshift·DocumentDB는 내장 기능으로 바로 붙고, 그 밖의 대상은 Lambda 함수로 교체 로직을 붙입니다. 이 기능이 다른 서비스와 갈리는 결정적 지점입니다.
- **저장 시 암호화** — 값은 [[aws-kms]] 키로 암호화되어 저장되고, 누가 언제 꺼내 갔는지는 [[aws-cloudtrail]]에 남습니다.
- **접근 제어** — IAM 정책과 리소스 정책으로 "어떤 역할이 어떤 비밀을 읽을 수 있는지"를 지정합니다.
- **교차 리전 복제** — 비밀을 다른 리전으로 복제해 재해 복구 구성에 활용하실 수 있습니다.

## 요금 모델

- **보관 중인 비밀의 개수(월 단위)** 와 **API 호출 수** 기준입니다.
- 무료 평가 기간이 있고, 그 이후에는 비밀 하나마다 월 요금이 붙습니다.
- 비용만 보면 Systems Manager Parameter Store의 표준 파라미터가 더 저렴합니다. **자동 교체가 필요할 때** Secrets Manager를 고르시면 됩니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-systems-manager]] | Parameter Store도 값을 안전하게 저장하지만 **자동 교체 기능이 없습니다.** 문제에 "자동으로 교체"가 보이면 Secrets Manager입니다 |
| [[aws-kms]] | KMS는 **암호화 키**를 다루고, Secrets Manager는 그 키로 암호화한 **비밀 값 자체**를 다룹니다 |
| [[aws-iam]] | IAM은 AWS 리소스 접근 **권한**을 다룹니다. 데이터베이스 비밀번호 같은 값을 보관하지는 않습니다 |

## 시험 포인트

- [ ] "**데이터베이스 자격 증명**", "**API 키**", "코드에 하드코딩하지 않고 관리" → Secrets Manager
- [ ] "**자동으로 교체(rotate)**"라는 표현이 결정적입니다. Parameter Store와 여기서 갈립니다
- [ ] 비밀 개수 기준 과금이라, 교체가 필요 없는 단순 설정값은 Parameter Store가 저렴합니다
- [ ] 비밀번호를 EC2 사용자 데이터나 환경 변수에 넣는다는 선택지는 오답입니다

## 한 줄로 말하면

여러 AWS 계정을 하나의 조직으로 묶어 **정책과 결제를 중앙에서 관리**하는 서비스입니다.

## 핵심 개념

- **조직과 관리 계정** — 계정 하나를 **관리 계정**으로 두고 나머지를 멤버 계정으로 초대하거나 새로 만듭니다. 관리 계정이 조직 전체의 정책과 청구를 담당합니다.
- **조직 단위(OU)** — 계정을 용도별(운영·개발·감사 등)로 묶는 폴더입니다. 정책은 보통 계정 하나가 아니라 OU에 걸어 두시면 됩니다.
- **서비스 제어 정책(SCP)** — 계정이 사용할 수 있는 권한의 **상한선**을 정합니다. **SCP는 권한을 부여하지 않고 막기만 합니다.** 실제 권한은 여전히 IAM으로 줘야 하고, SCP는 그 위에 뚜껑을 덮는 역할입니다.
- **통합 결제(Consolidated Billing)** — 모든 계정의 청구서를 하나로 모읍니다. 사용량이 합산되므로 **볼륨 할인 구간에 더 빨리 도달하고, 예약 인스턴스와 절감형 플랜 혜택을 계정끼리 공유**하게 되어 전체 비용이 줄어듭니다.
- **계정을 나누는 이유** — 환경별·부서별로 **격리**하고 청구를 분리해 보기 위해서입니다. 계정 경계는 AWS에서 가장 강력한 격리 수단입니다.
- **다른 서비스의 전제가 됩니다** — Control Tower, Firewall Manager, 조직 단위 CloudTrail 등이 Organizations 위에서 동작합니다.

## 요금 모델

- **AWS Organizations 자체는 무료입니다.** 계정을 몇 개 묶어도 서비스 요금이 붙지 않습니다.
- 각 계정이 사용한 **AWS 리소스 요금만** 관리 계정 청구서로 합쳐져 청구됩니다.
- 오히려 통합 결제로 사용량이 합산되면서 **볼륨 할인**을 더 유리하게 받게 됩니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-control-tower]] | Organizations는 계정을 묶는 **기반**이고, Control Tower는 그 위에 랜딩 존과 가드레일을 **자동으로 구성**해 주는 상위 도구입니다 |
| [[aws-iam]] | IAM은 계정 **안에서** 권한을 부여하고, SCP는 계정 **전체의 상한**을 정합니다. SCP만으로는 아무 권한도 생기지 않습니다 |
| [[aws-budgets]] | 예산을 정하고 초과 시 알리는 것은 Budgets입니다. Organizations는 청구서를 합칠 뿐입니다 |
| [[aws-cost-explorer]] | 합쳐진 비용을 계정별·서비스별로 쪼개 분석하는 것은 Cost Explorer입니다 |

## 시험 포인트

- [ ] "**여러 계정**", "**통합 결제**", "**SCP**", "OU로 그룹화" → Organizations
- [ ] **SCP는 권한을 주지 않습니다.** 허용 범위의 상한만 정하고, 실제 권한은 IAM으로 부여합니다
- [ ] 통합 결제의 이점은 청구서 하나로 합치는 것과 **볼륨 할인·예약 혜택 공유** 두 가지입니다
- [ ] Organizations 자체는 **무료**입니다
- [ ] "모범 사례대로 다계정 환경을 **자동 설정**"이 나오면 Control Tower 쪽입니다

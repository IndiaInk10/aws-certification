## 한 줄로 말하면

AWS 리소스에 대해 **누가 무엇을 할 수 있는지**를 정하는 서비스입니다.

## 핵심 개념

- **IAM 사용자** — 사람 한 명 또는 애플리케이션 하나에 대응하는 자격 증명입니다. 만든 직후에는 **아무 권한도 없고**, 정책을 붙여야 비로소 무언가를 할 수 있습니다.
- **IAM 그룹** — 사용자를 묶는 단위입니다. 그룹에 정책을 붙이면 소속 사용자 전원에게 한 번에 적용되므로, 사람이 늘어도 권한을 개별로 손보지 않아도 됩니다.
- **IAM 역할(Role)** — 필요할 때 **잠시 빌려 쓰는 권한 꾸러미**입니다. 임시 자격 증명을 발급받는 방식이라, EC2 인스턴스나 Lambda 함수가 다른 서비스에 접근할 때는 액세스 키를 심지 않고 역할을 연결하시면 됩니다.
- **IAM 정책(Policy)** — 무엇을 허용하고 무엇을 거부할지 적어 둔 JSON 문서입니다. 명시적 **거부(Deny)** 는 어떤 허용보다 우선합니다.
- **최소 권한 원칙** — 업무에 꼭 필요한 만큼만 부여합니다. 넓게 열어 두고 나중에 줄이는 방식은 쓰지 않습니다.
- **루트 사용자와 MFA** — 계정을 만들 때 생기는 루트 사용자는 무엇이든 할 수 있으므로 **일상 작업에 쓰지 않습니다.** MFA를 걸어 잠가 두고, 루트만 할 수 있는 소수의 작업에만 꺼내 쓰시기 바랍니다.
- **글로벌 서비스** — IAM은 리전을 고르지 않습니다. 한 번 만든 사용자와 역할이 모든 리전에서 그대로 통합니다.

## 요금 모델

- **IAM 자체는 무료입니다.** 사용자·그룹·역할·정책을 몇 개를 만들어도 IAM 요금은 붙지 않습니다.
- 요금은 IAM으로 접근한 **다른 AWS 서비스의 사용량**에만 발생합니다.
- 글로벌 서비스이므로 리전별 요금 차이도 없습니다.

## 시험 포인트

- [ ] "**최소 권한**", "특정 사용자에게 특정 리소스만 허용" → IAM 정책
- [ ] "EC2 인스턴스가 S3에 접근해야 한다" → 액세스 키를 인스턴스에 넣는 것이 아니라 **IAM 역할**을 연결합니다. 키를 코드에 하드코딩하는 선택지는 언제나 오답입니다
- [ ] **루트 사용자로 일상 작업을 하라는 선택지는 항상 오답입니다.** 루트에는 MFA를 켜고 잠가 둡니다
- [ ] IAM은 **글로벌**이고 **무료**입니다. "리전마다 따로 만들어야 한다"는 설명은 틀립니다
- [ ] 사용자가 많아지면 사용자마다가 아니라 **그룹**에 정책을 붙입니다
- [ ] 허용과 거부가 겹치면 **명시적 거부가 이깁니다**

# Amazon Inspector

> EC2·컨테이너의 취약점 자동 스캔

| | |
|---|---|
| **카테고리** | 05-보안-자격증명 |
| **배우는 모듈** | [[09-security]] |
| **문제은행 출현** | 46회 |

## 한 줄로 말하면

EC2 인스턴스·컨테이너 이미지·Lambda 함수를 자동으로 스캔해 **소프트웨어 취약점**을 찾아 주는 서비스입니다.

## 핵심 개념

- **하는 일은 취약점 스캔입니다** — 워크로드에 알려진 취약점(CVE)이 남아 있는지, 의도치 않게 네트워크 경로가 열려 있는지를 점검합니다.
- **대상은 워크로드** — Amazon EC2 인스턴스, Amazon ECR에 올린 컨테이너 이미지, AWS Lambda 함수입니다. 사람이나 계정이 아니라 **실행되는 코드와 서버**를 봅니다.
- **자동이고 지속적입니다** — 한 번 켜 두면 새 인스턴스나 새 이미지가 생기는 즉시 스캔 대상에 자동으로 들어갑니다. 일정을 잡아 수동으로 돌리지 않아도 됩니다.
- **위험 점수로 우선순위를 알려 줍니다** — 발견 항목마다 점수를 매겨 주므로 무엇부터 고쳐야 할지 판단하실 수 있습니다.
- **결과 전달** — 조사 결과를 [[aws-security-hub]]와 EventBridge로 보내 티켓 발행이나 자동 조치에 연결할 수 있습니다.
- **고치는 것은 내 몫입니다** — Inspector는 패치를 대신 적용해 주지 않습니다. 실제 패치는 [[aws-systems-manager]] 같은 도구로 수행합니다.

## 요금 모델

- 스캔한 **대상의 수와 스캔 횟수** 기준입니다. EC2는 인스턴스 수, 컨테이너는 스캔한 이미지 수, Lambda는 함수 수로 계산됩니다.
- 신규 계정에는 **무료 평가 기간**이 있어 규모를 미리 가늠하실 수 있습니다.
- 켜 두기만 하고 스캔할 대상이 없다면 요금은 발생하지 않습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-guardduty]] | Inspector는 "**뚫릴 구멍이 있는지**"를 미리 찾고, GuardDuty는 "**지금 공격받고 있는지**"를 로그에서 찾습니다 |
| [[amazon-macie]] | Macie가 보는 것은 패키지나 코드가 아니라 **S3에 저장된 데이터의 내용**입니다 |
| [[aws-systems-manager]] | 취약점을 **발견**하는 쪽이 Inspector, 발견된 것을 **패치**하는 쪽이 Systems Manager입니다 |
| [[aws-trusted-advisor]] | Trusted Advisor는 비용·성능·보안 전반의 **모범 사례 점검**이고, Inspector는 소프트웨어 취약점에 특화되어 있습니다 |

## 시험 포인트

- [ ] 대상은 **EC2·컨테이너 이미지·Lambda**입니다. "S3 버킷을 스캔한다"는 Macie와 바꿔 놓은 함정입니다

- [ ] "지속적으로 자동 스캔"이 특징입니다. 사람이 일정을 잡아 돌려야 한다는 설명은 틀립니다

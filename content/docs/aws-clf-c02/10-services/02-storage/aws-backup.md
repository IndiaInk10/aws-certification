# AWS Backup

> 여러 서비스의 백업을 한곳에서 중앙 관리

## 한 줄로 말하면

여기저기 흩어진 AWS 리소스의 백업을 **하나의 정책과 하나의 콘솔에서 통합 관리하는** 서비스입니다.

## 핵심 개념

- **여러 서비스를 한 번에 다룹니다** — EC2 인스턴스, [[amazon-ebs]] 볼륨, [[amazon-efs]], [[amazon-fsx]], [[amazon-rds]], [[amazon-dynamodb]], [[aws-storage-gateway]] 볼륨 등을 **같은 방식으로** 백업하실 수 있습니다.
- **백업 계획(Backup Plan)** — "매일 새벽 2시에 백업하고 35일 보관한 뒤 삭제" 같은 규칙을 만들어 두면, 태그가 붙은 리소스에 **자동으로 적용**됩니다. 스크립트를 짜실 필요가 없습니다.
- **백업 볼트** — 백업본이 모이는 저장소이고, KMS 키로 암호화됩니다. **Vault Lock**을 걸면 보존 기간이 끝나기 전에는 아무도 지울 수 없습니다.
- **교차 리전·교차 계정 복사** — 백업본을 다른 리전이나 다른 계정으로 복사해 두어 **재해 복구와 랜섬웨어 대비**를 하실 수 있습니다.
- **감사와 규정 준수** — 정책대로 백업이 돌고 있는지 리포트로 확인할 수 있어, 규정 준수 증빙이 필요한 조직에 유용합니다.

## 요금 모델

- **백업으로 저장한 용량(GB-월)** 과 **복원한 데이터 양**을 기준으로 과금합니다.
- 교차 리전 복사에는 **리전 간 데이터 전송 요금**이 추가로 붙습니다.
- AWS Backup 콘솔이나 정책 기능 자체에 별도 요금은 없습니다. 저장된 백업본에만 요금이 붙습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-s3-glacier]] | Glacier는 데이터를 **싸게 보관하는 저장소**이고, AWS Backup은 **언제 무엇을 백업하고 얼마나 보관할지 정책으로 관리하는 도구**입니다. |
| [[amazon-ebs]] | EBS 스냅샷을 직접 만들 수도 있지만 그러면 리소스마다 따로 관리해야 합니다. AWS Backup은 그 스냅샷들을 **하나의 정책으로 묶어** 줍니다. |
| [[aws-storage-gateway]] | Storage Gateway는 **온프레미스 데이터를 AWS 스토리지에 연결**하는 하이브리드 장치이고, AWS Backup은 **AWS 안의 리소스**를 백업합니다. |

## 시험 포인트

- [ ] 문제에 **"여러 AWS 서비스의 백업을 중앙에서 관리"**, **"백업 정책을 일관되게 적용"** 이 나오면 AWS Backup입니다
- [ ] **"규정 준수를 위해 백업 보존 정책을 강제하고 감사 보고서가 필요하다"** 도 이 서비스의 신호입니다
- [ ] 데이터를 **저장하는 곳**을 묻는 문제라면 S3·Glacier이고, **백업을 관리하는 도구**를 묻는 문제라면 AWS Backup입니다
- [ ] 교차 리전·교차 계정 복사로 **재해 복구**를 지원한다는 점을 기억해 두시기 바랍니다

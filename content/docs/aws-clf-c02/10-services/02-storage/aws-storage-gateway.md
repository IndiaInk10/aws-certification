# AWS Storage Gateway

> 온프레미스와 AWS 스토리지를 잇는 하이브리드 게이트웨이

## 한 줄로 말하면

온프레미스 애플리케이션이 **평소 쓰던 방식 그대로 AWS 클라우드 스토리지를 쓰게 해 주는** 하이브리드 게이트웨이입니다.

## 핵심 개념

- **애플리케이션을 고치지 않아도 됩니다** — 게이트웨이가 NFS·SMB·iSCSI 같은 **익숙한 프로토콜**로 보이므로, 기존 시스템은 로컬 스토리지에 쓰는 것처럼 동작하고 실제 데이터는 AWS로 갑니다.
- **게이트웨이 종류** — 용도에 따라 고르시면 됩니다.

| 종류 | 무엇을 하나 |
|---|---|
| **S3 File Gateway** | NFS·SMB로 올린 파일을 **S3 객체로** 저장합니다 |
| **FSx File Gateway** | 온프레미스에서 [[amazon-fsx]] for Windows File Server에 빠르게 접근합니다 |
| **Volume Gateway** | iSCSI **블록 볼륨**을 제공하고 백업을 클라우드에 둡니다 |
| **Tape Gateway** | 물리 테이프 장비를 **가상 테이프**로 대체하고 [[amazon-s3-glacier]]에 보관합니다 |

- **로컬 캐시가 있습니다** — 자주 쓰는 데이터는 온프레미스에 캐싱해 두므로 **접근 속도를 유지**하면서 용량은 클라우드에서 확보하실 수 있습니다.
- **계속 쓰는 연결입니다** — 한 번 옮기고 끝나는 마이그레이션 도구가 아니라, **상시로 온프레미스와 AWS를 잇는** 장치입니다.
- **어디에 배포하나** — 온프레미스의 가상 머신, 전용 하드웨어 어플라이언스, 또는 EC2 인스턴스 형태로 실행하실 수 있습니다.

## 요금 모델

- **AWS에 저장된 데이터 용량(GB-월)** 과 **요청 수**, 그리고 **아웃바운드 데이터 전송**을 기준으로 과금합니다.
- 저장 위치가 S3든 Glacier든, 해당 스토리지 클래스의 요금 체계를 그대로 따릅니다.
- 게이트웨이 소프트웨어 자체에는 별도 라이선스 요금이 없습니다. EC2에 배포하시면 그 인스턴스 요금이 추가됩니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-snow-family]] | Storage Gateway는 **네트워크로 상시 연결**하는 하이브리드 방식이고, Snow는 **물리 장비를 배송**해 한 번에 옮기는 방식입니다. "회선이 느리다 / 페타바이트급"이면 Snow입니다. |
| **AWS DataSync** | DataSync는 온프레미스와 AWS 사이에서 **데이터를 대량으로 복사·동기화**하는 전송 도구이고, Storage Gateway는 **계속 붙어 있는 스토리지 인터페이스**입니다. |
| [[aws-outposts]] | Outposts는 **AWS 하드웨어를 현장에 두는 것**이고, Storage Gateway는 현장 애플리케이션이 **클라우드 스토리지를 쓰게 이어 주는 것**입니다. |

## 시험 포인트

- [ ] 문제에 **"온프레미스 애플리케이션을 수정하지 않고 클라우드 스토리지를 쓰고 싶다"**, **"하이브리드 스토리지"** 가 나오면 Storage Gateway입니다
- [ ] **"물리 테이프 백업을 클라우드로 대체"** 는 곧 **Tape Gateway**입니다. 거의 고정된 신호입니다
- [ ] **"한 번에 대용량을 옮긴다 / 네트워크가 느리거나 없다"** 면 Storage Gateway가 아니라 **Snow Family**입니다
- [ ] **"파일을 반복적으로 동기화·전송"** 이면 DataSync 쪽입니다. 세 서비스를 상시 연결 / 일회성 배송 / 전송 자동화로 나눠 두시기 바랍니다
- [ ] 로컬 캐시 덕분에 **속도는 로컬처럼, 용량은 클라우드처럼** 쓴다는 점이 핵심 가치입니다

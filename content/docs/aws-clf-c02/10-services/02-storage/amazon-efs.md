## 한 줄로 말하면

**여러 EC2 인스턴스가 동시에 마운트해서 같은 파일을 공유하는** 완전관리형 파일 스토리지입니다.

## 핵심 개념

- **파일 스토리지입니다** — 폴더와 파일이라는 익숙한 구조로 접근하고, Linux 표준인 **NFS 프로토콜**로 마운트합니다.
- **여러 인스턴스가 동시에 붙습니다** — 수십, 수백 대의 인스턴스가 **같은 파일 시스템을 동시에 읽고 쓸 수 있습니다.** 웹 서버들이 공유하는 콘텐츠 디렉터리가 대표적인 용도입니다.
- **리전 서비스입니다** — 한 리전 안 **여러 가용 영역에 걸쳐** 데이터를 저장하므로, AZ 하나에 문제가 생겨도 파일에 계속 접근하실 수 있습니다.
- **용량을 미리 정하지 않습니다** — 파일을 넣으면 자동으로 커지고 지우면 줄어듭니다. **프로비저닝이라는 단계 자체가 없습니다.**
- **스토리지 클래스와 수명 주기** — 자주 쓰는 Standard와 저렴한 Infrequent Access가 있고, 일정 기간 접근되지 않은 파일을 **자동으로 저비용 클래스로 옮기실 수** 있습니다.
- **Linux 기반입니다** — SMB가 필요한 Windows 워크로드라면 EFS가 아니라 [[amazon-fsx]] for Windows File Server를 쓰시면 됩니다.

## 요금 모델

- **실제로 저장된 용량(GB-월)** 기준으로 과금합니다. EBS와 달리 **미리 잡아 둔 크기가 아니라 쓴 만큼**입니다.
- 스토리지 클래스에 따라 단가가 다르고, IA 클래스는 저장 단가가 낮은 대신 **읽어 올 때 요청 요금**이 붙습니다.
- 같은 용량이면 EBS보다 GB당 단가가 높은 편이므로, 공유가 필요 없는 워크로드에 쓰시면 손해입니다.
- 프리 티어에 매월 일정 용량의 Standard 스토리지가 포함됩니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-ebs]] | EFS는 **파일·리전 단위·여러 인스턴스 동시 연결**, EBS는 **블록·단일 AZ·한 인스턴스**입니다. 이 한 줄이 시험의 핵심입니다. |
| [[amazon-s3]] | S3는 **객체 스토리지**라 HTTP API로 접근하고, EFS는 **파일 시스템으로 마운트**해서 일반 애플리케이션이 그대로 씁니다. |
| [[amazon-fsx]] | EFS는 **Linux·NFS**용이고, FSx는 **Windows(SMB)나 Lustre(HPC)** 같은 특수 파일 시스템이 필요할 때 씁니다. |

## 시험 포인트

- [ ] 문제에 **"여러 EC2 인스턴스가 동시에 같은 파일에 접근"**, **"공유 파일 시스템"** 이 나오면 EFS입니다
- [ ] **"여러 가용 영역에 걸쳐"** 라는 표현이 스토리지 문제에 나오면 EBS가 아니라 EFS입니다
- [ ] EFS는 **용량을 미리 프로비저닝하지 않습니다.** "볼륨 크기를 지정해야 한다"는 선택지는 EBS의 설명입니다
- [ ] **Windows 파일 공유(SMB)** 를 물으면 EFS가 아니라 FSx for Windows File Server입니다
- [ ] EBS·EFS·S3 세 개를 **블록 / 파일 / 객체**로 묶어 두시면 스토리지 문제 대부분이 정리됩니다

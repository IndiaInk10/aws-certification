## 한 줄로 말하면

거의 꺼내 보지 않는 데이터를 **아주 싸게 장기 보관하는** S3의 아카이브 전용 스토리지 클래스입니다.

## 핵심 개념

- **S3와 별개 서비스가 아닙니다** — S3 안의 **스토리지 클래스**이므로 같은 버킷, 같은 API로 다루고 수명 주기 정책으로 자동 이동시킬 수 있습니다.
- **세 가지 클래스가 있습니다.**

| 클래스 | 꺼내는 데 걸리는 시간 | 어떤 데이터에 |
|---|---|---|
| **Glacier Instant Retrieval** | **밀리초**, 즉 즉시 | 분기에 한 번쯤 꺼내지만 꺼낼 때는 바로 필요한 데이터 |
| **Glacier Flexible Retrieval** | **몇 분에서 몇 시간** | 1년에 한두 번 꺼내고 기다릴 수 있는 백업 |
| **Glacier Deep Archive** | **몇 시간에서 하루 이상** | 법적 보존처럼 7~10년 두는 데이터. 가장 저렴합니다 |

- **검색(retrieval) 옵션** — Flexible Retrieval에서는 **Expedited(가장 빠르고 비쌈) · Standard · Bulk(가장 느리고 쌈)** 중에 고릅니다. Deep Archive에서는 Standard와 Bulk만 제공되고, 그마저도 시간 단위입니다.
- **최소 보관 기간이 있습니다** — 정해진 기간보다 일찍 지우면 남은 기간만큼 요금이 청구됩니다. Deep Archive가 가장 깁니다. "잠깐 넣었다 빼는" 용도로는 맞지 않습니다.
- **Vault Lock으로 규정 준수를 지원합니다** — 한 번 잠그면 아무도 지우거나 고칠 수 없는 **WORM** 정책을 걸 수 있어, 감사·법적 보존 요건에 대응하실 수 있습니다.

## 요금 모델

- **저장 용량(GB-월)** 기준이고, AWS 스토리지 중 단가가 가장 낮은 축에 속합니다.
- 대신 **데이터를 꺼낼 때 검색 요금**이 붙고, **빨리 꺼낼수록 비쌉니다.** 저장은 싸고 인출은 비싼 구조라고 기억하시면 됩니다.
- **최소 보관 기간**보다 일찍 삭제하면 조기 삭제 요금이 붙습니다.
- 요청 수와 아웃바운드 데이터 전송 요금은 S3와 같은 방식으로 별도 부과됩니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-s3]] | S3 Standard는 **자주 쓰는 데이터를 즉시** 꺼내는 용도이고, Glacier는 **거의 안 쓰는 데이터를 싸게 보관**하는 용도입니다. |
| [[aws-backup]] | AWS Backup은 여러 서비스의 **백업 작업을 정책으로 관리**하는 도구이고, Glacier는 그 데이터가 **최종적으로 저장되는 곳**입니다. |
| [[aws-storage-gateway]] | Tape Gateway를 쓰시면 온프레미스의 **가상 테이프 백업이 Glacier로** 들어갑니다. 물리 테이프 라이브러리를 대체하는 조합입니다. |

## 시험 포인트

- [ ] 문제에 **"아카이브"**, **"규정상 7년간 보관"**, **"거의 접근하지 않지만 삭제할 수는 없다"** 가 나오면 Glacier입니다
- [ ] **가장 저렴한 옵션 + 검색에 몇 시간이 걸려도 된다** → **Deep Archive**입니다
- [ ] **아카이브인데 꺼낼 때는 즉시 필요하다** → **Glacier Instant Retrieval**입니다. "아카이브 = 무조건 느림"이 아니라는 점이 함정입니다
- [ ] 검색 속도는 **Expedited > Standard > Bulk** 순으로 빠르고, 요금은 그 반대입니다
- [ ] **최소 보관 기간**과 **조기 삭제 요금**이 있다는 점을 기억해 두시기 바랍니다
- [ ] 자주 접근하는 데이터를 Glacier에 두면 검색 요금 때문에 **오히려 비싸집니다**

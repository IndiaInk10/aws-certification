# Amazon EBS

> EC2에 붙이는 블록 스토리지. 단일 AZ

## 한 줄로 말하면

EC2 인스턴스에 붙여 쓰는 **가상 하드디스크**이고, 인스턴스를 지워도 데이터가 남는 영구 블록 스토리지입니다.

## 핵심 개념

- **블록 스토리지입니다** — 운영 체제가 디스크로 인식하므로 **포맷하고 파일 시스템을 올려 쓰는** 방식입니다. 데이터베이스나 부팅 볼륨처럼 자주 바뀌는 데이터에 맞습니다.
- **가용 영역 하나 안에만 존재합니다** — 볼륨은 특정 AZ에 묶여 있어, **같은 AZ에 있는 인스턴스에만** 연결하실 수 있습니다. 다른 AZ로 옮기려면 스냅샷을 거쳐야 합니다.
- **기본적으로 인스턴스 하나에 연결합니다** — 한 번에 한 인스턴스가 붙는 것이 기본 사용 방식입니다. 여러 인스턴스가 동시에 같은 데이터를 써야 한다면 [[amazon-efs]]를 쓰시면 됩니다.
- **인스턴스와 수명이 분리됩니다** — 인스턴스를 종료해도 볼륨은 남길 수 있고, 다른 인스턴스에 다시 붙이실 수 있습니다.
- **스냅샷은 증분 백업입니다** — 스냅샷은 S3에 저장되고 **처음 한 번만 전체, 이후에는 바뀐 블록만** 저장합니다. 스냅샷으로 다른 AZ나 다른 리전에 볼륨을 복원하실 수 있습니다.
- **볼륨 유형** — 범용 SSD(gp3·gp2), 고성능 프로비저닝 IOPS SSD(io1·io2), 처리량 위주의 HDD(st1·sc1)가 있습니다. CLF-C02에서는 SSD는 IOPS, HDD는 처리량이라는 정도만 아시면 됩니다.

## 요금 모델

- **프로비저닝한 용량(GB-월)** 기준으로 과금합니다. 실제로 얼마나 채웠는지와 상관없이 **잡아 둔 크기 전체**에 요금이 붙습니다.
- 유형에 따라 **프로비저닝한 IOPS·처리량**에 추가 요금이 붙습니다.
- **스냅샷 저장 용량은 별도**로 GB-월 과금합니다.
- **인스턴스를 중지해도 EBS 요금은 계속 나갑니다.** 시험 단골 함정입니다.
- 프리 티어에 매월 일정 용량의 범용 SSD와 스냅샷 저장 공간이 포함됩니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-efs]] | EBS는 **블록·단일 AZ·한 인스턴스**이고, EFS는 **파일·리전 단위·여러 인스턴스 동시 연결**입니다. "여러 대가 같은 파일을 공유"면 EFS입니다. |
| [[amazon-s3]] | S3는 **객체 스토리지**로 통째로 넣고 꺼내는 구조이고, EBS는 **일부 블록만 수정**할 수 있습니다. 데이터베이스 파일은 EBS, 이미지·백업·로그는 S3입니다. |
| 인스턴스 스토어 | 인스턴스 스토어는 호스트에 직접 붙은 디스크라 **인스턴스를 중지·종료하면 데이터가 사라지는 휘발성**이고, EBS는 **영구**입니다. |

## 시험 포인트

- [ ] 문제에 **"EC2에 연결하는 영구 블록 스토리지"**, **"데이터베이스용 볼륨"**, **"운영 체제를 설치할 디스크"** 가 나오면 EBS입니다
- [ ] **EBS는 단일 AZ**입니다. "여러 AZ의 인스턴스가 동시에 연결한다"는 선택지는 EFS의 설명이라 오답입니다
- [ ] **인스턴스 스토어(휘발성) vs EBS(영구)** 는 매우 자주 나옵니다. "인스턴스를 중지하면 데이터가 사라진다"면 인스턴스 스토어입니다
- [ ] **스냅샷은 증분**이고 S3에 저장됩니다. "매번 전체를 복사한다"는 선택지는 오답입니다
- [ ] 인스턴스를 중지하면 인스턴스 요금은 멈추지만 **EBS 요금은 계속** 나갑니다
- [ ] 과금 기준은 **사용한 용량이 아니라 프로비저닝한 용량**입니다

## 한 줄로 말하면

**이벤트 버스**입니다. 어떤 사건이 일어나면 규칙에 따라 여러 대상 서비스로 그 사건을 흘려보냅니다.

## 핵심 개념

- **이벤트 버스** — AWS 서비스, 내가 만든 애플리케이션, 외부 SaaS가 보낸 이벤트가 모이는 통로입니다.
- **규칙(Rule)과 대상(Target)** — 이벤트 내용을 패턴으로 걸러 Lambda, SQS, SNS, Step Functions 등 여러 대상으로 동시에 보냅니다. 코드를 고치지 않고 규칙만 추가하면 됩니다.
- **한 사건에 여러 반응** — 주문 하나가 들어오면 결제 처리, 음식점 알림, 재고 확인, 배달 배차가 동시에 움직이는 구조를 이 서비스로 엮습니다.
- **SaaS 이벤트도 받습니다** — Zendesk, Datadog 같은 외부 SaaS 이벤트를 받아 AWS 쪽 처리를 트리거할 수 있습니다. **SNS와 뚜렷이 갈리는 지점**입니다.
- **일정 예약** — cron 형식으로 정해진 시각에 대상을 실행하는 스케줄 기능도 함께 제공합니다.
- **느슨한 결합** — 보내는 쪽은 누가 받는지 몰라도 되고, 받는 쪽을 나중에 추가해도 보내는 쪽을 손대지 않습니다.

## 요금 모델

- **버스로 게시된 이벤트 수**를 기준으로 과금합니다. 규칙을 몇 개 만들었는지가 아니라 **이벤트가 몇 건 흘렀는지**가 기준입니다.
- AWS 서비스가 기본 이벤트 버스로 보내는 이벤트는 **무료**입니다.
- 스키마 레지스트리, 이벤트 재생 같은 부가 기능은 별도로 계산됩니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-sns]] | SNS는 **주제를 구독한 대상 전원에게 그대로 팬아웃**합니다. EventBridge는 **이벤트 내용을 규칙으로 걸러** 대상마다 다르게 보내고, **SaaS 이벤트**까지 받습니다 |
| [[amazon-sqs]] | SQS는 받는 쪽이 꺼내 갈 때까지 **쌓아 두는 대기열**, EventBridge는 일어난 사건을 **즉시 라우팅**하는 버스입니다 |
| [[aws-step-functions]] | EventBridge는 "이 사건이 나면 저것들을 움직여라"이고, Step Functions는 "**1번 다음 2번, 실패하면 3번**"처럼 순서를 정의합니다 |

## 시험 포인트

- [ ] "이벤트 기반 아키텍처", "여러 AWS 서비스를 이벤트로 연결"이 보이면 EventBridge입니다
- [ ] 지문에 **SaaS 애플리케이션 이벤트**가 나오면 SNS가 아니라 EventBridge입니다
- [ ] "즉시 알림·이메일·SMS"는 SNS, "쌓아 두었다 처리"는 SQS입니다
- [ ] 과금 기준은 규칙 수가 아니라 **이벤트 수**입니다

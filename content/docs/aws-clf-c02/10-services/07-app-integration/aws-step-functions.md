# AWS Step Functions

> 여러 단계 워크플로를 시각적으로 조립

| | |
|---|---|
| **카테고리** | 07-애플리케이션-통합 |
| **배우는 모듈** | *이 코스에서는 다루지 않음 (문제은행 전용)* |
| **문제은행 출현** | 3회 |
| **상태** | - 미학습 |

## 한 줄로 말하면

여러 단계로 이루어진 작업을 **상태 머신**으로 그려 두고, 순서·분기·재시도를 서비스가 대신 관리하게 합니다.

## 핵심 개념

- **워크플로 오케스트레이션** — "1번 다음 2번, 성공하면 3번, 실패하면 4번" 같은 **순서와 분기**를 애플리케이션 코드가 아니라 서비스가 관리합니다.
- **상태 머신(State Machine)** — 각 단계를 상태로 정의합니다. 실행 결과가 시각적인 다이어그램으로 보이므로 **어느 단계에서 멈췄는지** 바로 확인하실 수 있습니다.
- **오류 처리와 재시도가 내장되어 있습니다** — 단계별 재시도, 대기, 대체 경로를 정의로 처리하므로 예외 처리 코드를 직접 짜지 않아도 됩니다.
- **여러 서비스를 단계로 엮습니다** — Lambda 함수 여러 개, ECS 작업, SNS·SQS 같은 서비스를 하나의 흐름으로 연결합니다.
- **긴 대기도 가능합니다** — 사람의 승인을 기다리는 단계처럼 오래 멈춰 있어야 하는 흐름도 다룰 수 있습니다.

## 요금 모델

- **상태 전환(state transition) 수**를 기준으로 과금합니다. 워크플로가 몇 단계를 지나갔는지가 기준입니다.
- 프리 티어가 있어 매달 일정 수의 상태 전환은 무료로 제공됩니다.
- 각 단계에서 호출한 **Lambda나 다른 서비스의 요금은 별도**입니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-eventbridge]] | EventBridge는 **사건이 나면 대상들을 트리거**합니다. Step Functions는 **정해진 순서대로 단계를 진행**하고 실패를 처리합니다 |
| [[amazon-sqs]] | SQS는 메시지를 쌓아 두는 **버퍼**일 뿐 순서와 분기를 관리하지 않습니다. 흐름을 지휘하는 쪽이 Step Functions입니다 |
| [[aws-lambda]] | Lambda는 **한 단계를 실행**하는 함수이고, Step Functions는 그 함수들을 **어떤 순서로 실행할지** 지휘합니다 |

## 시험 포인트

- [ ] "여러 단계 워크플로", "상태 머신", "시각적 워크플로", "단계별 순서와 분기"가 보이면 Step Functions입니다
- [ ] **"여러 Lambda 함수를 순서대로 조율"** 은 Step Functions가 정답입니다

- [ ] 과금 기준은 실행 시간이 아니라 **상태 전환 수**입니다

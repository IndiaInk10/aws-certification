## 한 줄로 말하면

노트북·스마트폰 같은 **개별 사용자의 디바이스**를 AWS 리소스와 온프레미스 네트워크에 안전하게 붙여 주는 완전관리형 원격 접속 VPN입니다.

## 핵심 개념

- **연결하는 대상은 "사람"입니다** — 네트워크와 네트워크를 잇는 것이 아니라, 재택근무자·출장자·외부 협력사 같은 **개인이 쓰는 디바이스 한 대 한 대**를 VPN 클라이언트로 연결합니다.
- **완전관리형이고 탄력적으로 확장됩니다** — 접속하는 사용자 수가 갑자기 늘어도 AWS가 알아서 용량을 늘립니다. VPN 장비를 직접 사서 증설할 필요가 없습니다.
- **고급 인증을 지원합니다** — Active Directory 연동, SAML 기반 페더레이션(회사의 기존 자격 증명 공급자), 상호 인증서 인증 중에서 고르실 수 있습니다. 문제에 "고급 인증 기능"이 나오는 이유입니다.
- **접근 범위를 규칙으로 통제합니다** — 어떤 사용자 그룹이 어떤 대상 네트워크에 닿을 수 있는지 권한 부여 규칙으로 나눌 수 있어, 전원에게 전체 네트워크를 열어 주지 않아도 됩니다.
- **AWS만 대상이 아닙니다** — VPC에 붙은 뒤 그 VPC와 이어진 **온프레미스 네트워크나 다른 VPC**까지 접근하도록 구성할 수 있습니다.
- **표준 OpenVPN 클라이언트를 씁니다** — 전용 하드웨어 없이 사용자의 PC에 클라이언트 소프트웨어만 깔면 됩니다.

## 요금 모델

- **엔드포인트를 붙여 둔 서브넷 하나당 시간당 요금**이 기본으로 붙습니다. 접속자가 없어도 엔드포인트를 살려 두면 계속 나갑니다.
- 여기에 **실제로 접속한 클라이언트 연결 시간**만큼 요금이 더해집니다.
- 프리 티어는 없습니다. 쓰지 않는 기간에는 엔드포인트 연결을 해제해 두는 것이 비용 관리 방법입니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-site-to-site-vpn]] | Client VPN은 **개별 사용자 디바이스**를 붙이고, Site-to-Site VPN은 **네트워크와 네트워크**(데이터 센터·지사)를 붙입니다. 이 한 줄이 시험에서 갈리는 지점입니다 |
| [[aws-direct-connect]] | Direct Connect는 온프레미스와 AWS를 잇는 **전용 물리 회선**입니다. 전 세계에 흩어진 개인을 붙이는 용도가 아니고, 대역폭을 늘리려는 경우의 답입니다 |
| [[amazon-workspaces]] | WorkSpaces는 **가상 데스크톱 자체**를 클라우드에 띄워 주고, Client VPN은 사용자가 쓰던 **자기 PC를 네트워크에 연결**해 줍니다 |
| [[aws-privatelink]] | PrivateLink는 사람이 아니라 **VPC가 서비스에** 프라이빗하게 연결하는 기술입니다 |

## 시험 포인트

- [ ] "**원격 작업자**", "**재택근무 직원**", "**개별 사용자가 AWS 리소스에 접속**" → Client VPN
- [ ] "**완전관리형**", "**수요에 따라 자동으로 확장**", "**고급 인증 기능**"이 함께 나오면 거의 확정입니다
- [ ] 함정: 지문에 "**사이트**", "**지사**", "**데이터 센터끼리**"가 보이면 Client VPN이 아니라 [[aws-site-to-site-vpn]]입니다
- [ ] 함정: "대역폭을 늘리고 일관된 성능"이 조건이면 [[aws-direct-connect]]입니다. VPN 계열은 인터넷 회선을 공유합니다

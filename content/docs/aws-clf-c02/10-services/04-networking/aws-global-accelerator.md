## 한 줄로 말하면

사용자를 가장 가까운 엣지에서 받은 다음 **AWS 백본망**으로 실어 날라, 전 세계 애플리케이션의 지연 시간과 가용성을 개선합니다.

## 핵심 개념

- **엣지로 받아 백본으로 보냅니다** — 사용자는 가장 가까운 AWS 엣지 로케이션으로 접속하고, 거기서 목적지 리전까지는 혼잡한 공용 인터넷 대신 AWS 내부 네트워크를 탑니다.
- **고정 애니캐스트 IP 두 개** — 애플리케이션 앞에 변하지 않는 IP 주소가 생깁니다. 뒤쪽 엔드포인트가 바뀌거나 다른 리전으로 넘어가도 클라이언트가 보는 주소는 그대로입니다. 방화벽에 IP를 등록해야 하는 환경에서 특히 유용합니다.
- **캐싱하지 않습니다** — CDN이 아니라 **네트워크 계층 가속**입니다. 그래서 HTTP뿐 아니라 **TCP와 UDP** 트래픽을 두루 다룹니다.
- **상태 확인과 자동 장애 조치** — 엔드포인트 상태를 계속 확인해, 문제가 생기면 몇 초 안에 정상 리전으로 트래픽을 넘깁니다.
- **여러 리전 배포에 씁니다** — 게임, 실시간 음성·영상, IoT처럼 지연 시간에 민감하고 캐싱할 수 없는 동적 트래픽이 대표 사례입니다.

## 요금 모델

- **액셀러레이터를 만들어 둔 시간(시간당 고정 요금)** 이 붙습니다. 트래픽이 없어도 켜 두면 계속 나갑니다.
- 여기에 **전송한 데이터양(GB)** 이 더해집니다. 인바운드와 아웃바운드 중 많은 쪽을 기준으로 하고, 트래픽이 오간 지역에 따라 단가가 다릅니다.
- 프리 티어는 없습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-cloudfront]] | CloudFront는 엣지에 **콘텐츠를 캐싱**하는 CDN이고 HTTP/HTTPS 중심입니다. Global Accelerator는 캐싱 없이 **경로를 가속**하며 TCP·UDP도 지원합니다 |
| [[amazon-route-53]] | Route 53은 DNS 응답으로 목적지를 알려 주므로 클라이언트의 DNS 캐시에 좌우됩니다. Global Accelerator는 **고정 IP로 직접 받아** 즉시 다른 리전으로 넘길 수 있습니다 |
| [[elastic-load-balancing]] | ELB는 한 리전 안에서 인스턴스에 분산하고, Global Accelerator는 **리전과 리전 사이**에서 고릅니다. 보통 Global Accelerator 뒤에 ELB를 둡니다 |

## 시험 포인트

- [ ] "**고정 IP 주소**", "**여러 리전에 걸친 애플리케이션**", "**TCP/UDP**", "**AWS 글로벌 네트워크(백본)로 지연 시간 개선**" → Global Accelerator
- [ ] 게임 서버, VoIP, 실시간 스트리밍처럼 **캐싱할 수 없는 동적 트래픽**이면 CloudFront가 아니라 Global Accelerator입니다
- [ ] 함정: 지문에 "**정적 콘텐츠를 캐싱**"이 들어가면 CloudFront입니다. Global Accelerator는 캐싱하지 않습니다
- [ ] 함정: 액셀러레이터는 **켜 둔 시간만큼 고정 요금**이 나가므로, 쓰지 않으면 지우시는 편이 좋습니다

> 여러 데이터 소스를 하나의 GraphQL API로 묶어 준다

## 한 줄로 말하면

앱이 필요한 데이터를 여기저기서 따로 불러오는 대신, **하나의 GraphQL 엔드포인트로 필요한 만큼만 요청하게** 해 주는 관리형 API 서비스입니다.

## 핵심 개념

- **GraphQL API를 위한 서비스입니다** — 이것 하나만 확실히 잡아 두시면 됩니다. 시험에서 AppSync는 거의 항상 **"GraphQL API"** 라는 한 줄로 정리됩니다.
- **여러 데이터 소스를 한 엔드포인트로 묶습니다** — [[amazon-dynamodb]], [[aws-lambda]], 관계형 데이터베이스, HTTP 엔드포인트 등에서 오는 데이터를 하나의 API 뒤에 모읍니다. 클라이언트는 어디서 오는지 몰라도 됩니다.
- **필요한 필드만 받아 갑니다** — 클라이언트가 원하는 항목을 지정해 요청하므로 불필요한 데이터를 덜 주고받습니다. 모바일 앱처럼 네트워크가 아까운 환경에서 유리합니다.
- **실시간 업데이트와 오프라인 동기화** — 데이터가 바뀌면 구독한 클라이언트에게 밀어 주고, 오프라인 상태에서 쌓인 변경을 다시 연결될 때 동기화하는 기능을 제공합니다. 채팅이나 협업 앱에서 씁니다.
- **완전관리형입니다** — 서버를 띄우거나 확장을 신경 쓰실 필요가 없습니다.
- **Amplify와 짝을 이룹니다** — [[aws-amplify]]로 풀스택 앱을 만들 때 데이터 계층으로 AppSync가 붙는 구성이 흔합니다. 다만 **AppSync는 데이터 연결 한 조각**이지 앱 전체를 만들어 주지 않습니다.

## 요금 모델

- **처리한 쿼리·데이터 변경 작업 수**를 기준으로 과금합니다.
- 실시간 업데이트를 쓰시면 **전달한 실시간 메시지 수**와 **클라이언트가 연결되어 있던 시간**에도 요금이 붙습니다.
- 뒤에 붙은 데이터 소스(DynamoDB, Lambda 등)의 요금은 별도로 냅니다.
- 프리 티어가 있어 가입 후 일정 기간 동안 일정량의 요청을 무료로 쓰실 수 있습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-api-gateway]] | API Gateway는 **REST·HTTP API**를 만드는 정문입니다. AppSync는 **GraphQL** 전용입니다. 문제에 GraphQL이라는 낱말이 없으면 대개 API Gateway 쪽입니다 |
| [[aws-amplify]] | Amplify는 인증·스토리지·호스팅까지 붙여 **풀스택 앱을 통째로** 만들어 줍니다. AppSync는 그중 **데이터 API 한 조각**입니다. "풀스택", "인증과 스토리지를 빠르게 추가"면 Amplify입니다 |
| [[aws-lambda]] | Lambda는 **코드를 실행**합니다. AppSync는 그 Lambda를 데이터 소스로 불러 쓰는 **API 계층**입니다 |

## 시험 포인트

- [ ] **GraphQL**이라는 낱말이 보이면 AppSync입니다. 반대로 AppSync가 보기에 있는데 GraphQL 이야기가 없으면 대개 **오답 미끼**입니다
- [ ] 모듈 13 평가에서 AppSync는 **정답이 아닌 보기로 반복해 등장합니다.** 풀스택 개발은 Amplify, 원격 데스크톱은 [[amazon-workspaces]] 쪽입니다
- [ ] REST API를 만드는 문제라면 AppSync가 아니라 [[amazon-api-gateway]]입니다
- [ ] **여러 데이터 소스를 하나의 엔드포인트로 묶는다**, **모바일 앱의 실시간·오프라인 동기화**가 이 서비스의 정답 신호입니다
- [ ] 과금 기준은 **요청 수**이고, 실시간 기능을 쓰면 연결 시간에도 요금이 붙습니다

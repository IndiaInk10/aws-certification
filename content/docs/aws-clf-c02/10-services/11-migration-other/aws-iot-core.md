## 한 줄로 말하면

센서가 달린 **현실의 물건**을 클라우드에 안전하게 연결하고, 그 데이터를 다른 AWS 서비스로 흘려보내는 서비스입니다.

## 핵심 개념

- **IoT의 조건은 "물리 디바이스"입니다** — 공장 조립 라인 장비, 스마트 홈 기기, 웨어러블처럼 **실제로 존재하는 물건**이 네트워크로 데이터를 주고받아야 IoT입니다. 모바일 앱이나 온라인 뱅킹은 아무리 똑똑해도 IoT가 아닙니다.
- **연결과 메시지 중계** — 수많은 디바이스가 동시에 붙어 메시지를 주고받게 해 주는 관문 역할을 합니다. MQTT처럼 저전력·저대역폭 환경에 맞는 경량 프로토콜을 지원합니다.
- **디바이스마다 인증서로 인증합니다** — 각 디바이스에 고유한 자격 증명을 발급하고 통신을 암호화하므로, 아무 장비나 끼어들 수 없습니다. 보안이 이 서비스의 큰 몫입니다.
- **규칙 엔진** — "온도가 임계값을 넘으면 알림을 보내라"처럼 조건을 걸어 두면, 들어온 메시지를 [[amazon-sns]]·[[aws-lambda]]·[[amazon-s3]]·[[amazon-kinesis]] 같은 서비스로 자동으로 넘겨 줍니다.
- **디바이스 섀도우** — 장비가 잠시 오프라인이어도 마지막 상태를 클라우드에 보관해 두어, 다시 연결되면 그 상태를 동기화합니다.
- **대규모를 전제로 합니다** — 디바이스가 수만 대로 늘어도 서버를 직접 늘리지 않습니다. 확장은 AWS가 맡습니다.

## 요금 모델

- **사용량 기준**입니다. 디바이스가 접속해 있던 **연결 시간**, 주고받은 **메시지 수**, **규칙 엔진 실행 횟수**, 디바이스 섀도우·레지스트리 **작업 수** 등을 각각 계산합니다.
- 최소 요금이나 선결제가 없어, 디바이스를 몇 대부터 시작해도 됩니다.
- **프리 티어**가 제공됩니다. 규칙에 따라 호출된 Lambda나 저장된 S3 요금은 해당 서비스 쪽에서 별도로 발생합니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-kinesis]] | Kinesis는 들어온 **스트리밍 데이터를 처리·분석**합니다. IoT Core는 그 앞 단계에서 **디바이스를 연결하고 메시지를 받아** Kinesis로 넘기는 쪽입니다 |
| [[amazon-connect]] | Connect는 **사람과의 통화**를 다루는 콜센터입니다. 장비 데이터 수집과 무관합니다 |
| [[aws-outposts]] | Outposts는 AWS 인프라를 **내 데이터 센터에 설치**하는 하드웨어이고, IoT Core는 이미 현장에 있는 디바이스를 **클라우드에 연결**하는 소프트웨어 서비스입니다 |

## 시험 포인트

- [ ] "**커넥티드 디바이스**", "**센서**", "**조립 라인 장비 모니터링**", "**스마트 홈 기기**" → IoT Core
- [ ] 판단 기준 한 문장: **물리적 디바이스가 데이터를 수집해 통신하는가.** 그렇다면 IoT, 소프트웨어뿐이면 IoT가 아닙니다
- [ ] 함정: 모바일 앱·온라인 뱅킹·스마트 TV의 추천 기능은 **IoT가 아닙니다.** IoT 사례를 고르는 복수 선택 문제로 나옵니다
- [ ] 디바이스별 **인증서 기반 인증과 암호화**가 기본이라는 점이 장점 선택지로 등장합니다

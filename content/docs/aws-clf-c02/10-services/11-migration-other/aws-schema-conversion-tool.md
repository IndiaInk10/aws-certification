## 한 줄로 말하면

원본 데이터베이스의 **테이블 구조와 저장 프로시저 같은 코드 객체를, 종류가 다른 대상 데이터베이스의 문법으로 바꿔 주는** 변환 도구입니다.

## 핵심 개념

- **이기종(異機種) 마이그레이션에서 씁니다** — Oracle을 [[amazon-aurora]] PostgreSQL로, SQL Server를 MySQL로 옮기는 것처럼 **엔진 종류가 바뀌는** 경우입니다. 같은 엔진끼리 옮길 때는 필요하지 않습니다.
- **옮기는 것은 데이터가 아니라 구조입니다** — 테이블·인덱스·뷰·저장 프로시저·함수 같은 **스키마와 코드 객체**를 번역합니다. 안에 든 데이터 행을 옮기는 일은 [[aws-dms]]가 맡습니다.
- **평가 보고서를 먼저 줍니다** — 변환을 돌리기 전에 "자동으로 바뀌는 것"과 "사람이 손봐야 하는 것"을 목록으로 알려 줍니다. 마이그레이션 난이도를 가늠하는 자료가 됩니다.
- **100% 자동은 아닙니다** — 엔진마다 문법과 기능이 다르므로 자동 변환되지 않는 부분이 남습니다. 그 부분은 개발자가 직접 고쳐야 합니다.
- **데이터 웨어하우스 스키마도 다룹니다** — 기존 웨어하우스의 스키마를 [[amazon-redshift]] 형식으로 바꾸는 데에도 사용합니다.
- **DMS를 돕는 보조 도구입니다** — 단독으로 마이그레이션을 완결하지 않습니다. **SCT로 그릇을 만들고, DMS로 내용물을 붓는** 순서로 기억해 두시기 바랍니다.

## 요금 모델

- **AWS SCT 자체는 무료로 내려받아 쓰실 수 있습니다.** 변환 작업에 요금이 붙지 않습니다.
- 실제 요금은 이전 대상이 되는 **데이터베이스 리소스**와, 데이터를 옮길 때 쓰는 **DMS 복제 인스턴스** 쪽에서 발생합니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-dms]] | DMS는 **데이터를 실제로 옮깁니다.** SCT는 **스키마와 코드를 번역**할 뿐입니다. 지문이 "계획·평가·변환·마이그레이션을 한 도구로"처럼 이관 전체를 요구하면 답은 DMS입니다 |
| [[aws-application-migration-service]] | 이쪽은 **서버 전체**를 옮깁니다. SCT는 데이터베이스 **스키마 한 조각**만 다룹니다 |
| [[aws-migration-hub]] | Migration Hub는 진행 상황을 **추적**합니다. SCT는 추적 기능이 없는 **변환 도구**입니다 |

## 시험 포인트

- [ ] 문제에 **"스키마 변환", "서로 다른 데이터베이스 엔진으로", "저장 프로시저·코드 객체 변환"** 이 나오면 SCT입니다
- [ ] **SCT는 데이터를 옮기지 않습니다.** 데이터 이전은 DMS입니다. 이 한 문장이 갈리는 지점입니다
- [ ] DMS와 나란히 보기로 나올 때, 지문이 **이관 전체**를 요구하면 DMS를 고르셔야 합니다. SCT는 보조 도구입니다
- [ ] 도구 자체는 **무료**입니다
- [ ] 같은 엔진끼리 옮기는 동종 마이그레이션에서는 SCT가 필요하지 않다는 점도 함께 기억해 두시기 바랍니다

## 한 줄로 말하면

**온프레미스와 AWS 사이에서 대용량 데이터를 네트워크로 빠르게 옮기는 일을 자동화**해 주는 전송 서비스입니다.

## 핵심 개념

- **네트워크를 통한 전송** — 인터넷이나 [[aws-direct-connect]] 회선을 타고 데이터를 옮깁니다. **물리적으로 장비를 배송하지 않는다**는 점이 Snow Family와 갈리는 결정적 지점입니다.
- **에이전트 방식** — 온프레미스 쪽에 DataSync 에이전트를 설치하면, 에이전트가 원본 스토리지를 읽어 AWS로 보냅니다. NFS, SMB, HDFS, 객체 스토리지를 원본으로 삼을 수 있습니다.
- **전송 대상** — [[amazon-s3]], [[amazon-efs]], [[amazon-fsx]]로 보낼 수 있고, **AWS 스토리지 서비스 사이의 전송**에도 씁니다.
- **자동화와 증분 전송** — 일정을 걸어 두면 주기적으로 실행되고, **바뀐 부분만 골라 전송**하므로 반복 동기화가 효율적입니다.
- **암호화와 검증** — 전송 중 데이터를 암호화하고, 옮긴 뒤 **무결성을 자동으로 검증**합니다. 스크립트로 직접 만들던 검증·재시도 로직이 필요 없습니다.
- **대표 사용 사례** — 데이터 센터의 파일 서버를 클라우드로 이전, 백업·아카이브를 S3로 이동, 온프레미스와 클라우드 사이의 정기 동기화입니다.

## 요금 모델

- **실제로 전송한 데이터 양(GB)** 을 기준으로 과금합니다. 에이전트 실행이나 작업 예약에는 별도 요금이 없습니다.
- 전송된 데이터가 도착해서 쌓이는 **S3·EFS·FSx의 스토리지 요금**은 따로 냅니다.
- 회선을 통한 **데이터 전송 요금**은 사용하는 네트워크 경로(인터넷 또는 Direct Connect)에 따라 별도로 발생할 수 있습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-snow-family]] | DataSync는 **네트워크로** 보내고, Snow Family는 **물리 장비를 배송**합니다. 대역폭이 부족하거나 페타바이트급이면 Snow, 회선이 충분하면 DataSync입니다 |
| [[aws-transfer-family]] | Transfer Family는 **SFTP·FTPS·FTP 프로토콜**로 외부 파트너가 파일을 주고받게 해 주고, DataSync는 **내가 대량 데이터를 옮기는** 도구입니다 |
| [[aws-storage-gateway]] | Storage Gateway는 온프레미스 앱이 클라우드 스토리지를 **계속 붙여 쓰게** 해 주는 하이브리드 도구이고, DataSync는 **데이터를 옮기는 전송 작업**입니다 |
| [[aws-dms]] | DMS는 **데이터베이스**를 이전하고, DataSync는 **파일·객체 데이터**를 옮깁니다 |

## 시험 포인트

- [ ] 문제에 **"온프레미스에서 AWS로 대용량 데이터를 네트워크로 전송"**, **"파일 전송을 자동화하고 일정을 잡는다"** 가 나오면 DataSync입니다
- [ ] **"네트워크 대역폭이 부족하다"**, **"인터넷 연결이 열악하다"**, **"페타바이트 규모"** 가 보이면 DataSync가 아니라 [[aws-snow-family]]입니다. 가장 자주 나오는 구분입니다
- [ ] **"파트너가 SFTP로 파일을 올린다"** 는 [[aws-transfer-family]]입니다
- [ ] DataSync는 **전송 중 암호화와 전송 후 무결성 검증**을 자동으로 해 준다는 점이 장점 선택지로 등장합니다
- [ ] 요금이 **전송한 데이터 양(GB) 기준**이라는 점을 기억하시기 바랍니다

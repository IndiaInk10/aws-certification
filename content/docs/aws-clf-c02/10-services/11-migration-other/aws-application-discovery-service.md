## 한 줄로 말하면

옮기기 전에 온프레미스 데이터 센터를 훑어 **어떤 서버가 몇 대 있고 서로 무엇에 의존하고 있는지 목록을 만들어 주는** 조사 서비스입니다.

## 핵심 개념

- **마이그레이션의 두 번째 단계, 동원(Mobilize)에서 씁니다** — 비용을 계산한 다음, 실제로 옮기기 전에 **무엇을 가지고 있는지부터 파악**하는 자리입니다.
- **서버 인벤토리를 수집합니다** — 서버 사양(CPU·메모리·디스크), 설치된 소프트웨어, 실제 사용률 같은 정보를 모읍니다. 손으로 엑셀을 채우던 일을 대신합니다.
- **상호 의존성 매핑이 핵심 가치입니다** — 어떤 서버가 어떤 서버와 통신하는지를 그려 줍니다. 이 지도가 없으면 **딸린 것을 모르고 하나만 옮겼다가 서비스가 멈춥니다.** 그래서 옮기는 순서를 정하는 근거가 됩니다.
- **수집 방식이 두 가지입니다** — 가상화 환경에 가상 어플라이언스를 올려 **에이전트 없이** 수집하는 방식과, 서버마다 **에이전트를 설치**해 더 자세히 수집하는 방식이 있습니다.
- **수집한 데이터는 Migration Hub로 모입니다** — 조사 결과를 [[aws-migration-hub]]에서 확인하고 애플리케이션 단위로 묶어 계획을 세웁니다.
- **직접 옮기지 않습니다** — 이름 그대로 **디스커버리(조사)** 까지가 역할입니다. 이전은 다른 서비스가 수행합니다.

## 요금 모델

- **Application Discovery Service 자체는 무료입니다.** 데이터를 수집하고 보는 데 요금이 붙지 않습니다.
- 수집한 데이터를 [[amazon-s3]]로 내보내 [[amazon-athena]] 등으로 더 깊게 분석하실 때에만 **그 서비스들의 요금**이 발생합니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[migration-evaluator]] | 평가기는 **얼마가 드는지 계산해 비즈니스 사례**를 만듭니다. Discovery Service는 **무엇이 있는지 자산과 의존 관계를 조사**합니다. "CFO·자금 지원"이면 평가기, "인벤토리·의존성"이면 Discovery Service입니다 |
| [[aws-application-migration-service]] | 이쪽은 **실제로 서버를 옮깁니다.** Discovery Service는 옮기기 전 조사만 합니다 |
| [[aws-migration-hub]] | Migration Hub는 조사 결과를 받아 **진행 상황을 추적하는 화면**입니다. 데이터를 **수집하는** 쪽이 Discovery Service입니다 |
| [[aws-config]] | Config는 **AWS 안의 리소스** 구성을 기록합니다. Discovery Service는 아직 AWS로 오지 않은 **온프레미스**를 조사합니다 |

## 시험 포인트

- [ ] 문제에 **"온프레미스 서버 인벤토리", "애플리케이션 간 상호 의존성 파악", "마이그레이션 계획 수립"** 이 나오면 Discovery Service입니다
- [ ] 마이그레이션 3단계 중 **동원(Mobilize)** 단계의 도구로 묶어 두시기 바랍니다
- [ ] **조사·계산·추적·실행**을 가르는 네 갈래 문제가 모듈 12의 단골입니다. Discovery Service는 **조사**입니다
- [ ] 서비스 자체는 **무료**입니다
- [ ] 데이터를 실제로 옮긴다는 설명이 붙으면 오답입니다

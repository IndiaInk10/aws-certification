## 한 줄로 말하면

온프레미스나 다른 클라우드에 있는 서버를 **통째로 복제해 두었다가 AWS에서 그대로 켜는**, 마이그레이션 실행 도구입니다.

## 핵심 개념

- **마이그레이션의 세 번째 단계, 실행을 맡습니다** — 조사와 계산이 끝난 뒤 **실제로 옮기는** 단계의 대표 서비스입니다. 모듈 12에서 "옮긴다"는 표현이 나오면 이 서비스입니다.
- **리호스팅(리프트 앤 시프트)이 기본입니다** — 애플리케이션을 다시 만들지 않고 **있는 그대로** 옮깁니다. 코드를 고치지 않아도 되므로 대규모 이전에서 가장 빠른 방법입니다.
- **지속적인 블록 수준 복제** — 원본 서버가 **돌아가는 동안** 디스크 내용을 AWS의 준비 영역으로 계속 복제합니다. 그래서 실제 전환 시점의 가동 중지 시간이 짧습니다.
- **전환 전에 테스트할 수 있습니다** — 원본에 영향을 주지 않고 테스트 인스턴스를 띄워 잘 뜨는지 확인한 뒤에 전환하실 수 있습니다.
- **옮긴 뒤 현대화로 이어집니다** — 일단 EC2로 올려놓은 다음 관리형 서비스로 바꿔 나가는 순서를 AWS가 권장합니다. "마이그레이션하면서 현대화"라는 지문이 이 서비스를 가리킵니다.
- **자동화가 목적입니다** — 서버마다 수작업으로 이미지를 만들어 옮기던 일을 자동화해, 많은 서버를 같은 방식으로 처리합니다.

## 요금 모델

- **복제 중인 소스 서버 1대당 시간**을 기준으로 과금합니다. 서버 대수 × 복제한 시간이 계산 기준입니다.
- 서버마다 일정 기간은 **무료로 복제**할 수 있어, 정해진 기간 안에 전환을 끝내면 이 요금이 발생하지 않습니다.
- 복제본을 담아 두는 **준비 영역의 EBS 볼륨·스냅샷**, 그리고 전환 후 돌아가는 **EC2 인스턴스** 요금은 별도로 냅니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-application-discovery-service]] | Discovery Service는 옮기기 전 **조사**만 합니다. 이 서비스는 **실제 이전을 수행**합니다 |
| [[migration-evaluator]] | 평가기는 **비용을 계산해 투자 근거**를 만듭니다. 이 서비스는 계산이 아니라 **실행**입니다 |
| [[aws-migration-hub]] | Migration Hub는 **어디까지 왔는지 보는 관제탑**입니다. 실제로 서버를 옮기는 것은 이 서비스입니다 |
| [[aws-dms]] | DMS는 **데이터베이스**를 옮깁니다. Application Migration Service는 **서버와 애플리케이션 전체**를 옮깁니다. 지문에 데이터베이스 이야기만 있으면 DMS입니다 |
| [[aws-elastic-disaster-recovery]] | 복제 방식이 거의 같지만 목적이 다릅니다. 이쪽은 **한 번 옮기고 끝내는 마이그레이션**, Elastic Disaster Recovery는 **평소에 대기시켜 두는 재해 복구**입니다 |

## 시험 포인트

- [ ] 문제에 **"애플리케이션을 실제로 마이그레이션", "가동 중지 시간을 최소화하며 서버를 이전", "리프트 앤 시프트"** 가 나오면 이 서비스입니다
- [ ] **"마이그레이션하면서 현대화하고 비용도 절감"** 이라는 지문이 이 서비스를 가리키는 실제 출제 표현입니다
- [ ] 모듈 12의 네 갈래(조사·계산·추적·실행)에서 **실행** 칸입니다
- [ ] 데이터베이스만 옮기는 문제라면 이 서비스가 아니라 [[aws-dms]]입니다
- [ ] 과금 기준은 **복제한 소스 서버 × 시간**이고, 서버마다 일정 기간 무료 복제가 제공됩니다

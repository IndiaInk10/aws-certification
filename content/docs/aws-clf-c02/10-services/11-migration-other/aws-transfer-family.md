## 한 줄로 말하면

**SFTP · FTPS · FTP 같은 기존 파일 전송 프로토콜을 그대로 쓰면서** S3나 EFS에 파일을 주고받게 해 주는 완전관리형 서비스입니다.

## 핵심 개념

- **프로토콜을 그대로 유지합니다** — 거래처나 파트너가 수년째 쓰던 **SFTP·FTPS·FTP 클라이언트와 스크립트를 바꾸지 않고** AWS로 옮겨 올 수 있습니다. 상대편은 저장소가 S3로 바뀐 줄도 모릅니다.
- **저장 대상은 S3와 EFS** — 올라온 파일은 곧바로 [[amazon-s3]] 버킷이나 [[amazon-efs]] 파일 시스템에 저장되므로, 이후 분석·처리 파이프라인에 바로 연결됩니다.
- **FTP 서버를 운영하지 않습니다** — 서버 프로비저닝, 패치, 고가용성 구성이 필요 없습니다. AWS가 엔드포인트를 관리하고 자동으로 확장합니다.
- **사용자 인증 방식 선택** — 서비스가 관리하는 사용자, Active Directory 연동, 또는 직접 만든 자격 증명 저장소 중에서 고를 수 있습니다.
- **대표 사용 사례** — 금융·의료·물류처럼 **파트너사와 정기적으로 파일을 교환**하는 업무, 기존 FTP 서버를 클라우드로 이전하는 작업입니다.

## 요금 모델

- **활성화한 프로토콜 엔드포인트가 켜져 있는 시간**을 기준으로 과금합니다. SFTP와 FTPS를 함께 켜면 각각 과금됩니다.
- 여기에 **업로드·다운로드한 데이터 양(GB)** 요금이 더해집니다.
- 파일이 실제로 저장되는 **S3·EFS의 스토리지 요금은 별도**입니다.
- 엔드포인트를 켜 두기만 해도 시간 요금이 발생하므로, **쓰지 않는 엔드포인트는 삭제**하는 것이 비용 관리의 기본입니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-datasync]] | Transfer Family는 **외부에서 SFTP 등으로 파일을 주고받는 창구**이고, DataSync는 **내가 대량 데이터를 옮기는 전송 작업**입니다 |
| [[aws-snow-family]] | Transfer Family는 **네트워크 프로토콜**로 전송하고, Snow Family는 **물리 장비를 배송**합니다 |
| [[aws-storage-gateway]] | Storage Gateway는 온프레미스 앱에 **파일 시스템·볼륨·테이프처럼 보이게** 해 주고, Transfer Family는 **FTP 계열 프로토콜 엔드포인트**를 제공합니다 |

## 시험 포인트

- [ ] 문제에 **"SFTP"**, **"FTPS"**, **"FTP"**, **"기존 파일 전송 워크플로를 바꾸지 않고"** 가 나오면 Transfer Family입니다
- [ ] **"파트너·고객이 파일을 업로드한다"** 는 표현이 함께 나오면 거의 확실합니다
- [ ] 대량 마이그레이션 자동화는 Transfer Family가 아니라 [[aws-datasync]]입니다. **"프로토콜을 유지하느냐"** 로 가르시기 바랍니다
- [ ] 저장 대상이 **S3와 EFS**라는 점, 그리고 **FTP 서버를 직접 운영하지 않아도 된다**는 점이 이점 선택지로 나옵니다
- [ ] 요금이 **엔드포인트 활성 시간 + 전송량**이라는 점을 기억하시기 바랍니다

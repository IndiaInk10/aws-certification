## 한 줄로 말하면

마케팅 뉴스레터부터 주문 확인 메일까지, **이메일을 대량으로 보내는 일**을 맡아 주는 서비스입니다.

## 핵심 개념

- **보내는 이메일의 두 종류를 모두 다룹니다** — 프로모션·뉴스레터 같은 **마케팅 이메일**과, 주문 확인·비밀번호 재설정 같은 **트랜잭션(거래) 이메일**을 모두 발송합니다.
- **메일 서버를 직접 운영하지 않습니다** — 발송 서버 구축, 확장, 유지 보수를 AWS가 맡습니다. 애플리케이션은 API나 SMTP로 요청만 보내면 됩니다.
- **도달률을 관리해 줍니다** — 반송(bounce)·수신 거부·스팸 신고를 추적하고 발신 평판을 관리하는 기능을 제공해, 메일이 스팸함에 빠지지 않도록 돕습니다.
- **발신 도메인을 검증합니다** — 아무 주소로나 보낼 수 없고, 소유한 도메인·주소를 먼저 인증해야 합니다. 처음에는 발송이 제한된 샌드박스 상태에서 시작합니다.
- **수신도 됩니다** — 메일을 받아 [[amazon-s3]]에 저장하거나 [[aws-lambda]]로 처리하도록 연결할 수 있습니다. 다만 시험에서는 대부분 **발송** 쪽으로 나옵니다.
- **다른 서비스와 조합됩니다** — API Gateway → Lambda → SES처럼, 애플리케이션 흐름의 마지막 "고객에게 알린다" 단계를 담당하는 구성이 자주 나옵니다.

## 요금 모델

- **발송한 이메일 건수** 기준으로 과금합니다. 여기에 첨부 파일 등 **보낸 데이터 용량**이 더해집니다.
- 메일을 **수신**하는 경우에도 받은 건수 기준으로 요금이 붙습니다.
- **프리 티어**가 제공되며, 전용 IP 주소처럼 선택적으로 추가하는 기능에는 별도 요금이 붙습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-sns]] | SNS는 **알림을 여러 구독자에게 뿌리는(팬아웃)** 메시징 서비스입니다. 이메일도 보낼 수 있지만 시스템 알림용이고, **고객 대상 대량·마케팅 이메일**은 SES입니다 |
| [[amazon-connect]] | Connect는 **콜센터**입니다. 같은 "고객 커뮤니케이션"이라도 통화·채팅 응대 쪽이라 이메일 발송과 갈립니다 |
| [[amazon-sqs]] | SQS는 애플리케이션 사이에 **메시지를 줄 세워 전달**합니다. 사람에게 메일을 보내는 일과는 다릅니다 |

## 시험 포인트

- [ ] "**마케팅 이메일**", "**대량 이메일 발송**", "**뉴스레터**", "**트랜잭션 이메일**" → SES
- [ ] "이메일 발송을 자동화·최적화해 고객 참여를 높인다"는 지문이 SES의 대표 문장입니다
- [ ] 함정: [[amazon-sns]]와 나란히 나옵니다. **시스템 알림·팬아웃 = SNS / 고객에게 보내는 이메일 = SES**로 갈라 두시기 바랍니다
- [ ] 함정: "고객 센터에서 전화를 받는다"는 [[amazon-connect]]입니다

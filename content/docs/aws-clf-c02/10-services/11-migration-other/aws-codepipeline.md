# AWS CodePipeline

> CI/CD 파이프라인 오케스트레이션

| | |
|---|---|
| **카테고리** | 11-마이그레이션-기타 |
| **배우는 모듈** | [[13-well-architected]] |
| **문제은행 출현** | 10회 |
| **상태** | - 미학습 |

## 한 줄로 말하면

**소스 → 빌드 → 테스트 → 배포 단계를 하나로 이어 자동으로 흐르게 만드는** CI/CD 파이프라인 서비스입니다.

## 핵심 개념

- **파이프라인을 잇는 역할** — 코드를 저장하지도, 빌드하지도, 배포하지도 않습니다. **각 단계를 담당하는 서비스들을 순서대로 연결하고 지휘**합니다. Code 4형제 중 **혼자만 오케스트레이션 도구**라는 점이 핵심입니다.
- **변경이 생기면 자동 실행** — 리포지토리에 코드가 푸시되는 순간 파이프라인이 자동으로 시작되어 배포까지 이어집니다. 사람이 단계마다 버튼을 누를 필요가 없습니다.
- **단계(stage)와 작업(action)** — 파이프라인은 여러 단계로 구성되고, 각 단계에 [[aws-codecommit]](소스), [[aws-codebuild]](빌드·테스트), [[aws-codedeploy]](배포) 같은 작업을 붙입니다. GitHub, Jenkins 같은 **서드 파티 도구도 단계로 넣을 수 있습니다.**
- **수동 승인 단계** — 프로덕션 배포 직전에 **사람의 승인을 받는 단계**를 끼워 넣을 수 있습니다. 자동화하되 통제는 남겨 두는 방식입니다.
- **한 단계라도 실패하면 멈춥니다** — 테스트가 깨지면 그 지점에서 파이프라인이 중단되므로, 문제 있는 코드가 프로덕션까지 흘러가지 않습니다.

## 요금 모델

- **활성 파이프라인 수(월 단위)** 를 기준으로 과금합니다. 그달에 변경이 한 번도 없던 파이프라인은 활성으로 세지 않습니다.
- **프리 티어**로 매달 일정 개수의 활성 파이프라인이 무료로 제공됩니다.
- 파이프라인이 호출하는 **CodeBuild 빌드 시간, S3 저장 용량 등 다른 서비스 요금은 별도**로 청구됩니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-codebuild]] | CodePipeline은 **전체 흐름을 지휘**하고, CodeBuild는 그 안의 **빌드 단계 하나**를 실행합니다 |
| [[aws-codedeploy]] | CodePipeline은 **언제 무엇을 실행할지 정하고**, CodeDeploy는 **실제 배포 작업을 수행**합니다 |
| [[aws-step-functions]] | Step Functions는 **애플리케이션 로직의 워크플로**를 조율하고, CodePipeline은 **소프트웨어 릴리스 절차**를 조율합니다 |

## 시험 포인트

- [ ] 문제에 **"CI/CD 파이프라인"**, **"소스부터 배포까지 릴리스 프로세스를 자동화"**, **"단계를 순서대로 연결"** 이 나오면 CodePipeline입니다
- [ ] Code 4형제를 한 줄로 정리해 두시기 바랍니다 — **CodeCommit(저장) · CodeBuild(빌드·테스트) · CodeDeploy(배포) · CodePipeline(이 셋을 잇는 파이프라인)**
- [ ] CodePipeline은 **직접 빌드하거나 배포하지 않습니다.** "코드를 컴파일한다"는 설명이 붙으면 CodeBuild입니다
- [ ] **수동 승인 단계**를 넣을 수 있다는 점이 거버넌스 관련 선택지로 나옵니다
- [ ] 요금이 **활성 파이프라인 수** 기준이라는 점을 기억하시기 바랍니다

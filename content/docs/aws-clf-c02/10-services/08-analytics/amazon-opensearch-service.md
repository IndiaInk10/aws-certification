## 한 줄로 말하면

쏟아져 들어오는 로그와 운영 데이터를 색인해 두고 **실시간으로 검색하고 대시보드로 지켜보는** 관리형 검색·분석 서비스입니다.

## 핵심 개념

- **주 용도는 로그 분석과 관찰성입니다** — 애플리케이션 로그, 서버 지표, 보안 이벤트를 모아 두고 "지금 오류가 몇 건 났는지", "어느 시점부터 느려졌는지"를 즉시 들여다봅니다.
- **실시간에 가깝습니다** — 데이터가 들어오는 즉시 색인되므로, 방금 일어난 일을 바로 조회하실 수 있습니다. 하루 지난 데이터를 배치로 훑는 방식과 다릅니다.
- **웹사이트·애플리케이션 검색 기능에도 씁니다** — 상품 검색창처럼 사용자에게 빠른 전문 검색을 제공하는 백엔드로도 사용합니다.
- **OpenSearch 대시보드가 함께 옵니다** — 별도 도구 없이 그래프와 대시보드를 만들어 볼 수 있습니다. 다만 이 시각화는 **운영 데이터**를 보는 쪽입니다.
- **관리형입니다** — 클러스터 프로비저닝, 패치, 장애 노드 교체, 백업을 AWS가 맡습니다. 직접 서버를 관리하실 필요가 없습니다.
- **데이터를 받아 오는 흔한 경로** — [[amazon-kinesis]] 계열의 스트림이나 CloudWatch Logs에서 흘려보낸 데이터를 받아 색인하는 구성이 자주 나옵니다.

## 요금 모델

- 클러스터를 직접 띄우는 방식에서는 **인스턴스를 켜 둔 시간**과 **연결한 스토리지 용량**을 기준으로 과금합니다.
- 서버리스로 쓰시면 **처리·검색에 쓰인 컴퓨팅 단위와 저장 용량**을 기준으로 계산합니다.
- 스냅샷을 [[amazon-s3]]에 보관하면 그 스토리지 요금이 따로 붙습니다.
- 프리 티어가 있어 가입 후 일정 기간 작은 인스턴스를 무료로 쓰실 수 있습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-athena]] | Athena는 S3에 그대로 둔 파일에 **SQL로 질의**합니다. OpenSearch는 데이터를 **색인해 두고 실시간으로 검색·모니터링**합니다. "S3에 SQL"이면 Athena, "로그를 실시간으로"면 OpenSearch입니다 |
| [[amazon-quicksight]] | 둘 다 시각화를 하지만 보는 대상이 다릅니다. QuickSight는 **비즈니스 인텔리전스 대시보드**(매출, KPI), OpenSearch는 **운영 데이터**(로그, 지표)입니다 |
| [[amazon-kendra]] | Kendra는 사람이 읽는 **사내 문서를 자연어로** 찾습니다. OpenSearch는 **기계가 뱉어 낸 로그·데이터**를 검색합니다 |
| [[amazon-redshift]] | Redshift는 정형 데이터를 적재해 두고 복합 분석을 돌리는 **데이터 웨어하우스**입니다. OpenSearch는 웨어하우스가 아니라 **검색 엔진**입니다 |

## 시험 포인트

- [ ] 문제에 **"로그 분석", "실시간 모니터링", "관찰성", "웹사이트 검색"** 이 나오면 OpenSearch Service입니다
- [ ] **"실시간"** 이라는 낱말이 Athena·Redshift와 갈라 주는 결정적 신호입니다
- [ ] 시각화 문제에서 **비즈니스 대시보드는 QuickSight, 운영 데이터는 OpenSearch**로 나눠 두시기 바랍니다
- [ ] 과금 기준은 **인스턴스 시간 + 스토리지**입니다. Athena처럼 스캔량으로 과금한다고 쓴 선택지는 오답입니다
- [ ] 분석 파이프라인 문제에서는 **수집(Kinesis) → 저장(S3) → 분석·시각화(OpenSearch)** 중 맨 뒤 칸에 놓입니다

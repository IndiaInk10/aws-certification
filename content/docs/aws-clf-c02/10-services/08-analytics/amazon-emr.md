# Amazon EMR

> Hadoop/Spark 빅데이터 처리 클러스터

## 한 줄로 말하면

Apache Hadoop, Spark 같은 **빅데이터 프레임워크를 돌릴 클러스터**를 AWS가 대신 띄우고 관리해 주는 서비스입니다.

## 핵심 개념

- **빅데이터 프레임워크를 위한 관리형 클러스터** — Hadoop, Spark, Hive, Presto 등을 실행합니다. 이런 프레임워크를 직접 설치하고 노드를 묶는 일은 손이 많이 가는데, EMR이 그 과정을 대신합니다.
- **EMR은 클러스터입니다** — 여러 대의 인스턴스가 모여 하나의 작업을 나눠서 처리합니다. 서버리스가 아니라 **띄워 둔 만큼 자원이 존재합니다.**
- **대규모 데이터 처리·변환** — 페타바이트 규모의 로그 처리, 대규모 배치 변환, 기계 학습용 데이터 준비처럼 **한 대로는 감당이 안 되는 분량**에 씁니다.
- **프레임워크를 직접 고릅니다** — 어떤 엔진을 쓸지, 노드를 몇 대 둘지, 어떤 인스턴스 유형을 쓸지 내가 정합니다. 그만큼 제어 폭이 넓고 그만큼 관리할 것도 많습니다.
- **작업이 끝나면 클러스터를 종료합니다** — 필요할 때만 띄우고 끝나면 내리는 방식으로 비용을 줄이실 수 있습니다.

## 요금 모델

- **클러스터를 구성하는 인스턴스 시간**을 기준으로 과금합니다. 즉 EC2 인스턴스 요금에 **EMR 관리 요금이 얹히는** 구조입니다.
- 클러스터가 떠 있는 동안에는 실제로 작업을 처리하지 않더라도 요금이 발생합니다. **다 쓰면 종료**하시는 것이 원칙입니다.
- 스팟 인스턴스나 절감형 플랜을 클러스터 노드에 적용해 비용을 낮출 수 있습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-athena]] | Athena는 **서버가 없고 SQL만** 던지면 됩니다. EMR은 **클러스터를 띄워** Spark·Hadoop 코드를 돌립니다. 문제에 프레임워크 이름이 나오면 EMR입니다 |
| [[aws-glue]] | 둘 다 데이터를 가공하지만, Glue는 **서버리스 ETL**이고 EMR은 **내가 관리하는 클러스터**입니다. "관리 부담을 줄이고 싶다"면 Glue입니다 |
| [[amazon-redshift]] | Redshift는 정형 데이터를 SQL로 분석하는 **데이터 웨어하우스**이고, EMR은 비정형 데이터까지 프레임워크로 **처리**합니다 |

## 시험 포인트

- [ ] 문제에 **"Hadoop", "Spark", "Hive", "빅데이터 프레임워크", "클러스터"** 가 나오면 EMR입니다
- [ ] **"페타바이트 규모의 데이터를 처리"** 같은 표현도 EMR 쪽 신호입니다
- [ ] 과금 기준은 **클러스터 인스턴스가 실행된 시간**입니다. 쿼리 스캔량으로 과금하는 Athena와 헷갈리지 마시기 바랍니다
- [ ] "인프라를 전혀 관리하고 싶지 않다"는 조건이 붙으면 EMR이 아니라 Athena 또는 Glue입니다

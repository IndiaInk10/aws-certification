## 한 줄로 말하면

여기저기 흩어진 데이터를 **끌어와서(Extract) 형식을 맞추고(Transform) 분석할 곳에 넣어 주는(Load)**, 서버가 필요 없는 ETL 서비스입니다.

## 핵심 개념

- **ETL이 핵심입니다** — 추출·변환·적재 세 단계를 대신 수행합니다. 원본 데이터는 형식도 제각각이고 빈 값도 섞여 있는데, 그 상태로는 분석할 수 없으니 **분석 가능한 모양으로 다듬는 단계**가 필요합니다. 그 자리를 Glue가 맡습니다.
- **서버리스** — ETL을 돌릴 서버를 따로 준비하지 않습니다. 작업을 실행하면 AWS가 필요한 리소스를 띄우고, 끝나면 정리합니다.
- **데이터 카탈로그** — 어떤 데이터가 어디에 어떤 스키마로 있는지 적어 두는 **중앙 메타데이터 저장소**입니다. [[amazon-athena]], [[amazon-emr]], [[amazon-redshift]]가 이 카탈로그를 함께 참조합니다.
- **크롤러(Crawler)** — S3 같은 데이터 소스를 자동으로 훑어서 스키마를 알아내고 카탈로그에 등록해 줍니다. 컬럼을 손으로 적지 않으셔도 됩니다.
- **분석 파이프라인의 준비 단계** — Glue로 정리한 데이터를 Athena로 조회하고 QuickSight로 시각화하는 흐름이 전형적인 조합입니다.

## 요금 모델

- ETL 작업이 **실행된 시간**을 기준으로 과금합니다. 처리에 쓰인 컴퓨팅 용량(DPU)을 초 단위로 계산합니다.
- 크롤러도 **실행된 시간**만큼 과금합니다.
- 데이터 카탈로그는 **저장된 객체 수와 요청 수**로 과금하며, 일정 수준까지는 무료입니다.
- 작업을 돌리지 않으면 실행 요금은 붙지 않습니다. 서버를 상시로 띄워 두지 않는다는 점이 서버리스의 이점입니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-athena]] | Glue는 데이터를 **정리해서 옮기고**, Athena는 정리된 데이터에 **질문을 던집니다.** "ETL"이라는 단어가 보이면 Glue입니다 |
| [[amazon-emr]] | 둘 다 데이터를 가공하지만, EMR은 **클러스터를 직접 띄우고 프레임워크를 고르는** 방식이고 Glue는 **서버리스**입니다 |
| [[aws-dms]] | DMS는 **데이터베이스를 다른 데이터베이스로 옮기는 마이그레이션** 도구이고, Glue는 분석을 위해 **형식을 바꾸는** 도구입니다 |
| [[amazon-kinesis]] | Kinesis는 **실시간으로 흘러 들어오는** 데이터를 받고, Glue는 이미 쌓인 데이터를 **배치로** 가공합니다 |

## 시험 포인트

- [ ] 문제에 **"ETL", "추출·변환·적재", "데이터를 분석용 형식으로 준비"** 가 나오면 Glue입니다
- [ ] **"데이터 카탈로그", "스키마를 자동으로 검색"** 도 Glue를 가리키는 표현입니다
- [ ] 서버리스라는 점이 자주 정답 근거가 됩니다. "ETL 서버를 관리하고 싶지 않다"면 EMR이 아니라 Glue입니다
- [ ] Glue(준비) → Athena(조회) → QuickSight(시각화) 순서를 한 줄로 외워 두시면 분석 문제 대부분이 정리됩니다

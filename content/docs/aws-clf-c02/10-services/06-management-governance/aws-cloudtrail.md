## 한 줄로 말하면

계정에서 일어난 모든 API 호출을 기록으로 남깁니다. **"누가, 언제, 어디서, 무엇을 했나"** 에 답하는 감사 서비스입니다.

## 핵심 개념

- **모든 작업은 API 호출입니다** — 콘솔에서 클릭하든, CLI로 명령을 넣든, SDK로 코드를 돌리든 결국 API 호출입니다. CloudTrail은 그 호출을 빠짐없이 기록합니다.
- **이벤트에 담기는 정보** — 누가 호출했는지(자격 증명), 언제 호출했는지(타임스탬프), 어디서 왔는지(소스 IP), 무슨 작업을 어떤 리소스에 했는지, 성공했는지 실패했는지까지 남습니다.
- **감사와 규정 준수** — 보안 사고를 조사하거나 내부 감사, 규정 준수 증빙을 요구받을 때 가장 먼저 여는 도구입니다.
- **기본으로 켜져 있습니다** — 최근 **90일치 관리 이벤트**는 콘솔의 이벤트 기록에서 바로 조회하실 수 있습니다.
- **추적(Trail)** — 90일보다 오래 보관하거나 데이터 이벤트까지 남기려면 추적을 만들어 **S3 버킷**으로 로그를 내보내면 됩니다.
- **CloudTrail Insights** — 평소와 다른 비정상적인 API 활동 패턴을 자동으로 짚어 주는 추가 기능입니다.

## 요금 모델

- 최근 90일 관리 이벤트를 보는 **이벤트 기록 조회는 무료**입니다.
- 추적을 만들어 **데이터 이벤트나 Insights 이벤트**를 기록하면 **기록된 이벤트 수**를 기준으로 과금합니다.
- 로그를 담아 두는 **S3 저장 요금**은 별도로 계산됩니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-cloudwatch]] | CloudTrail은 **누가 무엇을 했나**(감사), CloudWatch는 **성능이 어떤가**(지표·로그·경보)입니다 |
| [[aws-config]] | CloudTrail은 **행위 자체(API 호출)** 를 기록하고, Config는 그 결과로 **리소스 설정이 무엇에서 무엇으로 바뀌었는지**와 규정 준수 여부를 봅니다 |
| [[amazon-guardduty]] | CloudTrail은 기록을 남기기만 합니다. GuardDuty는 그 기록을 분석해 **위협을 탐지**합니다 |

## 시험 포인트

- [ ] "누가", "언제", "감사(audit)", "API 호출 이력"이 보이면 CloudTrail입니다
- [ ] "리소스를 삭제한 사람을 찾아라", "책임 추적성(accountability)" → CloudTrail
- [ ] CloudWatch와 역할을 바꿔 놓은 선택지가 단골 함정입니다
- [ ] 90일이 넘는 기록을 보관하려면 **추적을 만들어 S3로** 보내야 합니다
- [ ] 기록만 남길 뿐 위협 판단이나 차단은 하지 않습니다

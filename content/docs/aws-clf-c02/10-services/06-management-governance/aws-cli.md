## 한 줄로 말하면

터미널에 명령어를 입력해 AWS를 조작하는 도구로, 존재 이유는 **반복 작업의 자동화**입니다.

## 핵심 개념

- **하나의 도구로 모든 서비스를** — 서비스마다 다른 프로그램을 깔 필요 없이, `aws`라는 명령 하나로 EC2·S3·IAM 등 대부분의 서비스를 다룹니다.
- **자동화가 핵심 가치** — 명령을 셸 스크립트에 넣어 두면 같은 작업을 몇 번이든 똑같이 반복할 수 있습니다. 콘솔에서 손으로 하던 실수가 사라집니다.
- **어디서든 설치해 씁니다** — Windows, macOS, Linux에 설치할 수 있습니다. 설치 없이 브라우저에서 바로 쓰고 싶다면 콘솔에 내장된 **AWS CloudShell**을 이용하실 수 있습니다.
- **자격 증명을 설정해야 합니다** — `aws configure`로 액세스 키와 기본 리전을 등록합니다. EC2에서 실행할 때는 키 대신 **IAM 역할**을 붙이는 편이 안전합니다.
- **권한은 콘솔과 같은 IAM을 따릅니다** — CLI라고 더 많은 일이 되지 않습니다. 내 IAM 권한 범위 안에서만 동작합니다.
- **SDK와의 차이** — CLI는 **터미널에서 사람이 치거나 스크립트가 실행**하는 도구이고, SDK는 **애플리케이션 코드 안에** AWS 호출을 넣는 라이브러리입니다.

## 요금 모델

- **AWS CLI 자체는 무료입니다.** 내려받아 설치하고 명령을 실행하는 데 요금이 붙지 않습니다.
- CLI로 **만들거나 사용한 리소스의 요금**만 지불하시면 됩니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-management-console]] | 콘솔은 **브라우저에서 클릭**, CLI는 **터미널에서 명령어**입니다. "자동화"가 조건이면 CLI입니다 |
| [[aws-cloudformation]] | CLI는 명령을 **순서대로 실행**하고, CloudFormation은 원하는 상태를 **템플릿으로 선언**해 스택을 만들고 지웁니다. 대규모 인프라 반복 생성은 CloudFormation 쪽입니다 |
| [[aws-systems-manager]] | Systems Manager는 **여러 서버 안에서** 패치·명령 실행을 대신 해 주고, CLI는 **AWS API를 호출**하는 도구입니다 |

## 시험 포인트

- [ ] "**명령줄**", "**스크립트로 자동화**", "**터미널에서 반복 작업**" → AWS CLI
- [ ] 콘솔 대비 CLI의 **주요 이점은 자동화**입니다. "시각적이라 배우기 쉽다"는 콘솔의 장점이니 바꿔 고르지 마시기 바랍니다
- [ ] 함정: "**애플리케이션 코드 안에** AWS 기능을 통합한다"는 CLI가 아니라 **SDK**입니다
- [ ] CLI는 무료이며, IAM 권한을 넘어서는 작업은 할 수 없습니다

## 한 줄로 말하면

리소스의 지표와 로그를 모아 보고, 임계값을 넘으면 경보를 울립니다. **"지금 잘 돌아가고 있나?"** 에 답하는 서비스입니다.

## 핵심 개념

- **지표(Metric)** — CPU 사용률, 네트워크 처리량, 요청 수처럼 시간에 따라 변하는 숫자를 수집합니다. 대부분의 AWS 서비스가 기본 지표를 자동으로 보내 줍니다.
- **CloudWatch Logs** — EC2, Lambda, VPC 등에서 나온 로그를 한곳에 모아 보관하고 검색합니다. 서버에 일일이 접속해 로그 파일을 열어 볼 필요가 없습니다.
- **경보(Alarm)** — "CPU가 5분 연속 80%를 넘으면"처럼 조건을 걸어 두고, 조건을 만족하면 조치를 실행합니다. SNS로 알림을 보내거나 Auto Scaling을 움직이는 데 씁니다.
- **대시보드** — 여러 지표를 한 화면에 모아 놓고 시스템 상태를 한눈에 확인하시면 됩니다.
- **Auto Scaling의 눈** — EC2 Auto Scaling이 인스턴스를 몇 대 띄울지 판단할 때 근거로 삼는 지표가 바로 CloudWatch에서 나옵니다.
- **보는 것은 "성능"입니다** — "누가 무엇을 했는지"는 CloudTrail, "설정이 어떻게 바뀌었는지"는 Config가 맡습니다. 이 경계를 흐리지 마시기 바랍니다.

## 요금 모델

- **수집한 지표 수, 대시보드 수, 경보 수, 저장·수집한 로그 용량, API 요청 수**를 기준으로 과금합니다.
- 5분 간격의 **기본 모니터링은 무료**이고, 1분 간격의 **세부 모니터링**을 켜면 요금이 붙습니다.
- 프리 티어가 있어 일정 수의 지표·경보·대시보드와 일정 용량의 로그는 무료로 쓰실 수 있습니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-cloudtrail]] | CloudWatch는 **성능 지표와 로그**를 봅니다. CloudTrail은 **누가 언제 어떤 API를 호출했는지** 감사합니다 |
| [[aws-config]] | CloudWatch는 **지금 성능이 어떤가**, Config는 **리소스 설정이 어떻게 바뀌었고 규정을 지키는가**입니다 |
| [[aws-x-ray]] | CloudWatch는 **리소스 단위** 지표를 봅니다. X-Ray는 **요청 하나가 서비스들을 지나간 경로**를 추적합니다 |

## 시험 포인트

- [ ] "CPU 사용률", "임계값", "경보", "지표 모니터링"이 보이면 CloudWatch입니다
- [ ] CloudWatch·CloudTrail·Config 셋을 서로 뒤바꾼 선택지가 이 카테고리에서 가장 자주 나옵니다
- [ ] "누가 리소스를 삭제했는지 찾아야 한다"는 CloudWatch가 아니라 CloudTrail입니다
- [ ] 경보가 울리면 보통 **SNS로 알림**을 보내거나 **Auto Scaling**을 트리거합니다
- [ ] 로그를 모아 저장·검색하는 것도 CloudWatch Logs의 일입니다
- [ ] 기본 모니터링은 5분 간격이고, 1분 간격은 유료인 세부 모니터링입니다

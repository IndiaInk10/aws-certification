## 한 줄로 말하면

리소스의 설정이 시간에 따라 어떻게 바뀌어 왔는지 기록하고, 정해 둔 규칙을 지키고 있는지 평가합니다.

## 핵심 개념

- **구성 기록** — 리소스의 설정 상태를 시점별로 저장합니다. "사흘 전 이 보안 그룹은 어떤 모습이었나"를 되돌려 보실 수 있습니다.
- **변경 이력(타임라인)** — 무엇이 언제 어떤 값에서 어떤 값으로 바뀌었는지를 리소스별 타임라인으로 확인합니다.
- **Config 규칙(Rule)** — "S3 버킷은 반드시 암호화되어 있어야 한다", "EBS 볼륨에는 태그가 붙어 있어야 한다"처럼 바람직한 상태를 규칙으로 정의합니다. 어긋난 리소스는 **비준수(non-compliant)** 로 표시됩니다.
- **규정 준수 대시보드** — 계정 전체, 나아가 조직 전체의 준수 현황을 한 화면에서 봅니다.
- **자동 교정(Remediation)** — Systems Manager 자동화와 연결해 규칙을 어긴 설정을 자동으로 되돌리도록 구성할 수 있습니다.
- **리전 단위 서비스** — 쓰려는 리전마다 켜 주셔야 하고, 여러 계정·리전의 데이터는 애그리게이터로 모아 봅니다.

## 요금 모델

- **기록된 구성 항목 수**와 **규칙 평가 횟수**를 기준으로 과금합니다. 리소스가 바뀔 때마다, 규칙이 평가될 때마다 계산되는 구조입니다.
- 서비스를 켜 두는 것만으로 붙는 고정 요금은 없습니다. 대신 변경이 잦은 환경일수록 비용이 올라갑니다.
- 기록 결과를 저장하는 **S3 요금**은 별도입니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[aws-cloudtrail]] | CloudTrail은 **누가 어떤 API를 호출했나**, Config는 그 결과 **리소스 설정이 무엇에서 무엇으로 바뀌었나**입니다 |
| [[amazon-cloudwatch]] | CloudWatch는 **성능 지표와 경보**, Config는 **구성과 규정 준수**입니다 |
| [[aws-security-hub]] | Config는 구성 규칙 위반을 평가합니다. Security Hub는 여러 보안 서비스의 결과를 **한곳에 모아** 보여 줍니다 |

## 시험 포인트

- [ ] "구성 변경 이력", "설정이 언제 바뀌었는지", "규정 준수(compliance) 평가"가 보이면 Config입니다
- [ ] "원하는 구성에서 벗어난 리소스를 찾아라"는 Config 규칙입니다
- [ ] "누가 했나"는 CloudTrail, "성능이 어떤가"는 CloudWatch. 이 셋의 구분이 이 카테고리 최다 출제 지점입니다
- [ ] 리전 단위로 활성화하는 서비스입니다
- [ ] 기록한 구성 항목 수와 규칙 평가 횟수만큼 요금이 붙습니다

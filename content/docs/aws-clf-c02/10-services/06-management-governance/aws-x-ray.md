## 한 줄로 말하면

요청 하나가 여러 서비스를 거쳐 가는 경로를 따라가며, **어느 구간에서 느려졌고 어디서 오류가 났는지** 찾아 줍니다.

## 핵심 개념

- **분산 추적(distributed tracing)** — 마이크로서비스처럼 여러 조각으로 나뉜 애플리케이션에서 요청 하나의 **전체 여정**을 이어 붙여 보여 줍니다.
- **서비스 맵** — 어떤 구성 요소가 어떤 구성 요소를 호출하는지 그림으로 그려 주고, 느린 구간과 오류율을 그 위에 표시합니다.
- **세그먼트와 추적(trace)** — 구간별 소요 시간이 기록되므로 **병목 지점을 특정**할 수 있습니다.
- **"느리다"에서 "여기가 느리다"로** — 전체 응답이 느린 것까지는 CloudWatch로도 압니다. X-Ray는 그 안에서 **어느 단계가 원인인지**까지 좁혀 줍니다.
- **적용 대상** — Lambda, EC2, ECS, API Gateway, Elastic Beanstalk 등에서 사용할 수 있는 **개발자용 디버깅 도구**입니다.

## 요금 모델

- **기록한 추적(trace) 수와 검색·조회한 추적 수**를 기준으로 과금합니다.
- 프리 티어가 있어 매달 일정 건수의 추적 기록과 조회는 무료로 제공됩니다.

## 헷갈리는 것과 구분

| 비교 대상 | 차이 |
|---|---|
| [[amazon-cloudwatch]] | CloudWatch는 **리소스 단위 지표와 로그**를 봅니다. X-Ray는 **요청 하나가 지나간 경로**를 봅니다 |
| [[aws-cloudtrail]] | CloudTrail은 **AWS API 호출 감사**, X-Ray는 **애플리케이션 내부 요청 추적**입니다. 이름이 비슷해 보여도 대상이 완전히 다릅니다 |
| [[aws-config]] | Config는 리소스의 **구성**을 다루고, X-Ray는 애플리케이션의 **동작**을 다룹니다 |

## 시험 포인트

- [ ] "마이크로서비스", "요청이 어느 구간에서 느린지", "병목 분석", "애플리케이션 디버깅" → X-Ray입니다
- [ ] 지문이 **성능 지표와 경보**를 말하면 CloudWatch, **요청 경로**를 말하면 X-Ray입니다
- [ ] 인프라 모니터링 도구가 아니라 **애플리케이션 개발자용** 도구라는 점을 기억하시기 바랍니다
- [ ] 과금 기준은 기록·조회한 추적 수입니다

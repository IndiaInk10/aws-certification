> [!question] 한 기업이 재무·데이터 분석·개발 부서마다 별도 AWS 계정을 쓰며, 비용과 보안 때문에 **계정별로 사용할 수 있는 서비스를 통제**하려고 합니다. 운영 오버헤드가 가장 적은 솔루션은 무엇입니까?
> a) AWS Organizations에서 부서별 **조직 단위(OU)**를 만들고 **서비스 제어 정책(SCP)**을 연결한다
> b) Systems Manager 템플릿으로 부서별 사용 가능한 서비스를 통제한다
> c) CloudFormation으로 허용된 서비스만 프로비저닝한다
> d) Service Catalog 제품 목록으로 서비스 사용을 관리한다
>> [!success]- Answer
>> a) AWS Organizations에서 부서별 **조직 단위(OU)**를 만들고 **서비스 제어 정책(SCP)**을 연결한다
>> **왜 이 답인가** — SCP는 **계정이 쓸 수 있는 서비스의 상한선**을 정합니다. OU에 붙이면 부서 전체에 자동 적용되고 계정 관리자도 넘어설 수 없습니다.
>> **나머지가 아닌 이유** — 템플릿·카탈로그 방식은 **우회 경로가 남습니다.** 콘솔이나 CLI로 직접 만들면 막히지 않습니다.

> a) 보조 클러스터에 **쓰기 전달(write forwarding)**을 켜서 보조 엔드포인트로 온 쓰기를 기본 리전으로 넘기게 한다
> b) 보조 클러스터를 승격해 쓰기를 받게 한다
> c) 보조 리전에 별도 클러스터를 만들어 나중에 병합한다
> d) 애플리케이션이 항상 기본 리전으로만 연결하게 한다
>> [!success]- Answer
>> a) 보조 클러스터에 **쓰기 전달(write forwarding)**을 켜서 보조 엔드포인트로 온 쓰기를 기본 리전으로 넘기게 한다

> [!question] 온프레미스 데이터를 S3로 마이그레이션하면서 **전송 후 데이터 무결성을 자동으로 검증**해야 합니다. 어떤 솔루션이 요구 사항을 충족합니까?
> a) 온프레미스에 **AWS DataSync 에이전트**를 배포해 온라인 전송을 수행한다
> b) AWS Snowball Edge 디바이스를 주문해 온라인 전송을 수행한다
> c) 온프레미스에 S3 File Gateway를 만들어 전송을 수행한다
> d) S3 Transfer Acceleration 가속기를 온프레미스에 구성한다
>> [!success]- Answer
>> a) 온프레미스에 **AWS DataSync 에이전트**를 배포해 온라인 전송을 수행한다

> a) 읽기 전용 복제본을 **다중 AZ 배포로 구성**해 복제본 자체가 대기 인스턴스를 갖게 한다

> c) 복제본 인스턴스 크기를 키운다
> d) 보고서 트래픽을 기본 인스턴스로 되돌린다

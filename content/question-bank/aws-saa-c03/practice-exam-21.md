> [!question] 새로 만들어지는 **모든 EBS 볼륨과 스냅샷이 예외 없이 암호화**되어야 합니다. 사용자가 체크박스를 빠뜨려도 적용되어야 합니다. 어떻게 해야 합니까?
> a) 리전마다 **EBS 기본 암호화**를 활성화하고 기본 KMS 키를 지정한다
> b) 시작 템플릿에 암호화 옵션을 넣는다
> c) Config 규칙으로 미암호화 볼륨을 보고한다
> d) 볼륨 생성 권한을 제한한다
>> [!success]- Answer
>> a) 리전마다 **EBS 기본 암호화**를 활성화하고 기본 KMS 키를 지정한다
>> **왜 이 답인가** — 계정·리전 수준 설정이라 **어떤 경로로 볼륨을 만들어도 암호화가 강제**됩니다. 사용자의 선택에 의존하지 않습니다.
>> **나머지가 아닌 이유** — 시작 템플릿은 그 템플릿을 쓸 때만 적용됩니다. Config 규칙은 사후 보고이고, 권한 제한은 정상 업무를 막습니다.

> [!question] 한 기업이 온프레미스 Oracle 데이터베이스를 AWS 데이터베이스 서비스로 옮겨 **가용성과 성능을 높이고 보고 작업을 기본 시스템에서 분리**하려 합니다. 운영 효율이 가장 높은 솔루션은 무엇입니까?
> a) **다중 AZ 배포의 Amazon Aurora**를 만들고 **리더 인스턴스로 보고 기능**을 보낸다
> b) 단일 AZ RDS Oracle을 만들고 같은 AZ에 읽기 복제본을 두어 보고를 보낸다
> c) 다중 AZ 클러스터 배포로 Oracle 데이터베이스를 만들고 리더 인스턴스로 보고를 보낸다
> d) DMS로 여러 리전에 RDS 인스턴스를 만들고 보고를 별도 인스턴스로 보낸다
>> [!success]- Answer

>> **나머지가 아닌 이유** — 단일 AZ 구성은 가용성 요구를 어깁니다. **RDS 다중 AZ DB 클러스터는 MySQL·PostgreSQL만** 지원하므로 Oracle에는 쓸 수 없습니다.

> a) 볼륨의 **스냅샷을 만들고 암호화 옵션으로 복사**한 뒤 그 스냅샷에서 새 볼륨을 만들어 교체한다

> d) 인스턴스를 중지했다가 시작한다
>> [!success]- Answer

> d) 오리진을 S3 다중 리전 복제로 설정한다
>> [!success]- Answer
>> a) CloudFront 배포에 **오리진 그룹**을 만들어 기본 오리진과 보조 오리진을 지정하고 장애 조치 조건을 설정한다

> b) 삭제 요청 즉시 키가 사라지므로 백업 키로 복구해야 한다
> c) 삭제된 키는 같은 키 ID로 다시 만들 수 있다
> d) 키를 삭제해도 이미 암호화된 데이터는 계속 복호화된다
>> [!success]- Answer
>> a) KMS 키 삭제에는 **대기 기간(7~30일)**이 있어 그 안에 **삭제를 취소**할 수 있으며, 사용 중단만 원한다면 삭제 대신 **비활성화**를 쓴다
>> **왜 이 답인가** — 대기 기간은 **이런 실수를 되돌리기 위해** 존재합니다. 일시 중단 목적이라면 비활성화가 안전한 선택입니다.
>> **나머지가 아닌 이유** — 즉시 삭제되지 않고, 키를 백업하거나 같은 키로 재생성할 수 없습니다. **삭제가 완료되면 그 키로 암호화된 데이터는 영구히 복호화 불가**입니다.

> [!question] 관리자 권한(`AdministratorAccess`)을 가진 역할이 **KMS 키로 복호화하려다 거부**되었습니다. 원인은 무엇입니까?
> a) **키 정책에 그 주체에 대한 허용이 없기 때문**이며, KMS 접근은 키 정책이 근간이므로 키 정책에서 허용해야 한다
> b) IAM 정책에 `kms:Decrypt`가 없기 때문이다
> c) 키가 다른 계정 소유이기 때문이다
> d) 키가 비대칭 키이기 때문이다
>> [!success]- Answer
>> a) **키 정책에 그 주체에 대한 허용이 없기 때문**이며, KMS 접근은 키 정책이 근간이므로 키 정책에서 허용해야 한다
>> **왜 이 답인가** — KMS는 **키 정책이 1차 권한 소스**입니다. 키 정책이 IAM 정책에 위임하지 않으면 관리자라도 사용할 수 없습니다.
>> **나머지가 아닌 이유** — 관리자 정책에는 `kms:Decrypt`가 포함됩니다. 계정 소유나 키 유형 문제라면 오류 양상이 달라집니다.

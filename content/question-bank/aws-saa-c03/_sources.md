## 원칙

원문(지문·보기 문장)은 이 저장소에 두지 않습니다. 가져오는 것은 **판단이 갈리는 지점**뿐이고,
상황·보기·해설은 새로 씁니다. 그래서 대장에도 원문이 아니라 **판단 포인트의 이름**만 적습니다.

원본 파일은 작업자 로컬에 있습니다. 다시 캐야 하면 아래 위치에서 꺼내세요.

## 소재 1·2·3 에서 반복된 것

세 자료가 같은 문제 세트를 다른 각도로 정리한 것이라 겹침이 많았습니다.
아래는 **세 곳 모두에 나온** 판단 포인트입니다. 이미 문항으로 들어가 있으니 또 만들지 마세요.

`aws:PrincipalOrgID` · EBS→EFS 공유 · 70TB Snowball · SMB File Gateway 7일 · S3 게이트웨이 엔드포인트 ·
EC2 IAM 역할 · Gateway Load Balancer · SQS FIFO 순서 · CloudFront 정적+동적 · Network Firewall vs
Firewall Manager · Session Manager · ALB HTTP→HTTPS 리디렉트 · Lambda 동시성→SQS · Shield Advanced ·
CloudWatch 대시보드 공유 · Direct Connect + VPN 백업

## 커버리지 점검으로 찾은 갭 (2026-08-17)

소재 3의 서비스·기능 용어 63개를 문제은행 전체와 대조했더니 **55개는 이미 다루고** 있었고,
실제로 비어 있던 것은 셋이었습니다. 셋 다 채웠습니다.

| 갭 | 왜 비어 있었나 |
|---|---|
| S3 Glacier Instant Retrieval | 계층 문항이 Standard-IA 와 Deep Archive 만 다뤄 **분기 1회 즉시 조회** 구간이 없었음 |
| MFA 삭제 | 버전 관리·객체 잠금은 있는데 이것만 빠져 있었음 |
| 요청자 지불(Requester Pays) | 데이터 전송 비용 문항에 없었음 |

Run Command · Data Pipeline · NAT 인스턴스 · ACM 은 **오답 보기로만** 등장해서 문항으로 만들지 않았습니다.

> 이 점검은 다시 돌릴 수 있습니다 — 소재의 용어를 뽑아 `practice-exam-*.md` 와 `_inbox*.md` 전체에
> `grep -i` 로 대조하면 됩니다. 한글 표기로 쓴 개념은 영문 용어로 안 잡히니 대조표를 같이 두세요.

## 다음에 캘 때

1. 먼저 이 대장에서 **이미 완료된 소재인지** 본다
2. 새 소재면 `grep -c` 로 실제 개수를 센다
3. 판단 포인트를 뽑고 **기존 문항과 겹치는지** 대조한다 (`grep -li` 로 핵심어 검색)
4. 새 것만 `_inbox.md` 에 우리 문항으로 쓴다
5. `node scripts/rebalance-quiz.mjs` 로 편성한다
6. 이 대장에 한 줄 남긴다

> [!important] 도메인 쏠림을 먼저 보세요
> 소재 1·2·3 이 전부 **보안·고성능에 치우쳐** 있었습니다. 그대로 캐면 회차를 못 만듭니다.
> `rebalance-quiz.mjs` 가 마지막에 찍는 **주문서**(도메인별 부족분)를 보고,
> 그 도메인에 해당하는 문항만 골라 캐는 편이 훨씬 빠릅니다.

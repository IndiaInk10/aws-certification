## 원칙

원문(지문·보기 문장)은 이 저장소에 두지 않습니다. 가져오는 것은 **판단이 갈리는 지점**뿐이고,
상황·보기·해설은 새로 씁니다. 그래서 대장에도 원문이 아니라 **판단 포인트의 이름**만 적습니다.

원본 파일은 작업자 로컬에 있습니다. 다시 캐야 하면 아래 위치에서 꺼내세요.

## 소재 5 는 왜 중복을 걸러내지 않았나 (2026-08-18)

소재 1~4 까지는 **판단 포인트가 겹치면 넘겼다.** 소재 5 는 그러지 않았다 —
"말 그대로 다 넣어 달라"는 요청이라 684개를 **하나도 빼지 않고** 문항으로 옮겼다.

그래서 앞선 소재와 같은 갈림길을 다루는 문항이 여러 개 있다. 대신 상황·보기·해설은
문항마다 새로 쓴 것이라 **지문이 겹치지는 않는다.** 같은 개념을 다른 상황으로 두 번
만나는 셈이라, 반복 학습으로는 오히려 쓸모가 있다.

원문 PDF 에는 정답이 실려 있지 않았다. **정답은 우리가 판단해 골랐고**, 해설도 그
판단 근거를 적은 것이다.

> [!important] 도메인이 또 기울었다
> 684개를 도메인별로 나눠 보니 **복원력(도메인 2)만 크게 모자랐다.**
> 972개 중 회차로 나간 것은 750개(15회차)이고 **222개가 대기함에 남았다** —
> 보안 67 · 복원력 10 · 고성능 125 · 비용 20.
> ~~대기분을 전부 회차로 내보내려면 **복원력 문항 약 50개**를 더 써야 한다.~~ — **이 계산은 틀렸다.**
> 복원력만 50개 늘리면 17회차까지 가고 이번엔 **비용이 병목**이 되어 172개가 다시 남는다.
> 대기함을 실제로 비우려면 아래 "소재 없이 쓴 328문항" 을 보라.
> 시험 가이드상 **백업·복원과 재해 복구는 도메인 2**다. 이 기준으로 13문항을
> `03-data-protection` 에서 `05-high-availability` 로 옮겨 15회차를 만들었다.

## 소재 없이 쓴 328문항 — 대기함 0 (2026-08-18)

대기 222개를 전부 회차로 내보내려면 **한 도메인만 늘려서는 안 된다.** 회차는
`보안 15 · 복원력 13 · 고성능 12 · 비용 10` 비율로만 만들어지므로, 남는 도메인을
소진하려면 **모자란 세 도메인을 비율만큼 함께** 채워야 한다.

목표를 26회차(1300문항)로 잡고 역산한 부족분이 그대로 작업 지시가 됐다.

| 도메인 | 신규 | 어디에 |
|---|---|---|
| 1 보안 | 98 | `01-secure-access` 35 · `02-secure-workloads` 33 · `03-data-protection` 30 |
| 2 복원력 | 133 | `04-scalable-decoupled` 66 · `05-high-availability` 67 |
| 3 고성능 | 7 | 나머지 도메인 비율을 맞추는 데 필요한 만큼만 |

**쓰기 전에 기존 972문항을 먼저 읽었다.** 도메인별로 정답 줄만 뽑아 정렬해
무엇을 이미 묻고 있는지 확인하고, **겹치지 않는 갈림길만** 골랐다. 출제 틀도
기존 문항에서 그대로 가져왔다 — 상황 한 문단 + 굵게 표시한 결정 조건, 보기 4개,
`왜 이 답인가` 는 지문의 어느 단어가 답을 가리키는지 짚고, `나머지가 아닌 이유` 는

## 소재 6 — 원본이 들어오면 생성 문항을 물린다 (2026-08-18)

`quiz.md` 가 #261~270 으로 갱신됐다. 10개뿐이지만 **원본 소재가 내가 지어낸 문항보다 우선**이다.
그래서 10개를 넣고, **도메인별로 같은 수만큼 생성 문항을 뺐다** — 그래야 26회차 편성이 그대로 유지된다.

| 뺀 것 | 도메인 | 왜 이것을 뺐나 |
|---|---|---|
| Redshift 기존 클러스터 암호화 | 1 | 판단이 갈리는 지점이 얕다 |
| 서비스 연결 역할 | 1 | 설계 판단이 아니라 용어 설명에 가깝다 |
| FSx for Lustre · 클러스터 배치 그룹 · DAX · Aurora 읽기 전용 엔드포인트 · Global Accelerator | 3 | 새로 들어온 #266·#268·#269 와 갈림길이 겹친다 |
| VPC 피어링 비용 판단 | 4 | 새로 들어온 #262 와 정면으로 겹친다 |

남은 **복원력 2문항(#263 Fargate 조합 · #264 비정상 인스턴스 IP)은 대기함**에 있다.
복원력에서는 생성 문항을 빼지 않았기 때문인데, 둘 다 **이미 같은 문항이 회차에 있다** —
#263 은 3회차, #264 는 2회차·10회차. 그래서 학습 내용에는 빠짐이 없다.

> [!note] 원본이 겹치는 것은 정상이다
> #262 는 10회차, #269 는 12회차, #270 은 11회차에 이미 같은 갈림길이 있다.
> 소재 5(PDF)를 통째로 넣었기 때문에 이제 새 소재는 대부분 겹친다.
> **겹친다고 버리지 않는다** — 같은 개념을 다른 지문으로 두 번 만나는 것이 반복 학습에 낫다.

## 커버리지 점검으로 찾은 갭 (2026-08-17)

소재 3의 서비스·기능 용어 63개를 문제은행 전체와 대조했더니 **55개는 이미 다루고** 있었고,
실제로 비어 있던 것은 셋이었습니다. 셋 다 채웠습니다.

| 갭 | 왜 비어 있었나 |
|---|---|
| S3 Glacier Instant Retrieval | 계층 문항이 Standard-IA 와 Deep Archive 만 다뤄 **분기 1회 즉시 조회** 구간이 없었음 |
| MFA 삭제 | 버전 관리·객체 잠금은 있는데 이것만 빠져 있었음 |
| 요청자 지불(Requester Pays) | 데이터 전송 비용 문항에 없었음 |

처음에는 Run Command · Data Pipeline · NAT 인스턴스 · ACM 을 "오답 보기로만 등장한다"며 넘겼는데,
그건 판단이 틀렸습니다. **오답 보기로 자주 나오는 서비스야말로 자신 있게 지울 줄 알아야 하는 대상**입니다.
Run Command 와 NAT 인스턴스는 각각 정답이 되는 상황이 따로 있어 문항으로 만들었고, ACM 은 이미
세 문항에서 다루고 있었습니다(영문 용어로 대조하느라 놓쳤던 오탐).

**Data Pipeline 만 만들지 않았습니다.** AWS 가 물러나게 한 서비스라 정답이 되는 문항을 쓰면
지금 시험에 틀린 것을 가르치게 됩니다. 오답 보기로 나오면 "요즘은 Glue·Step Functions" 로 지우면 됩니다.

> 이 점검은 다시 돌릴 수 있습니다 — 소재의 용어를 뽑아 `practice-exam-*.md` 와 `_inbox*.md` 전체에
> `grep -i` 로 대조하면 됩니다. 한글 표기로 쓴 개념은 영문 용어로 안 잡히니 대조표를 같이 두세요.

## 소재 없이 만든 회차 (2026-08-17)

5회차는 새 자료를 캐서 만든 것이 아닙니다. **이미 있던 D2·D4 문항 103개를 전부 훑어
비어 있는 갈림길을 찾아** 13문항을 새로 썼습니다.

소재가 알려 주는 것은 "시험에 어떤 갈림길이 나오는가" 뿐이고, 그건 200문항쯤 쌓이면
이미 대부분 알고 있습니다. 그때부터는 **새 소재를 기다리는 것보다 빈 곳을 찾는 쪽이 빠릅니다.**

이때 채운 자리 — ASG 상태 확인을 EC2 에서 ELB 로 · DLQ 최대 수신 횟수 · Aurora 백트랙 ·
ElastiCache Redis 다중 AZ · 읽기 복제본 승격 · 인스턴스 새로 고침 · 복제 시간 제어(RTC) ·
Step Functions 재시도·분기 · 예열 대기 · NAT 인스턴스 트레이드오프 · 미사용 탄력적 IP 요금 ·
불완전한 멀티파트 업로드 · Run Command

> 빈 곳을 찾는 방법: `모듈 [[..]]` 태그로 도메인을 걸러 **정답 줄만 뽑아 정렬**하면
> 무엇을 이미 묻고 있는지 한 화면에 들어옵니다. 겹치지 않는 자리가 곧 다음 문항입니다.
